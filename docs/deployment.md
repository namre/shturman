# Развёртывание: как устроен экземпляр на сервере

Состояние: принятая схема, на живом сервере ещё не собрана. Что в ней проверено, а что остаётся предположением, сказано в конце.

## Принцип

**Hermes — стоковый.** Он ставится и обновляется своим штатным способом, его образ и код мы не меняем и возможности не урезаем. «Штурман» — это набор расширений к нему и один сервис рядом. Весь интеллект живёт в Hermes; сервис отвечает только за данные и сессию Telegram.

## Что чем сделано

| Что нужно | Чем делаем | Механизм Hermes |
|---|---|---|
| Бизнес-режим Telegram | Плагин, форк официального `hermes-telegram-business` | Обработчик обновлений Telegram |
| Поиск по переписке, досье, обязательства | MCP-сервер сервиса переписки | Штатный MCP-клиент |
| Гейт на отправку, «не отвечать посторонним» | Плагин с хуками | `pre_tool_call`, `pre_gateway_dispatch` |
| Ночная сборка, извлечение обязательств | Плагин и задача по расписанию | Доступ плагина к модели, cron |
| Утренняя сводка, подготовка ко встрече | Скиллы | `SKILL.md` |
| Страницы о людях и проектах | Встроенный скилл `llm-wiki` с нашим форматом страницы | Скиллы |
| Имя и характер | Блок в файле личности | `SOUL.md` |
| Кабинет владельца | Плагин дашборда | Вкладка и маршруты в дашборде Hermes |
| Сессия дополнительного аккаунта, архив, импорт, индексация | **Сервис переписки** — единственное, что вне Hermes | Для Hermes это обычный MCP-сервер |

Почему сервис нельзя сделать плагином: плагины исполняются в процессе агента, а сессия пользовательского аккаунта — это полный доступ к аккаунту. Она должна лежать там, куда агент и его инструменты не дотягиваются.

Следствие: **модель одна — та, что настроена в Hermes.** Все обращения к LLM, включая ночную сборку, идут через Hermes. Сервису переписки ключ модели не нужен. Отдельно нужны только эмбеддинги и распознавание речи — локально либо по ключу API.

## Эталонный вариант: один файл Compose

| Контейнер | Что это | Данные |
|---|---|---|
| `hermes` | Официальный образ `nousresearch/hermes-agent` без изменений. Плагины и скиллы ставятся штатными командами в его том | `data/hermes` |
| `shturman` | Сервис переписки: сессия Telegram, импорт, индексация, MCP-сервер, шлюз отправки | `data/session`, `data/wiki`, `data/media` |
| `postgres` | Архив сообщений, люди, обязательства, индексы | `data/postgres` |
| `embeddings`, `stt` | Локальные модели — включаются настройкой | кэш моделей |

Наружу открыт только дашборд Hermes, и только через прокси с аутентификацией. Пример рабочей конфигурации: прокси на хосте, перед ним сервис единого входа, порт 443 открыт файрволом только для адресов этого сервиса.

Все данные лежат в одном каталоге `data/` рядом с клоном репозитория. Резервная копия и переезд на другой сервер — одна операция.

Hermes в официальном образе остаётся стоковым, а его терминал ограничен контейнером — без каких-либо наших правок. Доступ к Docker контейнеру `hermes` не даётся.

## Вариант «пристройка»: Hermes уже есть

Если у владельца Hermes уже работает — в образе или прямо в системе, — Compose поднимает только `shturman` и `postgres`, а расширения ставятся в существующий Hermes. Интерфейс между частями тот же: MCP на локальном адресе.

Если Hermes установлен в систему и его пользователь имеет права администратора, инъекция через входящее сообщение может дотянуться до сессии Telegram. Это выбор владельца; безопасные настройки описываются, но не навязываются.

## Слои

| Слой | Что в нём | Кто меняет |
|---|---|---|
| 0. Хост | Docker, файрвол, SSH по ключу, обновления безопасности, клон репозитория, таймеры резервной копии и сторожа | Один раз при подготовке |
| 1. Стек | Контейнеры из Compose | `ops/up.sh`, `ops/upgrade.sh` |
| 2. Расширения | Плагины, скиллы, запись MCP-сервера в настройках Hermes, блок в `SOUL.md` | `ops/extensions.sh` штатными командами Hermes |
| 2а. Секреты и личные настройки | Ключ модели, токен бота, вход в аккаунты, правила | Владелец в веб-интерфейсе — `docs/setup.md` |
| 3. Обслуживание | Резервные копии, проверка здоровья, место на диске | Таймеры, без участия модели |
| 4. ИИ-оператор | Первое развёртывание, обновление версии, разбор поломки | Человек с агентом, по runbook |

Сторож и ИИ-оператор живут на хосте, вне контейнеров: иначе они не смогут ни сообщить, что стек упал, ни починить его.

## Обновления

- **Hermes обновляется штатно** — новой версией официального образа. Мы этого не запрещаем.
- **Совместимость — совет, а не замок.** В репозитории ведётся список версий Hermes, с которыми расширения проверены; наши тесты гоняются на стабильной и на свежей версии. Перед обновлением `ops/upgrade.sh` сообщает, проверена ли целевая версия.
- **После каждого старта** `ops/doctor.sh` обязан убедиться, что плагин бизнес-режима загружен. Если нет — Hermes принимает личные чаты владельца за команды (issue NousResearch/hermes-agent #127430), и владелец должен узнать об этом немедленно.
- **Расширения закрепляются по коммиту** и обновляются вместе с тегом этого репозитория.

## Что остаётся за сервисом, а не за плагинами

Подтверждение отправки проверяется на стороне сервиса переписки, а не только хуком в Hermes: гейт должен устоять, даже если агент ведёт себя неправильно или плагин не загрузился. Способ подтверждения, который агент не может подделать, — открытый вопрос проектирования.

## Проверено и не проверено

Проверено по документации Hermes на 2026-10-06: виды плагинов и хуков, установка плагинов из подкаталога репозитория с закреплением по коммиту, MCP-клиент, плагины дашборда, официальный образ с томом данных.

Предположения, которые проверяет спайк:

1. Плагин дашборда позволяет загрузку файлов и вход в Telegram по QR.
2. Плагины, установленные в том официального образа, переживают его обновление.
3. Плагин может запускать задачи по расписанию с доступом к модели Hermes.
4. Форк плагина бизнес-режима уживается с хуком `pre_gateway_dispatch`.
5. Встроенный скилл `llm-wiki` можно направить на наш формат страницы без правки самого скилла.
