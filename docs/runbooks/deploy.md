# Развёртывание базового экземпляра

**Для кого:** ИИ-агент (Claude Code, Codex) — на сервере в корне репозитория или с компьютера владельца по SSH (`prompts/deploy.md`, `prompts/deploy-remote.md`). **Состояние:** черновик — целиком на чистом сервере с настоящими сертификатом, ботами и аккаунтом не пройден ни разу. Вывод не совпал с ожидаемым — стоп.

Этот runbook — для режима с Hermes (`SHTURMAN_MODE=hermes`, по умолчанию). Установка без Hermes, «только архив и согласования», — `docs/runbooks/deploy-standalone.md`.

## Цель и критерий готовности

На чистом сервере работают стоковый Hermes из официального образа с ботом-ассистентом, который отвечает только владельцу, и сервис переписки, подключённый к Hermes; владелец настроил переписку на странице «Настройки Штурмана» или сознательно отложил это. Критерий: владелец написал боту и получил ответ; сообщение с постороннего аккаунта осталось без ответа; `./ops/doctor.sh` показывает `ИТОГ: OK`, `PASS service`, `PASS setup-origin`, `PASS setup-page-public`, `PASS setup-isolation`.

Первая настройка у владельца — два места в браузере: мастер (помощник, модель, бот-ассистент) и страница «Настройки Штурмана» (бот согласований, выбор одного из двух способов подключения, шаги этого способа). Бота согласований владелец создаёт и вводит сам, первым шагом страницы: без него запросы ассистента, которые должен подтвердить владелец, отклоняются. Дополнения (поиск по смыслу, защита, расшифровка голосовых, разбор фото) в первую настройку не входят — шаг 8. Отправка сообщений остаётся выключенной. Имя и характер ассистента владелец выбирает сам на первом шаге мастера.

## Как говорить с владельцем

Владелец решает, ты объясняешь. На каждой стоп-точке — готовая фраза ниже (строки «> »): что ты сделаешь, что изменится для него, чем грозит; затем жди явного «да». Команды и настройки показываешь, если он просит или если этого требует стоп-точка («покажи итоговую настройку»), но согласие он даёт на смысл, а не на текст файла. После шага — итог одной фразой: что готово и что дальше от него.

## Предусловия

- Сервер подготовлен по `docs/runbooks/server-prepare.md`: вход по SSH, пользователь с правом запускать Docker (не `root`), Docker и Caddy установлены, способ адреса выбран (`./ops/state.sh get address`: `domain`, `ip` или `relay`; сравнение — `docs/address.md`) и сервер подготовлен под него. Для адреса по IP нужен Caddy 2.11 или новее.
- У владельца готовы: домен, направленный на сервер, или код приглашения посредника (для адреса по IP — ничего); Telegram; ключ провайдера модели либо подписка ChatGPT. Двух ботов — бота-ассистента и бота согласований — он создаст сам у @BotFather по подсказкам мастера и страницы; свой числовой Telegram ID ему знать не нужно. Telegram Premium не нужен ни для одного способа (документация Telegram API, сверено 2026-10-14).
- Для своего домена и адреса по IP можно открыть порты 80, 443 и 8443. Нельзя открыть 8443 — странице понадобится другой порт или отдельное имя (шаг 5а). Через посредника входящие порты не нужны.
- Репозиторий склонирован в `/opt/shturman`. Агент работает в его корне на сервере или с компьютера владельца через SSH (`prompts/deploy-remote.md`).

## Инварианты

Действуют все правила `AGENTS.md`. Дополнительно для этого runbook:

- **Бот-ассистент (бот Hermes) в бизнес-режиме Telegram не подключается** ни на каком шаге. Бизнес-режим бывает только у бота согласований, подключает его владелец сам (шаг 7).
- **У страницы «Настройки Штурмана» свой адрес, не адрес дашборда.** По умолчанию — то же имя, порт 8443 (`SHTURMAN_SETUP_URL`). Не записывать адрес страницы равным адресу дашборда в обход `./ops/set-setup-url.sh`, не возвращать путь `/shturman-setup/` в блок дашборда обратного прокси, не объединять два блока сайта (пояснение 1). `FAIL setup-origin` или `FAIL setup-isolation` — стоп. Смена адреса страницы (`./ops/set-setup-url.sh`, в том числе `--clear`) — стоп-точка: за ней правка прокси, firewall или DNS.
- **Правка обратного прокси, открытие портов в firewall, установка `config/shturman-service-socket.conf` в `/etc/tmpfiles.d/` — стоп-точки** (`sudo`): покажи владельцу итоговую настройку и получи согласие. Второй блок сайта, путь к сервису через его сокет и отказ на `/shturman-setup*` в блоке дашборда — по образцу `config/Caddyfile.example`, без изменений по существу. Без домена — то же для варианта «без домена» в конце образца; порт 80 на таком экземпляре не закрывать и потом (пояснение 3).
- **Каталог сокета сервиса — только сервису и прокси.** Прокси ходит к сервису через Unix-сокет `/run/shturman-service/proxy.sock`, а не через порт 8765. Каталог `/run/shturman-service` подключается только контейнеру сервиса. Не подключать его, `/run` или `/proc` хоста и сокет Docker в контейнер Hermes (и в другие контейнеры), не давать Hermes `pid: host`, не переводить сокет в абстрактное пространство имён, не расширять права каталога (`config/shturman-service-socket.conf`: владелец — пользователь стека, группа `caddy`, 2710), не переводить прокси обратно на порт 8765 (пояснение 2). `WARN setup-socket` до переключения прокси — норма перехода, `FAIL setup-socket` — стоп.
- **Контейнеру Hermes не даётся право `CAP_NET_RAW`** (`cap_drop: [NET_RAW]` в `compose.yaml`, Р-76). Это настройка запуска, а не правка образа (пояснение 2). Вернуть это право или убрать другие — только отдельным решением владельца; `FAIL hermes-net-raw` — стоп.
- Посторонние контейнеры на сервере — стоп; что сказать владельцу — `server-prepare.md`, шаг 3.
- Отправку не включать: строку `SHTURMAN_SENDING` в `.env` не добавлять (`docs/architecture.md`, «Открытое ограничение»).
- `./ops/tg-login.sh` и `./ops/init-env.sh` без `--auto` — запасной путь только для человека; агент их не запускает и их вывод не читает.
- Ссылки `./ops/activation-link.sh`, `./ops/setup-link.sh`, `./ops/bot-bind.sh` — по правилам `AGENTS.md`, «Ссылки входа»: передать как есть, нигде не сохранять, самому не открывать. `setup-link` и `bot-bind` — только по явной просьбе владельца.
- На страницу «Настройки Штурмана» не заходить, её адреса не запрашивать, что владелец на ней ввёл — не спрашивать; её состояние — строки `setup-*` в `./ops/doctor.sh`.
- Журналы контейнеров (Hermes, сервиса, базы, дополнений, посредника) и прокси (`journalctl -u caddy`) агент не читает (`AGENTS.md`): вместо них — `./ops/diag.sh --print` (виды ошибок и счётчики, пояснение 5) и `./ops/resources.sh` (память, перезапуски). Чего пакет не показывает — стоп: журнал читает человек с доступом к серверу. Каталог `data/` и содержимое базы не читать.

## Шаги

Формат шага: действие → проверка → итог владельцу одной фразой; затем `./ops/state.sh done <шаг>`. Провал проверки дважды — стоп.

### 1. Состояние и вариант установки

`./ops/state.sh show`. Шаги уже отмечены — продолжить со следующего.

Шагов ещё нет — **до любого другого действия** спросить, какой вариант ставится (если стартовый промпт уже спросил и владелец ответил — не переспрашивать). Выбирает владелец; стартовый промпт или runbook — не ответ. Отличия — `docs/standalone.md`, «Что это».

> Какой из двух вариантов ставим? 1. **«Ассистент в Telegram»** — ассистент отвечает вам в Telegram, ведёт архив переписки, готовит ответы и сводки. 2. **«Только архив и согласования»** — без ассистента в Telegram: архив переписки с поиском и список обязательств, вопросы вы задаёте из своего Codex или Claude Code; для него вам самому понадобится терминал.

Выбран второй — этот runbook закрыть, идти по `docs/runbooks/deploy-standalone.md`.

- В состоянии есть шаг `business-plugin` (развёртывание начато по прежней схеме) — шаги до 6-го засчитываются, дальше этот runbook с шага 7; уже подключённый бизнес-режим — `UPGRADING.md`, «0.0.5 → 0.0.6».
- **Способ адреса**: `./ops/state.sh get address` → `domain`, `ip` или `relay` (выбран в `server-prepare.md`, шаг 5). Пусто и шаг `hermes-up` не отмечен — выбрать сейчас, до шага 2, тем же порядком: `server-prepare.md`, шаги 5а–5е (проверки, рекомендация, вопрос, для посредника — риски), затем Caddy и firewall под выбор — там же, шаги 6 и 7 (стоп-точки). Агент на самом сервере выполняет эти команды без `ssh shturman-app '…'`; адрес сервера для 5а спросить у владельца; проверку снаружи (5б, пункт 2) делает владелец — открывает `http://<IP>/` в браузере телефона через мобильный интернет, пока работает приёмник. Запись: `./ops/state.sh set address domain` (или `ip`, `relay`).
- Итог владельцу: какой вариант и какой адрес выбраны.
- Запись: `./ops/state.sh done choice`

### 2. Проверка сервера

`./ops/preflight.sh`
- Проверка: `ИТОГ: OK`. Строки `WARN` пересказать простыми словами.
- `FAIL docker` — **стоп-точка** (`sudo`): после «да» поставить Docker по официальной инструкции для дистрибутива и повторить preflight.

> Для работы ассистента на сервер нужно поставить служебную программу, которая запускает части ассистента, — из официального источника. Нужны права администратора. Пользователь ассистента получит право управлять ею, а это равно правам администратора сервера; для такого сервера это обычно. Ставлю?

- `WARN net:telegram` или `net:openai` — **стоп-точка**: без исходящего маршрута дальше идти бессмысленно; нужен прокси (`EGRESS_PROXY_URL`). Решает владелец.

> Сервер не достаёт до Telegram (или до провайдера модели). Нужен промежуточный выход в интернет, который настраиваете вы или ваш администратор; тот, кто его держит, будет видеть, к каким сервисам и когда обращается сервер (содержимое — нет, оно зашифровано). Обходить ограничения провайдера модели из неподдерживаемой страны — нарушение его условий: можно потерять аккаунт. Настроите такой выход и дадите мне его адрес — или остановимся здесь?

- `WARN setup-port: порт 8443 уже кто-то слушает` — выяснить, что за программа; посторонняя — странице понадобится другой порт или отдельное имя (шаг 5а), сказать владельцу.
- Итог владельцу: сервер проверен, что не так — простыми словами.
- Запись: `./ops/state.sh done preflight`

### 3. Часовой пояс и служебные значения

3а. **Город — один раз.** Если владелец уже назвал город (стартовым промптом, на шаге 0 или при подготовке сервера) — не переспрашивать. Иначе:

> В каком городе вы живёте? По вашему времени ассистент пришлёт утреннюю сводку (08:27) и обзор недели (пятница, 17:47), а сервис будет считать тихие часы (23:00–08:00), ночной разбор, сроки и напоминания.

По умолчанию — Москва (`Europe/Moscow`). Екатеринбург — `Asia/Yekaterinburg`, Астрахань — `Europe/Astrakhan`, Новосибирск — `Asia/Novosibirsk`; полный список — `timedatectl list-timezones`. Пояс не секретный.

3б. `./ops/init-env.sh --auto --mode hermes --timezone <пояс>` — записывает вариант установки и пояс, генерирует пароль базы и токены сервиса, ничего не спрашивает и не печатает значений, кроме режима и пояса. `.env` не читать. Токены и ключи владельца здесь не вводятся: их он вводит в браузере на шагах 6 и 7 (`docs/setup.md`).
- Проверка: `[SHTURMAN_TIMEZONE] записан пояс: <пояс>`; `./ops/preflight.sh` — `PASS env: есть, права 600`. «неизвестный часовой пояс» — опечатка: сверить с `timedatectl list-timezones` и повторить (`.env` при отказе не меняется). Строки `timezone`, `hermes-tz`, `cron-schedule` — после шага 5г.
- Итог владельцу: время записано, сводки и напоминания пойдут по нему.
- Запись: `./ops/state.sh done timezone` и `./ops/state.sh done env`

### 4. Версия Hermes

В `compose.yaml` — версия официального образа, с которой проверены расширения (`config/hermes-versions.txt`). Показать её владельцу.

> Ассистент будет работать на проверенной версии Hermes. Новые версии будут приходить вместе с обновлениями «Штурмана», когда разработчик проверит их и включит в выпуск. Можно закрепить другую версию, но тогда обновления её больше менять не будут, снять закрепление потом сможет только человек в терминале сервера, а с непроверенной версией что-то может не работать.

`HERMES_VERSION`: на работающем экземпляре агент строку не пишет; при первой установке — только до первого запуска (шаг `hermes-up` не отмечен) и по просьбе владельца. Владелец просит другую версию — его решение: сверить её с `config/hermes-versions.txt` (нет в списке — сказать, что плагин с ней не проверен), затем по его «да» дописать строку в конец `.env`: `echo 'HERMES_VERSION=<версия>' >> .env` (файл не читать; `./ops/init-env.sh` эту строку не пишет). На работающем экземпляре смена версии Hermes — `docs/runbooks/update.md`, «Новая версия Hermes» (пояснение 6). Теги `latest` и `main` не использовать, образ не пересобирать.
- Проверка: после шага 5 `./ops/doctor.sh` — `hermes-version` с явной версией.
- Итог владельцу: на какой версии Hermes будет работать ассистент.
- Запись: `./ops/state.sh set hermes.image <версия>` и `done pin`

### 5. Внешний адрес, прокси и запуск

5а. Адрес — по выбору владельца (`./ops/state.sh get address`).

**`domain` — свой домен.** Спросить имя, на которое владелец создал запись DNS (`server-prepare.md`, шаг 7б): `./ops/set-public-url.sh https://assistant.example.ru`.

**`ip` — по IP-адресу сервера.** Внешний IPv4-адрес, проверенный при выборе (`server-prepare.md`, шаг 5а): `./ops/set-public-url.sh https://203.0.113.10`. Скрипт напечатает, что нужно экземпляру без домена («Это IP-адрес, а не имя…»), — пересказать. Адрес закрытой сети (`10.…`, `192.168.…`) скрипт не примет.

Для `domain` и `ip`:
- Скрипт записывает и печатает два адреса: дашборда и страницы «Настройки Штурмана» (то же имя, порт 8443). Владельцу порт ни знать, ни набирать не нужно: он переходит по кнопке и ссылке.
- 8443 открыть нельзя или он занят — другой порт: `./ops/set-setup-url.sh https://адрес:порт`, или отдельное имя на этот же сервер (запись DNS делает владелец): `./ops/set-setup-url.sh https://второе-имя`. Адрес, совпадающий с адресом дашборда, скрипт не примет. Это **стоп-точка** (за ней — прокси и защита сети):

> Порт 8443 для страницы «Настройки Штурмана» открыть нельзя. Поставлю её на другой порт, например 9443 (или на отдельное имя — тогда вы добавите для него запись у регистратора). Для этого поменяю настройку программы, которая принимает обращения из браузера, и открою этот порт в защите сети; прежние ссылки на страницу перестанут работать. Делаю?
- Проверка: `./ops/set-setup-url.sh` без параметров показывает адрес страницы, он отличается от адреса дашборда.

**`relay` — через посредника** (вместо `set-public-url.sh`). **Стоп-точка:** перед `join` — явное «да» владельца после рисков из `docs/relay.md` (1, 8, 9) — той же фразой, что в `server-prepare.md`, шаг 5е (и если там «да» уже было — повторить её перед `join`):

> Через посредника есть риск, который полностью не убирается. Его держатель технически может направить ваш адрес на свой сервер и показать поддельную страницу настроек — а на ней вы входите в Telegram; так же он может подменить приложение «Штурман» в боте и минут десять нажимать кнопки согласований за вас. Пока посредник не признан браузерами отдельной зоной, то же может сделать и другой владелец на этом посреднике, если узнает служебный номер вашего подключения. Поэтому подключайтесь, только если доверяете держателю посредника и тем, кому он раздаёт коды. Посредник видит, когда и откуда открывают ваш адрес, но не то, что на страницах; если он недоступен, страницы не откроются, а бот в Telegram будет работать. Подключаемся?

Код приглашения даёт владелец; код нигде не сохранять — ни в состоянии, ни в журнале, ни в отчёте, — только подставлять в `check` и `join`.
1. **Имя.** Спросить владельца или предложить 2–3 из того, что он о себе сказал: имя и фамилия латиницей (`ivan-petrov`), компания (`romashka`). Правила: 3–30 знаков — строчные латинские буквы, цифры, дефис внутри; не начинается с `setup-`; служебные (`www`, `api`, `admin`, `test`, `mail` и подобные) не выдаются.

> Имя будет видно в адресе и в открытых журналах выдачи сертификатов — не берите того, чего не хотите показывать.

2. **Свободно ли** — для каждого имени `./ops/relay.sh check КОД ИМЯ` (код не расходуется, `.env` не меняется):
   - «Имя «ИМЯ» свободно: адреса будут …» (код 0);
   - «…уже занято.», «…служебное…» и «Свободные варианты: …» (код 3);
   - «Посредник не умеет проверять имя заранее (служба посредника старше 0.3.0)» — сразу `join`: занятое имя код не тратит;
   - «(HTTP 403): Код приглашения не подошёл…» — код использован, истёк или с ошибкой: новый — у держателя; «(HTTP 429)» — подождать (30 проверок за 15 минут);
   - «Имя не подходит: 3–30 знаков…» — исправить имя.
3. **Выбор.** Показать владельцу свободные имена и адреса из них; выбирает он.
4. **Подключение:** `./ops/relay.sh join КОД ИМЯ`.

Качество скромное: на проверочном наборе верный ответ попадает в первую десятку в 35–55 % случаев, на вашей переписке — заранее неизвестно. Пока сервер готовит архив к поиску (на большом архиве — часы), поиск по смыслу видит только часть сообщений. Моделей две: многоязычная (по умолчанию, лучше держит длинные тексты) и русская (для коротких русских сообщений, легче). Включаю многоязычную?

Смена модели на работающем экземпляре (`./ops/embeddings.sh on --model …`) — только по его явной просьбе:

> Сменю модель поиска по смыслу. Сервер скачает другую модель и заново подготовит весь архив — около трёх часов на 300 000 сообщений; всё это время поиск по смыслу видит только уже подготовленные сообщения. Вернуться к прежней модели — такой же пересчёт. Меняю?

- Проверка: `PASS embeddings` с именем модели или `WARN embeddings: …идёт подсчёт векторов` со счётчиками — пока архив считается, это норма; `./ops/embeddings.sh status`.

Распознавание ошибается примерно в 5 % слов на чистой речи, на шуме больше — имена и числа сверяйте. Нужно около 1,4 ГБ памяти и 4 ГБ диска. Включаю?

## Если вход перестал работать

1. `./ops/doctor.sh`. `FAIL plugin` — `./ops/up.sh`: он включит плагин и перезапустит Hermes.
2. Плагин включён, а дашборд не отвечает — `./ops/diag.sh --print` (журнал Hermes в нём — только счётчики ошибок; сам журнал Hermes не читается и с разрешения владельца). Плагин не загружается — аварийный вход (стоп-точка): `./ops/emergency-access.sh on`, объяснить владельцу, как открыть дашборд через SSH-туннель; снаружи адрес в этом режиме закрыт.

> Обычный вход в ассистента сейчас не работает. Могу включить запасной: снаружи адрес на это время закроется, а дашборд откроется без входа — только на вашем компьютере, через защищённое соединение с сервером, которое настраивает агент или технический специалист на этом компьютере. Пока запасной вход включён, кто сидит за вашим компьютером с этим соединением, тот и в дашборде. Включаю?

3. После починки — `./ops/emergency-access.sh off` и снова `./ops/doctor.sh`.

Страница «Настройки Штурмана» от входа в дашборд не зависит: у неё свой вход и свой адрес. Не открывается она — таблица ниже, строки `setup-*`.

## Откат

Остановить стек без удаления данных. Сессии аккаунтов Telegram владелец завершает сам: «Настройки → Устройства». Бота согласований в бизнес-режиме отключает человек в настройках Telegram Business. Блок страницы в прокси и открытый для неё порт можно убрать (стоп-точки). Всё, что удаляет данные (`data/`, тома, `down -v`), — стоп-точка. Возврат на прежнюю версию — `./ops/restore.sh --rollback` или восстановление копии (`docs/runbooks/restore.md`); что вне репозитория — раздел «Откат» версии в `UPGRADING.md`.

## Что ещё должно появиться

Копии по расписанию; проверка экземпляра снаружи одной командой (сейчас её частично делает `./ops/doctor.sh`: строки `setup-page-public`, `proxy-cert`); проход этого runbook на чистом сервере целиком.

## Пояснения

1. **Почему у страницы свой адрес.** На адресе дашборда ассистент в Hermes может исполнять свой код, а на странице владелец вводит ключи Telegram и входит в аккаунт: браузер разделяет их только по адресу (схема, имя, порт). Простыми словами — в шапке `config/Caddyfile.example`; подробно — `docs/setup.md`, «Почему у страницы „Настройки Штурмана“ свой адрес».
2. **Сокет вместо порта и `CAP_NET_RAW` (Р-76).** Hermes работает в сети хоста: пока сервис перезапускается, порт 8765 может занять процесс из Hermes и принять запросы страницы. Процессы Hermes работают под тем же uid, что и сервис, и от сокета их отделяет только то, что каталога `/run/shturman-service` нет в их файловой системе; systemd-tmpfiles создаёт каталог при каждой загрузке (зачем — шапка `config/shturman-service-socket.conf`, `docs/deployment.md`, «Сокет для обратного прокси»). Право `CAP_NET_RAW` убрано: с ним процесс root в контейнере Hermes, работающем в сети хоста, может сырыми сокетами читать чужие соединения сервера, в том числе запросы к странице. Сырые сокеты и ICMP Hermes не использует (`ping` в его терминале работает через ICMP-сокеты, если их разрешает ядро).
3. **Порт 80 без домена.** Через него (и через 443) Let's Encrypt проверяет адрес при каждом продлении; сертификат на IP-адрес короткий (`profile shortlived`) и продлевается раз в несколько дней. Закрыть 80 — сорвать продление (`docs/deployment.md`, «Без домена: HTTPS по IP-адресу»).
4. **Admin API прокси и restart.** Контейнер Hermes в сети хоста достаёт до `localhost:2019`, поэтому admin API уходит на Unix-сокет в закрытом каталоге (`config/caddy-admin-socket.conf`). Работающий Caddy слушает admin API по прежнему адресу, и `reload` в настройку с новым адресом не проходит (`dial unix /run/caddy-admin/admin.sock: … no such file or directory`) — поэтому `restart`.
5. **Почему журналы — только пакетом.** В журнале базы бывают значения строк таблиц (`Failing row contains (…)`, `CONTEXT: COPY …`), то есть начало текста сообщений; в журнале сервиса — те же фрагменты в тексте исключений базы, номера чатов и аккаунтов; в журнале frpc — номер подключения к посреднику; в журнале прокси — адреса запросов и IP-адреса посетителей; в журнале Hermes — начало каждого входящего сообщения. Всё, что агент прочитал, уходит провайдеру его модели. `./ops/diag.sh` берёт из журналов только виды ошибок и счётчики белым списком (`docs/deployment.md`, «Диагностический пакет»); его вывод можно и показать владельцу, и переслать.
6. **`HERMES_VERSION` после запуска.** Смена образа Hermes на работающем экземпляре требует свежей копии, а откат — восстановления `data/hermes` из неё; скрипта для этого нет. Поэтому без терминала владельца новая версия приходит только с выпуском «Штурмана» (`docs/runbooks/update.md`, «Новая версия Hermes»; сценарий О10).
