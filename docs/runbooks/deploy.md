# Развёртывание базового экземпляра

**Версия runbook:** 0.0.4 · **Для `VERSION`:** 0.0.3 · **Состояние: черновик.** Шаги 1–4 пройдены на живом сервере 2026-10-06 (Ubuntu 24.04, Hermes 0.21.5). Шаги 5–7 переписаны под вход и мастер настройки версии 0.0.2: скрипты и мастер проверены на стенде, на живом сервере в этом виде не пройдены. С версии 0.0.3 шаг 5в поднимает ещё и сервис переписки с базой, добавлен шаг 8; **эта часть под Docker не запускалась ни разу** — первый проход и есть проверка. Вывод не совпал с ожидаемым — стоп.

Этот runbook — для режима с Hermes (`SHTURMAN_MODE=hermes`, по умолчанию). Установка без Hermes, «только архив и согласования», — `docs/runbooks/deploy-standalone.md`.

## Цель и критерий готовности

На чистом сервере работают стоковый Hermes из официального образа с управляющим ботом, который отвечает только владельцу, и сервис переписки с пустым архивом, подключённым к Hermes. Критерий: владелец написал боту и получил ответ; сообщение с постороннего аккаунта осталось без ответа; `./ops/doctor.sh` показывает `ИТОГ: OK` и `PASS service`.

Бизнес-режим, загрузка истории, поиск по смыслу и подключение аккаунтов Telegram — по желанию владельца, шаги 7 и 8. Отправка сообщений в этот runbook не входит и остаётся выключенной. Имя и характер ассистента владелец выбирает сам на первом шаге мастера.

## Предусловия

- Сервер Linux, доступ по SSH, пользователь с правом запускать Docker.
- У владельца готовы: адрес (домен), направленный на сервер; Telegram на телефоне или компьютере; ключ провайдера модели либо подписка ChatGPT. Бота он создаст по подсказке мастера, свой числовой Telegram ID ему знать не нужно.
- Репозиторий склонирован, агент запущен в его корне.

## Инварианты

Действуют все инварианты, стоп-точки и запреты из `AGENTS.md`. Дополнительно для этого runbook:

- Бота нельзя подключать в бизнес-режиме в настройках Telegram до шага 7.
- Ссылку из `./ops/activation-link.sh` передать владельцу и больше нигде не сохранять.
- На сервере не должно быть посторонних контейнеров. Нашлись — стоп.
- Отправку не включать: строку `SHTURMAN_SENDING` в `.env` не добавлять (`docs/architecture.md`, «Открытое ограничение»).
- `./ops/tg-login.sh` запускает только человек; его вывод не читать и не просить.
- Каталог `data/` и содержимое базы не читать; о состоянии архива судить по счётчикам `./ops/doctor.sh`.

## Шаги

Формат шага: действие → проверка → запись состояния. Провал проверки дважды — стоп.

### 1. Состояние
`./ops/state.sh show`. Если шаги уже отмечены — продолжить со следующего.

### 2. Проверка сервера
`./ops/preflight.sh`
- Ожидается: `ИТОГ: OK`. Строки `WARN` объяснить человеку простыми словами.
- `FAIL docker` — **стоп-точка**: установка Docker требует `sudo`. Получить согласие, ставить по официальной инструкции Docker для дистрибутива, после — повторить preflight.
- `WARN net:telegram` или `net:openai` — **стоп-точка**: без исходящего маршрута дальше идти бессмысленно. Объяснить, что нужен прокси (`EGRESS_PROXY_URL`), и что доступ к провайдеру модели из неподдерживаемого региона нарушает его условия и может стоить аккаунта. Решение принимает человек.
- Запись: `./ops/state.sh done preflight`

### 3. Служебные значения
`./ops/init-env.sh --auto` — генерирует пароль базы и два токена сервиса переписки, ничего не спрашивает и не печатает значений. Файл `.env` не читать.
- Проверка: `./ops/preflight.sh` показывает `PASS env: есть, права 600`.
- Токены и ключи владельца здесь не вводятся: их вводит владелец в мастере настройки на шаге 6, порядок — `docs/setup.md`.
- Запись: `./ops/state.sh done env`

### 4. Версия Hermes
В `compose.yaml` указана версия официального образа, с которой расширения проверены. Показать её человеку. Если он хочет другую — записать `HERMES_VERSION=<версия>` в `.env` командой `echo` с добавлением в конец файла (сам файл не читать) и предупредить, что она не проверена. Образ не пересобирать и не менять. Теги `latest` и `main` не использовать.
- Проверка: после шага 5 `./ops/doctor.sh` показывает образ с явной версией.
- Запись: `./ops/state.sh set hermes.image <версия>` и `done pin`

### 5. Внешний адрес, прокси и запуск
5а. Спросить у владельца адрес, по которому он будет открывать ассистента, и записать его: `./ops/set-public-url.sh https://адрес`.
- Проверка: скрипт печатает записанный адрес.

5б. **Стоп-точка (`sudo`, TLS, порты).** Настроить обратный прокси на хосте по образцу `config/Caddyfile.example`: страницы входа из `plugins/shturman/public` по пути `/shturman-auth/`, всё остальное — на `127.0.0.1:9119`. Заголовок `Host` не подменять. Перед выполнением показать человеку итоговую настройку и получить согласие.
- Проверка: проверка синтаксиса настройки проходит; сертификат для адреса получен.

5в. `./ops/up.sh` — скачивает образы (Hermes — около 4 ГБ, несколько минут), собирает образ сервиса переписки (первая сборка — ещё несколько минут, нужен интернет для пакетов), запускает базу, сервис и Hermes, включает плагин `shturman`, подключает архив к Hermes и сам вызывает `./ops/doctor.sh`. Что скрипт делает по шагам — `docs/deployment.md`.
- Ожидается: `PASS hermes`, `PASS dashboard`, `PASS dashboard-bind`, `PASS plugin`, `PASS public-url`, `PASS login`, `PASS login-page`, `PASS service`, `PASS service-bind`, `PASS database`, `PASS archive-mcp`, `PASS archive` с нулями, `PASS jobs`, `ИТОГ: OK`.
- Предупреждения про токен бота, владельца, мастер, плагин бизнес-режима, `WARN service-owner` и `WARN embeddings` на этом шаге нормальны.
- `FAIL login-page` — прокси не отдаёт страницы входа: вернуться к 5б.
- «Сервис переписки не ответил за 90 секунд» или `FAIL service`, `FAIL database`, `FAIL archive-mcp`, `FAIL archive` — раздел «Сервис переписки не отвечает».
- `FAIL service-bind` — порт сервиса или базы открыт наружу: **стоп**, стек остановить не удаляя данных и разобраться с `compose.override.yaml`.
- Проверка: `docker ps` показывает только контейнеры этого стека: `shturman-hermes`, `shturman-service`, `shturman-postgres`.
- Запись: `done hermes-up`

### 6. Первый вход владельца и мастер — стоп-точка
6а. Убедиться, что владелец на связи и готов потратить десять минут. Выполнить `./ops/activation-link.sh` и передать ему ссылку как есть. Ссылка действует 30 минут и один раз; если не успел — выдать новую.

6б. Владелец в браузере проходит шаги мастера «Помощник», «Модель» и «Бот в Telegram». Агент в это время ничего не делает и значений не спрашивает. Дождаться слова «готово».
- Проверка: `./ops/doctor.sh` показывает `PASS bot-token`, `PASS bot-owner`, `PASS service-owner`. Если `service-owner` ещё `WARN` — повторить через минуту: плагин сообщает сервису владельца при запуске шлюза.
- Проверка (делает человек): написать боту «привет» — пришёл ответ. Написать с другого аккаунта — ответа нет. Выйти из дашборда и войти снова — по кнопке «Получить код в Telegram» бот прислал код, код подошёл.
- Запись: `done control-bot`

### 7. Бизнес-режим — по желанию владельца
Владелец на шаге мастера «Бизнес-режим» нажимает «Установить защиту»: мастер ставит официальный плагин бизнес-режима по полному SHA и перезапускает бота. Инструкции подключения в Telegram мастер показывает только после этого.
- Проверка: `./ops/doctor.sh` показывает `PASS business-plugin`.
- **Стоп-точка:** человек включает режим у @BotFather и подключает бота в настройках Telegram, выбрав для начала один тестовый чат. Право бота отвечать на сообщения при подключении лучше не давать: отправка в этой версии выключена (`docs/architecture.md`, «Открытое ограничение»). Как официальный плагин ведёт себя без этого права, не проверено.
- Сказать владельцу до подключения: с этого момента сообщения из выбранных чатов записываются в архив на сервере, а раз в сутки ночью разбираются моделью.
- Проверка (делает человек): собеседник из тестового чата пишет сообщение; владельцу в управляющий чат приходит черновик с кнопками; собеседнику **ничего** не приходит, пока владелец не нажал «Отправить».
- Проверка: после тестового сообщения `./ops/doctor.sh` показывает в строке `PASS archive` число сообщений больше нуля.
- Если собеседник получил ответ без нажатия кнопки — немедленно отключить бота в настройках Telegram и остановиться.
- Если владелец бизнес-режим пропускает — записать `./ops/state.sh set business skipped` и идти дальше.
- Запись: `done business-plugin`

### 8. Переписка — по желанию владельца
Экранов для этого в кабинете ещё нет; команды и их параметры — `docs/service.md`, раздел «Как пользоваться без веб-интерфейса». Каждый пункт предлагать отдельно и делать только после согласия.

8а. Загрузка истории из экспорта Telegram Desktop: `./ops/import-export.sh scan /путь/к/result.json`, затем `import`. Вывод `scan` — названия чатов владельца: команду запускает владелец либо агент по его явной просьбе. Какие чаты исключить, решает владелец.
- Проверка: `./ops/doctor.sh` — в строке `PASS archive` число сообщений выросло.

8б. Поиск по смыслу — **стоп-точка** (скачивание около 0,5 ГБ, около 1,2 ГБ памяти): `./ops/embeddings.sh on`.
- Проверка: `PASS embeddings`; `./ops/embeddings.sh status` показывает счётчики.
- Сервер начал тормозить или появился `FAIL` — `./ops/embeddings.sh off`.

8в. Аккаунт Telegram — **стоп-точка, выполняет только человек.** Владелец в своём терминале: `./ops/init-env.sh` (ключи приложения Telegram, остальные вопросы — Enter), `./ops/up.sh`, `./ops/tg-login.sh assistant` или `./ops/tg-login.sh owner`. Порядок — `docs/setup.md`. Агент ждёт слова «готово».
- Проверка: `docker exec shturman-service shturman call GET /api/tg/accounts` показывает аккаунт со статусом без ошибки. Чаты для чтения выбирает владелец — `docs/service.md`.

- Запись: `done archive`; если владелец всё пропускает — `./ops/state.sh set archive skipped`.

### 9. Итог
- Проверка: все шаги отмечены в `./ops/state.sh show`; `./ops/doctor.sh` показывает `PASS wizard`.
- `./ops/backup.sh` — первая копия. Ожидаются строки «Копия готова» и «Копия базы готова».
- Сообщить человеку: версия Hermes и версия «Штурмана»; что работает; что отправка сообщений выключена и почему; что из шага 8 не сделано; где лежат данные (каталог `data/`) и копии (`local/backups`); что копии делаются вручную, по расписанию — пока нет.

## Если вход перестал работать

1. `./ops/doctor.sh`. `FAIL plugin` — запустить `./ops/up.sh`: он включит плагин и перезапустит Hermes.
2. Плагин включён, но дашборд не отвечает — посмотреть `docker logs --tail 50 shturman-hermes`. Если плагин не загружается, включить аварийный вход: `./ops/emergency-access.sh on` и объяснить владельцу, как открыть дашборд через SSH-туннель. Снаружи адрес в этом режиме закрыт.
3. После починки — `./ops/emergency-access.sh off` и снова `./ops/doctor.sh`.

## Сервис переписки не отвечает

Вход, мастер и бот от сервиса не зависят: пока он не работает, ассистент отвечает владельцу, но архива не видит, а сообщения бизнес-режима копятся в памяти плагина и при долгом простое теряются.

| Строка `./ops/doctor.sh` | Что смотреть |
|---|---|
| `WARN service: сервис переписки не развёрнут` | Контейнера нет: `./ops/up.sh` |
| `FAIL service` | `docker logs --tail 50 shturman-service` — причина отказа запуска названа в последних строках. Если база не поднялась — следующая строка таблицы |
| `FAIL database` | `docker logs --tail 50 shturman-postgres`; свободное место — строка `disk` |
| `FAIL archive-mcp` | Запись в настройках Hermes пропала: `./ops/up.sh` запишет её и перезапустит Hermes |
| `FAIL archive: сервис не отдал состояние` | Сервис жив, но не отвечает на запрос состояния: `docker logs --tail 50 shturman-service` |
| `WARN jobs` | Задания копятся: Hermes их не забирает. Проверить `PASS hermes`, `PASS plugin`, `PASS bot-token`; журнал — `docker logs --tail 50 shturman-hermes` |
| `WARN service-owner` | Бот не привязан в мастере или шлюз ещё не сообщил владельца: подождать минуту после запуска, затем шаг 6 |
| `FAIL embeddings` | `docker logs --tail 50 shturman-embeddings`; не хватает памяти — `./ops/embeddings.sh off` |
| Сборка образа в `./ops/up.sh` завершилась ошибкой | Нет доступа в интернет к пакетам или не хватило места на диске. Повторить один раз; не помогло — стоп |

В журналах сервиса нет текста сообщений, но есть номера чатов и виды ошибок. Журнал показывать владельцу можно, пересылать куда-либо — нет. Две неудачи подряд — остановиться и описать проблему. Данные (`data/`) при разборе не трогать и не читать.

## Откат

Остановить стек без удаления данных; бота в бизнес-настройках Telegram отключает человек. Если владелец входил в аккаунты Telegram, эти сессии он завершает сам в Telegram: «Настройки → Устройства». Всё, что удаляет данные (`data/`, тома, `down -v`), — стоп-точка. Возврат на прежнюю версию — `UPGRADING.md`, «Откат».
