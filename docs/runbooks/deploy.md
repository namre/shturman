# Развёртывание базового экземпляра

**Версия runbook:** 0.0.3 · **Для `VERSION`:** 0.0.2 · **Состояние: черновик.** Шаги 1–4 пройдены на живом сервере 2026-10-06 (Ubuntu 24.04, Hermes 0.21.5). Шаги 5–7 переписаны под вход и мастер настройки версии 0.0.2: скрипты и мастер проверены на стенде, на живом сервере в этом виде не пройдены.

## Цель и критерий готовности

На чистом сервере работает стоковый Hermes из официального образа с управляющим ботом, который отвечает только владельцу, и с установленным бизнес-плагином. Критерий: владелец написал боту и получил ответ; сообщение с постороннего аккаунта осталось без ответа; `hermes doctor` без ошибок.

Дополнительный аккаунт, архив и импорт истории в этот runbook не входят. Имя и характер ассистента владелец выбирает сам на первом шаге мастера.

## Предусловия

- Сервер Linux, доступ по SSH, пользователь с правом запускать Docker.
- У владельца готовы: адрес (домен), направленный на сервер; Telegram на телефоне или компьютере; ключ провайдера модели либо подписка ChatGPT. Бота он создаст по подсказке мастера, свой числовой Telegram ID ему знать не нужно.
- Репозиторий склонирован, агент запущен в его корне.

## Инварианты

Действуют все инварианты, стоп-точки и запреты из `AGENTS.md`. Дополнительно для этого runbook:

- Бота нельзя подключать в бизнес-режиме в настройках Telegram до шага 7.
- Ссылку из `./ops/activation-link.sh` передать владельцу и больше нигде не сохранять.
- На сервере не должно быть посторонних контейнеров. Нашлись — стоп.

## Шаги

Формат шага: действие → проверка → запись состояния. Провал проверки дважды — стоп.

### 1. Состояние
`./ops/state.sh show`. Если шаги уже отмечены — продолжить со следующего.

### 2. Проверка сервера
`./ops/preflight.sh`
- Ожидается: `ИТОГ: OK`. Строки `WARN` объяснить человеку простыми словами.
- `FAIL docker` — **стоп-точка**: установка Docker требует `sudo`. Получить согласие, ставить по официальной инструкции Docker для дистрибутива, после — повторить preflight.
- `WARN net:telegram` или `net:openai` — **стоп-точка**: без исходящего маршрута дальше идти бессмысленно. Объяснить, что нужен прокси (`EGRESS_PROXY_URL`), и что доступ к провайдеру модели из неподдерживаемого региона нарушает его условия и может стоить аккаунта. Решение принимает человек.
- Запись: `./ops/state.sh done preflight`

### 3. Служебные значения
`./ops/init-env.sh --auto` — генерирует пароль базы и внутренние токены, ничего не спрашивает и не печатает значений. Файл `.env` не читать.
- Проверка: `./ops/preflight.sh` показывает `PASS env: есть, права 600`.
- Токены и ключи владельца здесь не вводятся: их вводит владелец в мастере настройки на шаге 6, порядок — `docs/setup.md`.
- Запись: `./ops/state.sh done env`

### 4. Версия Hermes
В `compose.yaml` указана версия официального образа, с которой расширения проверены. Показать её человеку. Если он хочет другую — записать `HERMES_VERSION=<версия>` в `.env` командой `echo` с добавлением в конец файла (сам файл не читать) и предупредить, что она не проверена. Образ не пересобирать и не менять. Теги `latest` и `main` не использовать.
- Проверка: после шага 5 `./ops/doctor.sh` показывает образ с явной версией.
- Запись: `./ops/state.sh set hermes.image <версия>` и `done pin`

### 5. Внешний адрес, прокси и запуск
5а. Спросить у владельца адрес, по которому он будет открывать ассистента, и записать его: `./ops/set-public-url.sh https://адрес`.
- Проверка: скрипт печатает записанный адрес.

5б. **Стоп-точка (`sudo`, TLS, порты).** Настроить обратный прокси на хосте по образцу `config/Caddyfile.example`: страницы входа из `plugins/shturman/public` по пути `/shturman-auth/`, всё остальное — на `127.0.0.1:9119`. Заголовок `Host` не подменять. Перед выполнением показать человеку итоговую настройку и получить согласие.
- Проверка: проверка синтаксиса настройки проходит; сертификат для адреса получен.

5в. `./ops/up.sh` — скачивает образ (около 4 ГБ, несколько минут), запускает стек, включает плагин `shturman` и сам вызывает `./ops/doctor.sh`.
- Ожидается: `PASS hermes`, `PASS dashboard`, `PASS dashboard-bind`, `PASS plugin`, `PASS public-url`, `PASS login`, `PASS login-page`, `ИТОГ: OK`. Предупреждения про токен бота, владельца, мастер и плагин бизнес-режима на этом шаге нормальны.
- `FAIL login-page` — прокси не отдаёт страницы входа: вернуться к 5б.
- Проверка: `docker ps` показывает только контейнеры этого стека.
- Запись: `done hermes-up`

### 6. Первый вход владельца и мастер — стоп-точка
6а. Убедиться, что владелец на связи и готов потратить десять минут. Выполнить `./ops/activation-link.sh` и передать ему ссылку как есть. Ссылка действует 30 минут и один раз; если не успел — выдать новую.

6б. Владелец в браузере проходит шаги мастера «Помощник», «Модель» и «Бот в Telegram». Агент в это время ничего не делает и значений не спрашивает. Дождаться слова «готово».
- Проверка: `./ops/doctor.sh` показывает `PASS bot-token`, `PASS bot-owner`.
- Проверка (делает человек): написать боту «привет» — пришёл ответ. Написать с другого аккаунта — ответа нет. Выйти из дашборда и войти снова — по кнопке «Получить код в Telegram» бот прислал код, код подошёл.
- Запись: `done control-bot`

### 7. Бизнес-режим — по желанию владельца
Владелец на шаге мастера «Бизнес-режим» нажимает «Установить защиту»: мастер ставит официальный плагин бизнес-режима по полному SHA и перезапускает бота. Инструкции подключения в Telegram мастер показывает только после этого.
- Проверка: `./ops/doctor.sh` показывает `PASS business-plugin`.
- **Стоп-точка:** человек включает режим у @BotFather и подключает бота в настройках Telegram, выбрав для начала один тестовый чат.
- Проверка (делает человек): собеседник из тестового чата пишет сообщение; владельцу в управляющий чат приходит черновик с кнопками; собеседнику **ничего** не приходит, пока владелец не нажал «Отправить».
- Если собеседник получил ответ без нажатия кнопки — немедленно отключить бота в настройках Telegram и остановиться.
- Если владелец бизнес-режим пропускает — записать `./ops/state.sh set business skipped` и идти дальше.
- Запись: `done business-plugin`

### 8. Итог
- Проверка: все шаги отмечены в `./ops/state.sh show`; `./ops/doctor.sh` показывает `PASS wizard`.
- Сообщить человеку: версия Hermes, что работает, что не входит в этот этап, где лежат данные (том), что резервного копирования пока нет.

## Если вход перестал работать

1. `./ops/doctor.sh`. `FAIL plugin` — запустить `./ops/up.sh`: он включит плагин и перезапустит Hermes.
2. Плагин включён, но дашборд не отвечает — посмотреть `docker logs --tail 50 shturman-hermes`. Если плагин не загружается, включить аварийный вход: `./ops/emergency-access.sh on` и объяснить владельцу, как открыть дашборд через SSH-туннель. Снаружи адрес в этом режиме закрыт.
3. После починки — `./ops/emergency-access.sh off` и снова `./ops/doctor.sh`.

## Откат

Данных владельца на этом этапе ещё нет. Откат: отключить бота в бизнес-настройках Telegram (делает человек), остановить стек без удаления томов. Удаление томов — стоп-точка.

## Что должно появиться после спайка

`ops/smoke.sh`, `ops/backup.sh`, `ops/restore.sh`; этот runbook проходит проверку на чистом сервере целиком.
