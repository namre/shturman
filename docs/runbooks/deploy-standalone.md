# Развёртывание экземпляра без Hermes («только архив и согласования»)

**Для кого:** ИИ-агент (Claude Code, Codex) — на сервере в корне репозитория или с компьютера владельца по SSH (`prompts/deploy-standalone.md`, `prompts/deploy-remote.md`). **Состояние:** черновик — с настоящими ботом Telegram, аккаунтом и моделью не пройден ни разу. Вывод не совпал с ожидаемым — стоп.

Что это за режим, чего в нём нет и что из написанного проверено — `docs/standalone.md`. Установка с Hermes — `docs/runbooks/deploy.md`.

## Цель и критерий готовности

На чистом сервере работают сервис переписки и база; Hermes не установлен; владелец настроил переписку на странице «Настройки Штурмана» или сознательно отложил это. Критерий: `./ops/doctor.sh` показывает `ИТОГ: OK`, `PASS service`, `PASS setup-page`, `PASS setup-origin`; `docker ps` показывает только `shturman-service` и `shturman-postgres`.

Первая настройка у владельца — страница «Настройки Штурмана»: бот согласований, выбор одного из двух способов подключения и шаги этого способа. Внешнего адреса у экземпляра нет, поэтому страница открывается через туннель SSH с компьютера владельца. Бота согласований владелец создаёт и вводит сам, первым шагом страницы: без него запросы, которые должен подтвердить владелец, отклоняются, а карточки доставлять некому. Подключение архива к Codex CLI или Claude Code — шаг 6, своя модель сервиса — шаг 7, дополнения — шаг 8; всё по желанию владельца. Отправка сообщений в этот runbook не входит и остаётся выключенной.

## Как говорить с владельцем

Владелец решает, ты объясняешь. На каждой стоп-точке — готовая фраза ниже (строки «> »): что ты сделаешь, что изменится для него, чем грозит; затем жди явного «да». Команды показываешь, если он просит или если этого требует стоп-точка, но согласие он даёт на смысл, а не на текст команды. После шага — итог одной фразой: что готово и что дальше от него.

В этом варианте честно говори, где нужен его терминал: туннель к странице настроек (и к архиву, если клиент на его компьютере) и ключ доступа к архиву для его клиента. Без терминала эти два шага не пройти; другого пути сейчас нет (`docs/standalone.md`, «Для владельца»). Команды подсказываешь ты, запускает он; что они печатают, тебе знать не нужно.

## Предусловия

- Сервер Linux, доступ по SSH, пользователь с правом запускать Docker.
- У владельца готовы: Telegram на телефоне; компьютер с терминалом, с которого он входит на сервер по SSH. Домен, обратный прокси и TLS не нужны: у экземпляра нет веб-адреса.
- Для шага 7, если владелец его хочет: ключ провайдера модели с API, совместимым с OpenAI, и точное имя модели. Бот согласований — отдельный бот у @BotFather, которым не пользуется ни одна другая программа.
- Репозиторий склонирован и переключён на последний выпуск: `./ops/install-ref.sh` (до `./ops/init-env.sh`; повторный запуск безвреден), агент запущен в его корне.

## Инварианты

Действуют все правила `AGENTS.md`. Дополнительно для этого runbook:

- Журналы контейнеров агент не читает — вместо них `./ops/diag.sh --print` и `./ops/resources.sh` (пояснение 3). Каталог `data/` и содержимое базы не читать; о состоянии архива судить по счётчикам `./ops/doctor.sh`.
- Ссылку из `./ops/setup-link.sh` выдавать только по явной просьбе владельца, передать как есть и нигде не сохранять — либо владелец запускает скрипт сам.
- На страницу «Настройки Штурмана» не заходить, её адреса не запрашивать, что владелец на ней ввёл — не спрашивать.
- Токен бота и ключ модели вводит только владелец — на странице «Настройки Штурмана» либо в своём терминале: `./ops/init-env.sh` без `--auto` агент не запускает, значений не просит, файл `.env` не читает.
- `./ops/mcp-token.sh` запускает только владелец; его вывод не читать и не просить (пояснение 2). `./ops/connect.sh` запускать можно: токен он не печатает. В настройки клиента владельца вписывается имя переменной окружения, а не значение токена.
- Ссылку из `./ops/bot-bind.sh` передать владельцу как есть и нигде не сохранять — либо владелец запускает скрипт сам.
- Наружу ничего не публиковать: порт 8765 остаётся на `127.0.0.1`, обратный прокси перед ним не ставить, внешний адрес странице «Настройки Штурмана» не задавать (пояснение 1).
- Отправку не включать: строку `SHTURMAN_SENDING` в `.env` не добавлять.
- `./ops/tg-login.sh` — запасной путь, запускает только человек; его вывод не читать и не просить.
- Посторонние контейнеры на сервере — стоп.

## Шаги

Формат шага: действие → проверка → итог владельцу одной фразой; затем `./ops/state.sh done <шаг>`. Провал проверки дважды — стоп.

### 1. Состояние и вариант установки

`./ops/state.sh show`. Первая строка называет режим установки. Шаги уже отмечены — продолжить со следующего.

Шагов ещё нет — **до любого другого действия** спросить, какой вариант ставится (если стартовый промпт уже спросил и владелец ответил — не переспрашивать). Выбирает владелец; стартовый промпт или runbook — не ответ. Отличия — `docs/standalone.md`, «Что это».

> Какой из двух вариантов ставим? 1. **«Ассистент в Telegram»** — ассистент отвечает вам в Telegram, ведёт архив переписки, готовит ответы и сводки. 2. **«Только архив и согласования»** — без ассистента в Telegram: архив переписки с поиском и список договорённостей, вопросы вы задаёте из своего Codex или Claude Code; для него вам самому понадобится терминал на вашем компьютере.

Выбран первый — этот runbook закрыть, идти по `docs/runbooks/deploy.md`.

- Развёртывание начато по runbook прежней версии (в состоянии есть шаги `secrets` или `owner-bind`): бот и модель уже настроены — бот теперь первый шаг страницы (шаг 5), модель — шаг 7; идти дальше с шага 5, бота заново не заводить.
- Итог владельцу: ставим «Только архив и согласования».
- Запись: `./ops/state.sh done choice`

### 2. Проверка сервера

`./ops/preflight.sh`
- Проверка: `ИТОГ: OK`. Строки `WARN` пересказать простыми словами.
- `FAIL docker` — **стоп-точка** (`sudo`): после «да» поставить Docker по официальной инструкции для дистрибутива и повторить preflight.

> Для работы архива на сервер нужно поставить служебную программу, которая запускает его части, — из официального источника. Нужны права администратора. Пользователь, под которым работает архив, получит право управлять ею, а это равно правам администратора сервера; для такого сервера это обычно. Ставлю?

- `WARN net:telegram` — **стоп-точка**: без маршрута к Telegram сервис не войдёт в аккаунт и не будет принимать сообщения; нужен прокси (`EGRESS_PROXY_URL`). Решает владелец. `WARN net:openai` важно, только если он берёт модель у OpenAI.

> Сервер не достаёт до Telegram (или до провайдера модели). Нужен промежуточный выход в интернет, который настраиваете вы или ваш администратор; тот, кто его держит, будет видеть, к каким сервисам и когда обращается сервер (содержимое — нет, оно зашифровано). Обходить ограничения провайдера модели из неподдерживаемой страны — нарушение его условий: можно потерять аккаунт. Настроите такой выход и дадите мне его адрес — или остановимся здесь?

- Итог владельцу: сервер проверен, что не так — простыми словами.
- Запись: `./ops/state.sh done preflight`

### 3. Часовой пояс, режим и служебные значения

3а. **Город — один раз.** Если владелец уже назвал город (стартовым промптом или при подготовке сервера) — не переспрашивать. Иначе:

> В каком городе вы живёте? По вашему времени сервис будет считать тихие часы уведомлений (23:00–08:00), ночной разбор, сроки договорённостей и напоминания.

По умолчанию — Москва (`Europe/Moscow`). Екатеринбург — `Asia/Yekaterinburg`, Астрахань — `Europe/Astrakhan`, Новосибирск — `Asia/Novosibirsk`; полный список — `timedatectl list-timezones`. Утренней сводки и обзора недели в этом режиме нет — их присылает ассистент Hermes. Пояс не секретный.

3б. `./ops/init-env.sh --auto --mode standalone --timezone <пояс>` — записывает режим без Hermes и часовой пояс (`SHTURMAN_TIMEZONE`), а с кандидата — ещё канал обновлений `pilot` (строка «[SHTURMAN_UPDATE_CHANNEL]…» в выводе), генерирует пароль базы и два токена сервиса. Ничего не спрашивает и не печатает значений, кроме режима, пояса и канала обновлений. Файл `.env` не читать.
- Проверка: строки `[SHTURMAN_MODE] записан режим: standalone` и `[SHTURMAN_TIMEZONE] записан пояс: <пояс>`, а с кандидата — `[SHTURMAN_UPDATE_CHANNEL] установлен кандидат … — канал обновлений: pilot` (нет её — стоп, строка дефекта); `./ops/mode.sh` — `Режим: standalone`; `./ops/preflight.sh` — `PASS env: есть, права 600`.
- «неизвестный часовой пояс» — опечатка: сверить с `timedatectl list-timezones` и повторить.
- «Режим уже выбран: hermes» — на этом сервере уже начата установка с Hermes: **стоп**. Смена режима на работающем экземпляре — отдельная процедура (`docs/standalone.md`, «Переход между режимами»).
- Итог владельцу: время записано, тихие часы и напоминания пойдут по нему.
- Запись: `./ops/state.sh set mode standalone`, `done timezone` и `done env`

### 4. Запуск

`./ops/up.sh` — скачивает образ базы, собирает образ сервиса переписки (первая сборка — несколько минут, нужен интернет для пакетов), запускает базу и сервис и сам вызывает `./ops/doctor.sh`. Образ Hermes не скачивается.
- Проверка: три строки «пропущено: режим без Hermes — …», затем `PASS mode: без Hermes…`, `SKIP hermes`, `PASS service`, `PASS service-bind`, `PASS database`, `PASS timezone: часовой пояс владельца: <пояс>`, `PASS archive-mcp`, `PASS archive` с нулями, `PASS jobs`, `PASS jobs-failing`, `PASS setup-page`, `PASS setup-origin: внешнего адреса … нет, как и положено без Hermes`, `ИТОГ: OK`. Строк `hermes-tz` и `cron-schedule` в этом режиме нет.
- Проверка: `docker ps` — только `shturman-service` и `shturman-postgres`.
- Нормальны на этом шаге: `WARN setup-state: …Переписка ещё не настроена`, `WARN approvals-bot: …не настроен`, `WARN model: …не настроена`, `WARN embeddings`, `WARN guard`.

| Строка или сообщение | Что делать |
|---|---|
| `WARN setup-origin: режим без Hermes, а у страницы настройки задан внешний адрес` | Остался от режима с Hermes. **Стоп-точка** — фраза ниже; после «да» — `./ops/set-setup-url.sh --clear`, затем `./ops/up.sh` |
| `WARN service-bind` со словами «нет программы ss» | Нет пакета `iproute2`, проверка адресов не выполнена: сказать владельцу; установка — стоп-точка (`sudo`) |
| «`SHTURMAN_PUBLIC_URL` (или `SHTURMAN_SETUP_URL`) в .env записан не как адрес…» | Скрипт остановился до запуска: строка осталась от режима с Hermes или вписана вручную. В этом режиме обе не нужны; что с ними делать, решает владелец |
| «Сервис переписки не ответил за 90 секунд», `FAIL service`, `FAIL database`, `FAIL archive` | Раздел «Если что-то не работает» |
| `FAIL service-bind`, `FAIL archive-mcp: …ответил без токена` | **Стоп**: стек остановить, не удаляя данных, разобраться с `compose.override.yaml` |

> На сервере осталась настройка от варианта с ассистентом: по ней страница настроек должна была открываться из интернета. В этом варианте наружу ничего не открывается — уберу эту настройку и перезапущу архив на несколько секунд; страница будет открываться только с вашего компьютера. Убираю?

- Итог владельцу: архив запущен, пока пустой; дальше — страница настроек (шаг 5).
- Запись: `done stack-up`

### 5. Переписка: страница настройки — стоп-точка

На странице «Настройки Штурмана» владелец сначала создаёт бота согласований и привязывает себя к нему, затем выбирает способ: «Через ваш аккаунт» — ключи приложения Telegram, вход в свой аккаунт по QR-коду (только чтение), выбор чатов; «Через бота и помощника» — бизнес-режим Telegram у бота согласований для личных чатов, для групп по желанию — ключи приложения и отдельный аккаунт помощника. Что он видит — `docs/setup.md`, «Страница „Настройки Штурмана“»; туннель — `docs/standalone.md`, «Страница „Настройки Штурмана“ через туннель SSH».

5а. До ссылки пересказать простыми словами:
- страница открывается только с его компьютера: сначала он открывает туннель SSH в своём терминале и оставляет окно открытым; команду напечатает скрипт;
- первым шагом он создаст у @BotFather **новый бот** — бот согласований (`/newbot`) — и сам вставит токен на странице; это пульт с кнопками «Да» и «Нет», через него приходят карточки с договорённостями; токен он никому не показывает и в чат не вставляет; кнопкой «Создать бота в одно нажатие» лучше не пользоваться — токен такого бота может получить держатель посредника (`docs/approvals-bot.md`);
- «Через ваш аккаунт» — сервис входит в его аккаунт **только на чтение** и ничего не отправляет (только кладёт текст в поле ввода, когда он нажмёт «В чат»), но вход в основной аккаунт хранится на сервере и в копиях; «Через бота и помощника» — входа в основной аккаунт нет, личные чаты видны через бизнес-режим (только новые сообщения; Telegram Premium не нужен), группы — через аккаунт помощника на втором номере. Telegram может ограничить подключённый аккаунт при любом способе. Выбирает он; сменить можно позже;
- читаются только чаты, которые он сам отметит или откроет боту; их сообщения сохраняются на сервере;
- ключи приложения, если понадобятся, — на my.telegram.org, страница подскажет; ни агенту, ни в чат их не присылать.

> Теперь страница «Настройки Штурмана». Наружу сервер её не показывает, поэтому открывается она только с вашего компьютера: в терминале вы запускаете одну команду — она соединяет ваш компьютер с сервером защищённым каналом, — и пока это окно открыто, страница работает. Без терминала в этом варианте не обойтись, команду я подскажу. На странице вы сами заведёте у @BotFather бота для кнопок «Да» и «Нет» (кнопкой «в одно нажатие» лучше не пользоваться: ключ такого бота может получить держатель посредника). Потом решите, как сервис будет видеть переписку: через ваш аккаунт — тогда вход в него хранится на сервере и в копиях, — или через бота и помощника. При любом способе Telegram может ограничить подключённый аккаунт. Читаться будут только чаты, которые вы сами выберете. Права бота отвечать на сообщения не давайте: с ним писать от вашего имени сможет любой, у кого есть ключ бота. Ссылку на страницу можете получить сами одной командой на сервере — тогда её не увидит никто, кроме вас, — или я выдам её по вашей просьбе. Можно и отложить.

5б. **Ссылка входа — стоп-точка, только по явной просьбе владельца в текущей сессии**: `./ops/setup-link.sh`; лучше, если скрипт запускает сам владелец. Скрипт печатает ссылку вида `http://127.0.0.1:8765/shturman-setup/#…` и команду туннеля. Ссылку передать как есть, нигде не сохранять — ни в состоянии, ни в журнале, ни в отчёте; самому не открывать. Действует 30 минут и один раз.

> Вот ссылка на страницу настроек и команда для терминала на вашем компьютере. Сначала запустите команду и не закрывайте окно, потом откройте ссылку в браузере. Ссылка одноразовая, действует 30 минут и даёт право настраивать сбор вашей переписки — откройте её сразу и никому не пересылайте; она прошла через меня и провайдера моей модели. Что вы там вводите, мне знать не нужно; когда закончите, напишите «готово».

- «контейнер shturman-service не запущен» — шаг 4.
- «сервис не выдал ссылку» — образ сервиса прежней версии: `./ops/up.sh`.

5в. Владелец открывает туннель, затем ссылку и проходит шаги: бот согласований, выбор способа, шаги способа. Агент ничего не делает, на страницу не заходит, значений не спрашивает, способ не выбирает; ждёт «готово».
- Проверка: `./ops/doctor.sh` — `PASS approvals-bot: бот согласований на связи с Telegram` и `PASS approvals-owner`. `FAIL approvals-bot` с кодом неполадки — шаг 7б, разбор кодов. `WARN approvals-owner` — владелец не нажал «Запустить» в боте: вернуться к первому шагу страницы.
- Проверка: `PASS setup-state` — «Через ваш аккаунт»: `ключи приложения Telegram: заданы, аккаунтов Telegram: 1, сообщений в архиве: N` (пока история загружается, N растёт); «Через бота и помощника»: аккаунтов может быть 0 — строка проходит, когда подключён бизнес-режим или в архиве есть сообщения (появляются с новыми входящими, шаг 8г).
- Страница не открывается у владельца — туннель не открыт либо порт слева в команде туннеля не 8765.
- Итог владельцу: карточки с кнопками будут приходить в бота согласований; всё, что расширяет то, что сервис читает и делает, ждёт его нажатия там.
- Отложил — `./ops/state.sh set setup-page skipped` и дальше.
- Запись: `done setup-page`

### 6. Архив для Codex CLI или Claude Code — по желанию владельца

6а. Спросить, где работает его клиент — на этом сервере или на его компьютере — и по какому адресу он входит на сервер по SSH. `./ops/connect.sh --ssh пользователь@сервер` — показать ему вывод целиком. Скрипт токен не печатает.

Его вы забираете сами командой в своём терминале — я её подскажу, но не запускаю: ключ открывает на чтение всю вашу переписку, и через меня ему проходить нельзя. Мне его не показывайте и в чат не вставляйте. Если клиент на вашем компьютере, нужен тот же защищённый канал к серверу, что и для страницы настроек. Помните: клиент отправляет прочитанное из архива своему провайдеру модели и хранит историю по своим правилам, а чужое сообщение в архиве может попытаться им управлять — не запускайте его без подтверждения действий и лучше не на самом сервере. Подключаем?

6б. **Выполняет только владелец:** шаг 1 из вывода (токен в переменную окружения: `./ops/mcp-token.sh --pipe`, для своего компьютера — `--out` и `scp`; без терминала человека скрипт откажет), для своего компьютера — ещё туннель SSH, затем настройка клиента. Агент `./ops/mcp-token.sh` не запускает; ждёт «готово».

- Запись: `done connect`; пропускает — `./ops/state.sh set connect skipped`.

### 7. Договорённости: своя модель — по желанию владельца

Бот согласований владелец заводит на шаге 5; здесь — модель и запасной путь для бота. Без модели экземпляр — архив с поиском. С ней сервис сам разбирает новые сообщения — днём раз в час и ночью (`docs/memory.md`, «Расписание прогонов») — и присылает найденные договорённости карточками в бота согласований. Предлагать после шагов 5 и 6, не как обязательное.

7а. Что понадобится владельцу: ключ провайдера модели и точное имя модели; если провайдер не OpenAI — ещё адрес его API (для OpenRouter — `https://openrouter.ai/api/v1`); если бот согласований на шаге 5 не заведён — **новый бот** у @BotFather.

> Если подключить сервису модель, он будет сам находить в переписке договорённости — что обещали вы и что обещали вам — и присылать их в бот кнопками. Для этого законченные разговоры читаемых чатов днём раз в час и ночью уходят провайдеру модели; это его счёт, по подписке — ваш общий лимит. Ключ вы вводите сами на странице настроек, раздел «Дополнительно»; мне его не присылайте. Без модели остаётся архив с поиском. Подключаем?

7б. **Стоп-точка, вводит только владелец.** Основной путь — страница «Настройки Штурмана» (ссылка — шаг 5б): ключ и имя модели — «Дополнительно»; токен бота и привязка владельца, если их ещё нет, — шаг 1 страницы. Значения применяются сразу. Запасной путь — терминал владельца: `./ops/init-env.sh` (скрытый ввод; на ненужный вопрос — Enter), затем `./ops/up.sh`. Агент значений не спрашивает; ждёт «готово».
- Проверка: `PASS approvals-bot: бот согласований на связи с Telegram`, `PASS model: модель <имя> настроена, обращений ещё не было`.
- `WARN approvals-bot: …ещё не начал опрос` — повторить `./ops/doctor.sh` через минуту.
- `FAIL approvals-bot` с кодом — `docker exec shturman-service shturman bot-status` даёт расшифровку. `token_rejected`, `bad_token_format` — токен введён неверно: владелец вводит его заново на странице (в терминальном пути — удаляет строку `SHTURMAN_BOT_TOKEN` из `.env` и повторяет). `other_poller`, `webhook`, `conflict` — ботом пользуется другая программа: нужен отдельный бот. `no_connection` — нет маршрута к Telegram: шаг 2.
- Ключ, введённый на странице, проверяется сразу (короткий вопрос модели, причина отказа — там же); токен бота — запросом к Telegram. В терминальном пути ключ не проверяется до первого разбора (пояснение 4).
- Адрес API на странице — только `https://` и только в интернете. Локальную модель (например, Ollama) владелец задаёт строкой `SHTURMAN_LLM_BASE_URL` в `.env` в своём терминале; со страницы такой адрес не меняется.
- Итог владельцу: модель подключена; первые договорённости придут в бота после ближайшего разбора.
- Запись: `done secrets`

7в. Привязка владельца к боту — **стоп-точка.** Обычно уже сделана на шаге 5: тогда проверить `PASS approvals-owner` и записать шаг. Кто первым откроет одноразовую ссылку в Telegram и нажмёт «Запустить», тот и получает карточки и право нажимать кнопки. На странице ссылку владелец получает сам, кнопкой на шаге 1. В терминальном пути — `./ops/bot-bind.sh`: лучше, если его запускает владелец; агент — только по его явной просьбе, ссылку передаёт как есть и нигде не сохраняет. Действует 15 минут, один раз.

> Вот ссылка, которая делает вас хозяином бота согласований. Кто первым откроет её в Telegram и нажмёт «Запустить», тот и будет получать карточки и нажимать кнопки за вас. Ссылка одноразовая, действует 15 минут и прошла через меня и провайдера моей модели — откройте её сразу и никому не пересылайте.

- Проверка (делает человек): бот ответил «Готово: вы привязаны как владелец». `./ops/doctor.sh` — `PASS approvals-owner`.
- Итог владельцу: бот согласований ваш; кнопки в нём принимаются только от вас.
- Запись: `done owner-bind`; весь шаг пропущен — `./ops/state.sh set secrets skipped`.

### 8. Позже, по желанию владельца

Для первой настройки ничего из этого не нужно. Один раз перечислить, что есть; каждое — отдельно, только после согласия. На сервере с 4 ГБ из тяжёлых дополнений помещается одно — расшифровка голосовых **или** поиск по смыслу с защитой (`docs/voice.md`, «Какой сервер нужен»).

8а. **Выгрузка из Telegram Desktop** — прошлое глубже, чем загружает сессия, и единственный путь к прошлому личных чатов в бизнес-режиме. Основной путь — страница «Настройки Штурмана» (ссылка — шаг 5б). Запасной — `./ops/import-export.sh scan /путь/к/result.json`, затем `import`: вывод `scan` — названия чатов, поэтому запускает владелец либо агент по его явной просьбе.
- Проверка: `PASS archive` — число сообщений выросло.

8б. **Поиск по смыслу — стоп-точка** (скачивание около 0,5 ГБ, до 1,2 ГБ памяти): `./ops/embeddings.sh on`. Модель по умолчанию — `e5-small`; `user2-small` — только по решению владельца после пересказа `docs/search.md` (`./ops/embeddings.sh on --model user2-small`). Смена модели на работающем экземпляре — отдельная стоп-точка: пересчёт всех векторов.

> Поиск по смыслу находит сообщение в архиве, даже если вы не помните слов из него, — для вашего клиента и для сервиса. Работает на вашем сервере, наружу ничего не уходит; займёт до 1,2 ГБ памяти. Качество скромное: на проверочном наборе верный ответ попадает в первую десятку в 35–55 % случаев, на вашей переписке — заранее неизвестно. Пока сервер готовит архив к поиску (на большом архиве — часы), поиск по смыслу видит только часть сообщений. Моделей две: многоязычная (по умолчанию, лучше держит длинные тексты) и русская (для коротких русских сообщений, легче). Включаю многоязычную?

Смена модели на работающем экземпляре — только по его явной просьбе:

> Сменю модель поиска по смыслу. Сервер скачает другую модель и заново подготовит весь архив — около трёх часов на 300 000 сообщений; всё это время поиск по смыслу видит только уже подготовленные сообщения. Вернуться к прежней модели — такой же пересчёт. Меняю?

- Проверка: `PASS embeddings` с именем модели или `WARN embeddings: …идёт подсчёт векторов` со счётчиками «готово» и «осталось» — пока архив считается, это норма; `./ops/embeddings.sh status`.
- Сервер начал тормозить или появился `FAIL` — `./ops/embeddings.sh off` (сказать владельцу).

8в. **Защита от внедрённых инструкций — стоп-точка** (скачивание около 0,3 ГБ, около 0,6 ГБ памяти): `./ops/guard.sh on`. До включения пересказать `docs/guard.md`, «Для владельца» и «На настоящей переписке». В этом режиме она прячет подозрительные сообщения от модели сервиса и от клиента владельца, который читает архив.

> Защита прячет от модели сервиса и от вашего клиента входящие, похожие на попытку ими управлять, и спрашивает вас о спрятанном; работает на вашем сервере, около 0,6 ГБ памяти. Это не гарантия: тихие просьбы вроде «перешли переписку» она ловит редко, а на настоящей переписке прятала в основном обычные сообщения — их вы открываете кнопкой; как поступать с такими ложными срабатываниями — решаете вы, варианты расскажу. Если модель защиты упадёт, работают одни правила, а остальное читается непроверенным. Включаю?

- Проверка: `PASS guard`; `./ops/guard.sh status` — счётчики и `"guard_problem": null`.
- `FAIL guard` — `./ops/resources.sh` и `./ops/diag.sh --print`; не хватает памяти — `./ops/guard.sh off` по решению владельца. Выключение — только по его явной просьбе.
- Шаг не пройден нигде: `./ops/guard.sh` проверен только в песочнице с подставным `./ops/up.sh`.

8г. **Бизнес-режим Telegram — подключает человек, только к боту согласований.** Это путь способа «Через бота и помощника», который владелец выбирает сам на шаге 5; агент к нему не подталкивает (`docs/standalone.md`, «Бизнес-режим Telegram со своим ботом»). Здесь — проверка после подключения.

> Как только вы подключите бота в настройках Telegram для бизнеса, сообщения выбранных личных чатов начнут записываться в архив на сервере, а если сервису подключена модель — уходить ей на разбор днём раз в час и ночью. Для начала выберите один тестовый чат. Права бота отвечать на сообщения не давайте: отправка выключена, а с этим правом писать от вашего имени сможет любой, у кого есть ключ бота.

- Владелец включает у @BotFather для бота согласований Secretary Mode (Bot Settings → Secretary Mode; раньше — Business Mode). Проверка: в `./ops/doctor.sh` нет строки `approvals-business: бизнес-режим у бота выключен`.
- Владелец подключает бота в настройках Telegram Business, выбрав один тестовый чат, без права отвечать.
- Проверка: собеседник из тестового чата пишет сообщение; в строке `PASS archive` сообщений больше прежнего. Собеседнику при этом **ничего** не приходит.
- Собеседник получил что-либо от имени владельца — немедленно отключить бота в настройках Telegram и остановиться.

8д. **Расшифровка голосовых и «кружков» — стоп-точка** (скачивание модели около 0,9 ГБ, сборка образа около 2,3 ГБ, около 1,4 ГБ памяти; только x86-64): `./ops/asr.sh on`. До включения пересказать `docs/voice.md`, «Для владельца». Перед запуском: `uname -m` — `x86_64`; `free -m` — свободно не меньше 1,8 ГБ; `./ops/preflight.sh` — строки `net:huggingface` и `net:pytorch` без `WARN`.

> Голосовые и «кружки» из читаемых чатов — не старше 30 дней и не длиннее 10 минут — станут текстом: поиск и договорённости будут работать с ними как с обычными сообщениями. Звук распознаётся на вашем сервере и не хранится. Получившийся текст, как обычная переписка, уходит провайдеру модели сервиса, если она подключена, и вашему клиенту, когда он читает архив. Распознавание ошибается примерно в 5 % слов на чистой речи, на шуме больше — имена и числа сверяйте. Нужно около 1,4 ГБ памяти и 4 ГБ диска. Включаю?

- 5–15 минут — в фоне: `nohup ./ops/asr.sh on > /tmp/shturman-asr.log 2>&1 &`, ждать `ИТОГ:` в конце файла.
- Проверка: `PASS voice`; счётчики — `./ops/asr.sh status`. Первую минуту контейнер загружает модель — `FAIL voice: контейнер распознавания речи не отвечает` в это время норма, повторить через минуту. Через две минуты всё ещё `FAIL` — `./ops/resources.sh`, `./ops/diag.sh --print` и стоп.
- Выключение (`./ops/asr.sh off`) — только по явной просьбе владельца.

8е. **Разбор фото и документов** включает **сам владелец** на странице «Настройки Штурмана», шаг «Фото и документы»; агент его не включает. Нужна своя модель сервиса (шаг 7). Назвать один раз:

> Можно включить пересказ фото и документов из переписки: что за документ, суммы, сроки. Для этого сами файлы уходят провайдеру модели сервиса, и каждый — отдельный запрос (по подписке — из вашего лимита). Включаете вы сами на странице настроек, шаг «Фото и документы».

- Проверка после его решения: строка `media` в `./ops/doctor.sh`.

8ж. **Сменить часовой пояс**: `./ops/init-env.sh --auto --timezone <пояс>`, затем `./ops/up.sh` (сервис перезапустится с новым поясом).
- Проверка: `PASS timezone` с новым поясом.

- Итог владельцу: что из дополнений включено, что нет.
- Запись: `done archive`; владелец всё пропускает — `./ops/state.sh set archive skipped`.

## Откат

Остановить стек без удаления данных. Сессии аккаунтов Telegram владелец завершает сам: «Настройки → Устройства». Бота в настройках Telegram Business, если его подключали, отключает человек. Подключение архива у клиента убирается командами из `docs/standalone.md`. Токен бота владелец может отозвать у @BotFather. Всё, что удаляет данные (`data/`, тома, `down -v`), — стоп-точка.

Возврат на прежнюю версию и восстановление из копии — `docs/runbooks/restore.md`. Переход на режим с Hermes — `docs/standalone.md`, «Переход между режимами».

## Что ещё должно появиться

Проход этого runbook на чистом сервере с настоящими аккаунтом, ботом и моделью; проверка ключа модели, заданного в `.env`, сразу после ввода, а не при первом разборе (на странице она уже есть); копии по расписанию; путь к странице настроек и ключу архива без терминала владельца.

## Пояснения

1. **Почему наружу ничего.** Без Hermes нет дашборда, а значит, нет и адреса, на котором чужой код мог бы соседствовать со страницей настроек; страница и архив слушают только `127.0.0.1:8765`, а владелец приходит к ним туннелем SSH — соединение шифрует сам SSH, поэтому по туннелю страница открывается по `http`. Порт слева в команде туннеля — именно 8765: сервис сверяет имя, под которым к нему обратились (`docs/standalone.md`, «Страница „Настройки Штурмана“ через туннель SSH»). Единственное исключение — необязательный внешний шлюз архива, только по явному решению владельца (`docs/remote-mcp.md`).
2. **Почему ключ архива — только у человека.** Токен архива открывает на чтение всю переписку из выбранных чатов. Всё, что агент прочитал, уходит провайдеру его модели, поэтому `./ops/mcp-token.sh` без терминала человека отказывает, а в настройки клиента пишется имя переменной, а не значение (`docs/standalone.md`, «Подключить Codex CLI или Claude Code»).
3. **Почему журналы — только пакетом.** В журнале базы бывают значения строк таблиц, то есть начало текста сообщений; в журнале сервиса — номера чатов и аккаунтов и фрагменты текста в исключениях базы. `./ops/diag.sh` берёт из журналов только виды ошибок и счётчики белым списком (`docs/deployment.md`, «Диагностический пакет»); его вывод можно показать владельцу, а сам журнал никуда не пересылать.
4. **Ключ модели из терминала.** Страница проверяет ключ коротким вопросом модели до сохранения. Строку в `.env` никто не проверяет: первое обращение будет при ближайшем разборе, когда найдётся законченный разговор (днём раз в час вне тихих часов, ночью в 03:30 по часам владельца, `docs/memory.md`, «Расписание прогонов»), и ошибку ключа покажет `WARN model: …последнее обращение не удалось`.
