# Развёртывание экземпляра без Hermes («только архив и согласования»)

**Версия runbook:** 0.0.5 · **Для `VERSION`:** 0.0.7 · **Состояние: черновик.** Шаги 3 и 4 пройдены 2026-10-07 под Docker на стенде разработки с выдуманными значениями (версии 0.0.5 и 0.0.6); шаг 6 — с настоящими Claude Code 2.1.292 и Codex CLI 0.160.1 (версия 0.0.5). Шаг 5 (страница «Переписка») для версии 0.0.6 пройден на том же стенде до входа в аккаунт: ссылка из `./ops/setup-link.sh`, вход на страницу по локальному адресу в браузере, шаг 1; вход в аккаунт Telegram и выбор чатов — только на стенде сервиса с подставным Telegram. Через настоящий туннель SSH и с настоящим аккаунтом не пройден. **С настоящим ботом Telegram и настоящей моделью runbook не пройден ни разу**: шаги 5, 7 и 8 на живом сервере — первая проверка. Вывод не совпал с ожидаемым — стоп.

Что это за режим, чего в нём нет и что из написанного проверено — `docs/standalone.md`. Установка с Hermes — `docs/runbooks/deploy.md`.

## Цель и критерий готовности

На чистом сервере работают сервис переписки и база; Hermes не установлен; владелец настроил переписку на странице «Переписка» или сознательно отложил это. Критерий: `./ops/doctor.sh` показывает `ИТОГ: OK`, `PASS service`, `PASS setup-page`, `PASS setup-origin`; `docker ps` показывает только `shturman-service` и `shturman-postgres`.

Первая настройка у владельца — страница «Переписка»: ключи приложения Telegram, вход в аккаунт по QR-коду, выбор чатов. Она открывается через туннель SSH: внешнего адреса у экземпляра нет. Подключение архива к Codex CLI или Claude Code — шаг 6. **Ключ модели и бот согласований нужны, чтобы сервис разбирал обязательства и присылал их карточками, — это шаг 7, по желанию владельца.** Выгрузка, поиск по смыслу, защита от внедрённых инструкций и бизнес-режим — шаг 8, позже. Отправка сообщений в этот runbook не входит и остаётся выключенной.

## Предусловия

- Сервер Linux, доступ по SSH, пользователь с правом запускать Docker.
- У владельца готовы: Telegram на телефоне; компьютер, с которого он входит на сервер по SSH. Домен, обратный прокси и TLS не нужны: у экземпляра нет веб-адреса.
- Для шага 7, если владелец его хочет: ключ провайдера модели с API, совместимым с OpenAI, и точное имя модели; бота согласований он создаст у @BotFather. Это отдельный бот: он не должен использоваться ни одной другой программой.
- Репозиторий склонирован, агент запущен в его корне.

## Инварианты

Действуют все инварианты, стоп-точки и запреты из `AGENTS.md`. Дополнительно для этого runbook:

- Ссылку из `./ops/setup-link.sh` выдавать только по явной просьбе владельца, передать как есть и нигде не сохранять — либо владелец запускает скрипт сам.
- На страницу «Переписка» не заходить, её адреса не запрашивать, что владелец на ней ввёл — не спрашивать.
- Токен бота и ключ модели вводит только владелец — на странице «Переписка» либо в своём терминале: `./ops/init-env.sh` без `--auto` агент не запускает, значений не просит, файл `.env` не читает.
- `./ops/mcp-token.sh` запускает только владелец; его вывод не читать и не просить.
- Ссылку из `./ops/bot-bind.sh` передать владельцу как есть и нигде не сохранять — либо владелец запускает скрипт сам.
- Наружу ничего не публиковать: порт 8765 остаётся на `127.0.0.1`, обратный прокси перед ним не ставить, внешний адрес странице «Переписка» не задавать.
- Отправку не включать: строку `SHTURMAN_SENDING` в `.env` не добавлять.
- `./ops/tg-login.sh` — запасной путь, запускает только человек; его вывод не читать и не просить.
- Каталог `data/` и содержимое базы не читать; о состоянии архива судить по счётчикам `./ops/doctor.sh`.
- На сервере не должно быть посторонних контейнеров. Нашлись — стоп.

## Шаги

Формат шага: действие → проверка → запись состояния. Провал проверки дважды — стоп.

### 1. Состояние и вариант установки
`./ops/state.sh show`. Первая строка называет режим установки. Если шаги уже отмечены — продолжить со следующего.
- Если шагов ещё нет — **до любого другого действия спросить владельца, какой из двух вариантов он ставит**, простыми словами:
  - **«Ассистент в Telegram (Hermes)»** — ассистент отвечает владельцу в Telegram, ведёт архив переписки, готовит ответы и сводки. Тогда этот runbook закрыть и идти по `docs/runbooks/deploy.md`.
  - **«Только архив и согласования»** — без ассистента в Telegram: архив переписки с поиском и список обязательств; вопросы владелец задаёт из своего Codex CLI или Claude Code. Полного разговорного агента нет; ограниченные сервисные задачи ответа возможны при своём боте и модели. Это этот runbook.
- Вариант выбирает владелец. Не выбирать за него и не считать выбором то, какой runbook или стартовый промпт получен: нужен явный ответ. Чем варианты отличаются — `docs/standalone.md`, «Что это».
- Развёртывание начато по runbook прежней версии (в состоянии есть шаги `secrets` или `owner-bind`): бот и модель уже настроены — это нынешний шаг 7; идти дальше с шага 5.
- Запись: `./ops/state.sh done choice`

### 2. Проверка сервера
`./ops/preflight.sh`
- Ожидается: `ИТОГ: OK`. Строки `WARN` объяснить человеку простыми словами.
- `FAIL docker` — **стоп-точка**: установка Docker требует `sudo`. Получить согласие, ставить по официальной инструкции Docker для дистрибутива, после — повторить preflight.
- `WARN net:telegram` — **стоп-точка**: без маршрута к Telegram сервис не войдёт в аккаунт и не будет принимать сообщения. Объяснить, что нужен прокси (`EGRESS_PROXY_URL`). Решение принимает человек.
- `WARN net:openai` важно, только если владелец берёт модель у OpenAI. Доступ к провайдеру модели из неподдерживаемого региона нарушает его условия и может стоить аккаунта: сказать об этом владельцу.
- Запись: `./ops/state.sh done preflight`

### 3. Режим и служебные значения
`./ops/init-env.sh --auto --mode standalone` — записывает режим без Hermes, генерирует пароль базы и два токена сервиса. Ничего не спрашивает и не печатает значений. Файл `.env` не читать.
- Ожидается: строка `[SHTURMAN_MODE] записан режим: standalone`.
- Сообщение «Режим уже выбран: hermes» значит, что на этом сервере уже начата установка с Hermes: **стоп**. Смена режима на работающем экземпляре — отдельная процедура (`docs/standalone.md`, «Переход между режимами»).
- Проверка: `./ops/mode.sh` показывает `Режим: standalone`; `./ops/preflight.sh` показывает `PASS env: есть, права 600`.
- Запись: `./ops/state.sh set mode standalone` и `done env`

### 4. Запуск
`./ops/up.sh` — скачивает образ базы, собирает образ сервиса переписки (первая сборка — несколько минут, нужен интернет для пакетов), запускает базу и сервис и сам вызывает `./ops/doctor.sh`. Образ Hermes не скачивается.
- Ожидается: три строки «пропущено: режим без Hermes — …», затем `PASS mode: без Hermes…`, `SKIP hermes`, `PASS service`, `PASS service-bind`, `PASS database`, `PASS archive-mcp`, `PASS archive` с нулями, `PASS jobs`, `PASS setup-page`, `PASS setup-origin: внешнего адреса … нет, как и положено без Hermes`, `ИТОГ: OK`.
- `WARN setup-state: …Переписка ещё не настроена`, `WARN approvals-bot: …не настроен`, `WARN model: …не настроена`, `WARN embeddings` и `WARN guard` на этом шаге нормальны.
- `WARN setup-origin: режим без Hermes, а у страницы настройки задан внешний адрес` — остался от режима с Hermes. Смена адреса страницы — **стоп-точка**: сказать владельцу, что в этом режиме наружу ничего не публикуется, и после согласия — `./ops/set-setup-url.sh --clear`, затем `./ops/up.sh`.
- `WARN service-bind` со словами «нет программы ss» — на сервере нет пакета `iproute2`, проверка адресов не выполнена: сказать владельцу; установка пакета — стоп-точка (`sudo`).
- «`SHTURMAN_PUBLIC_URL` (или `SHTURMAN_SETUP_URL`) в .env записан не как адрес…» — скрипт остановился до запуска: строка осталась от режима с Hermes или вписана вручную. В этом режиме обе не нужны; что с ними делать, решает владелец.
- «Сервис переписки не ответил за 90 секунд», `FAIL service`, `FAIL database`, `FAIL archive` — раздел «Если что-то не работает».
- `FAIL service-bind` или `FAIL archive-mcp: …ответил без токена` — **стоп**: стек остановить, не удаляя данных, и разобраться с `compose.override.yaml`.
- Проверка: `docker ps` показывает только `shturman-service` и `shturman-postgres`.
- Запись: `done stack-up`

### 5. Переписка: страница настройки — стоп-точка
На странице «Переписка» владелец делает три вещи: вводит ключи приложения Telegram, входит в свой аккаунт Telegram по QR-коду и выбирает чаты. Что именно он видит — `docs/setup.md`, «Страница „Переписка“». В этом режиме страница открывается через туннель SSH (`docs/standalone.md`, «Страница „Переписка“ через туннель SSH»).

5а. Сказать владельцу до выдачи ссылки простыми словами:
- на странице он подключит свой аккаунт Telegram **только на чтение**: сервис с этой сессией ничего не отправляет, но риск ограничений со стороны Telegram для такого подключения есть, и он его;
- читаться будут только те чаты, которые он сам отметит; их сообщения сохраняются на сервере;
- ключи приложения он возьмёт на my.telegram.org — страница подскажет где; ни агенту, ни в чат их присылать не нужно;
- сначала на своём компьютере он открывает туннель SSH и оставляет его работать; команду напечатает скрипт.

5б. **Стоп-точка: выдача ссылки входа.** Только по явной просьбе владельца в текущей сессии: `./ops/setup-link.sh`. Скрипт печатает ссылку вида `http://127.0.0.1:8765/shturman-setup/#…` и команду туннеля. Передать ссылку как есть и нигде не сохранять — ни в состоянии, ни в журнале, ни в отчёте; самому не открывать. Ссылка действует 30 минут и один раз. Предпочтительно скрипт запускает сам владелец.
- «контейнер shturman-service не запущен» — шаг 4.
- «сервис не выдал ссылку» — образ сервиса прежней версии: `./ops/up.sh`.

5в. Владелец открывает туннель, затем ссылку в своём браузере и проходит три шага. Агент в это время ничего не делает, на страницу не заходит и значений не спрашивает. Дождаться слова «готово».
- Проверка: `./ops/doctor.sh` показывает `PASS setup-state: ключи приложения Telegram: заданы, аккаунтов Telegram: 1, сообщений в архиве: N`. Пока история загружается, число сообщений растёт.
- Страница не открывается у владельца — туннель не открыт либо порт слева в команде туннеля не 8765.
- Если владелец откладывает — `./ops/state.sh set setup-page skipped` и идти дальше.
- Запись: `done setup-page`

### 6. Архив для Codex CLI или Claude Code — по желанию владельца
6а. Спросить у владельца, где работает его клиент: на этом сервере или на его компьютере, и по какому адресу он входит на сервер по SSH. `./ops/connect.sh --ssh пользователь@сервер` — показать ему вывод целиком. Скрипт токен не печатает.

6б. **Выполняет только владелец:** шаг 1 из вывода (токен в переменную окружения командой `./ops/mcp-token.sh --pipe`), для своего компьютера — ещё и туннель SSH (тот же, что для страницы «Переписка»), затем настройка клиента. Агент команду `./ops/mcp-token.sh` не запускает. Дождаться слова «готово».
- Проверка (делает человек): `claude mcp list` показывает `shturman … Connected` либо `codex mcp list` показывает строку `shturman`; на вопрос «какие чаты есть в архиве» клиент отвечает (пока архив пуст — что чатов нет).
- Если у клиента другая версия и команда не подошла — смотреть `claude mcp add --help`, `codex mcp add --help` и документацию клиента; флаги не выдумывать.
- Сказать владельцу: клиент отправляет прочитанное своему провайдеру модели; режим клиента без подтверждений действий включать не стоит (`docs/standalone.md`, «О чём помнить»).
- Запись: `done connect`; если владелец пропускает — `./ops/state.sh set connect skipped`.

### 7. Обязательства: модель и бот согласований — по желанию владельца
Без этого шага экземпляр — архив с поиском. С ним сервис раз в сутки сам разбирает новые сообщения моделью, находит обязательства и присылает их владельцу карточками с кнопками. Предлагать после шагов 5 и 6, не как обязательное. Что уходит провайдеру модели — фрагменты переписки: сказать об этом владельцу.

7а. Объяснить владельцу, что понадобится:
- ключ провайдера модели и точное имя модели; если провайдер не OpenAI — ещё и адрес его API (для OpenRouter — `https://openrouter.ai/api/v1`);
- **новый бот** у @BotFather (команда `/newbot`); его токен владелец никому не показывает и в чат не вставляет.

7б. **Стоп-точка, вводит только владелец.** Основной путь — страница «Переписка», раздел «Дополнительно» (ссылка — шаг 5б): ключ и имя модели, токен бота, привязка владельца к боту. Значения применяются сразу, перезапуск не нужен. Запасной путь в терминале: владелец запускает `./ops/init-env.sh` (скрытый ввод; на ненужный вопрос — Enter), затем `./ops/up.sh`. Агент значений не спрашивает. Дождаться слова «готово».
- Ожидается: `PASS approvals-bot: бот согласований на связи с Telegram`, `PASS model: модель <имя> настроена, обращений ещё не было`.
- `WARN approvals-bot: …ещё не начал опрос` — повторить `./ops/doctor.sh` через минуту.
- `FAIL approvals-bot` с кодом неполадки — `docker exec shturman-service shturman bot-status` даёт расшифровку. `token_rejected`, `bad_token_format` — токен введён неверно: владелец вводит его заново на странице (в терминальном пути — удаляет строку `SHTURMAN_BOT_TOKEN` из `.env` и повторяет). `other_poller`, `webhook`, `conflict` — этим ботом пользуется другая программа: нужен отдельный бот. `no_connection` — нет маршрута к Telegram: шаг 2.
- На странице ключ модели проверяется сразу: перед сохранением сервис задаёт модели один короткий вопрос и при отказе объясняет причину владельцу там же. Токен бота страница так же проверяет запросом к Telegram. В терминальном пути ключ обращением не проверяется: первое обращение к модели сервис делает при ночной обработке, и ошибку ключа покажет `WARN model: …последнее обращение не удалось` на следующий день.
- Адрес API на странице — только `https://` и только в интернете. Локальную модель (например, Ollama) со страницы не подключить: её адрес владелец задаёт строкой `SHTURMAN_LLM_BASE_URL` в `.env` (терминальный путь), и со страницы такой адрес не меняется.
- Запись: `done secrets`

7в. Привязка владельца к боту — **стоп-точка.** Кто первым откроет одноразовую ссылку в Telegram и нажмёт «Запустить», тот и получает карточки и право нажимать кнопки. На странице «Переписка» ссылку владелец получает сам. В терминальном пути — `./ops/bot-bind.sh`: предпочтительно его запускает сам владелец; агент — только по его явной просьбе, ссылку передаёт как есть и нигде не сохраняет. Действует 15 минут, один раз.
- Проверка (делает человек): бот ответил «Готово: вы привязаны как владелец».
- Проверка: `./ops/doctor.sh` показывает `PASS approvals-owner`.
- Запись: `done owner-bind`; если владелец весь шаг пропускает — `./ops/state.sh set secrets skipped`.

### 8. Позже, по желанию владельца
Ничего из этого для первой настройки не нужно. Каждый пункт предлагать отдельно и делать только после согласия.

8а. Выгрузка из Telegram Desktop. Основной путь — страница «Переписка» (ссылка — шаг 5б). Запасной путь в терминале: `./ops/import-export.sh scan /путь/к/result.json`, затем `import`; вывод `scan` — названия чатов владельца, команду запускает владелец либо агент по его явной просьбе.
- Проверка: `./ops/doctor.sh` — в строке `PASS archive` число сообщений выросло.

8б. Поиск по смыслу — **стоп-точка** (скачивание около 0,5 ГБ, около 1,2 ГБ памяти): `./ops/embeddings.sh on`. Модель по умолчанию — `e5-small`. Вторую модель, `user2-small`, ставят только по решению владельца: `./ops/embeddings.sh on --model user2-small`; до этого пересказать ему, чем модели отличаются (`docs/search.md`). Смена модели на работающем экземпляре — отдельная стоп-точка: пересчёт всех векторов.
- Проверка: `PASS embeddings` с именем модели либо `WARN embeddings: …идёт подсчёт векторов` со счётчиками «готово» и «осталось» — пока архив считается, это нормально; `./ops/embeddings.sh status` показывает модель и счётчики.
- Сервер начал тормозить или появился `FAIL` — `./ops/embeddings.sh off`.

8в. Защита от внедрённых инструкций — **стоп-точка** (скачивание около 0,3 ГБ, около 0,6 ГБ памяти): `./ops/guard.sh on`. Перед включением пересказать владельцу раздел «Что защита ловит и чего не ловит» из `docs/guard.md`. В этом режиме она прячет подозрительные сообщения от модели сервиса и от клиента владельца, который читает архив.
- Проверка: `PASS guard`; `./ops/guard.sh status` показывает счётчики и `"guard_problem": null`.
- `FAIL guard` — `docker logs --tail 50 shturman-guard`; не хватает памяти — `./ops/guard.sh off`. Выключение — только по явной просьбе владельца.
- Шаг не пройден нигде: `./ops/guard.sh` проверен только в песочнице с подставным `./ops/up.sh`.

8г. Бизнес-режим Telegram — **стоп-точка, подключает человек; только к боту согласований** (нужен шаг 7). Он нужен для отправки от имени владельца, а отправка выключена: предлагать, только если владелец сам спросил (`docs/standalone.md`, «Бизнес-режим Telegram со своим ботом»).
- Владелец включает у @BotFather для бота согласований Secretary Mode (Bot Settings → Secretary Mode; раньше пункт назывался Business Mode). Проверка: после `./ops/doctor.sh` строки `WARN approvals-business` нет.
- Сказать владельцу до подключения: с этого момента сообщения из выбранных личных чатов записываются в архив на сервере, а раз в сутки ночью разбираются моделью у выбранного провайдера.
- Владелец подключает бота в настройках Telegram Business, выбрав для начала один тестовый чат. Право бота отвечать на сообщения не давать: отправка выключена.
- Проверка: собеседник из тестового чата пишет сообщение; `./ops/doctor.sh` показывает в строке `PASS archive` число сообщений больше прежнего. Собеседнику при этом **ничего** не приходит.
- Если собеседник получил что-либо от имени владельца — немедленно отключить бота в настройках Telegram и остановиться.

- Запись: `done archive`; если владелец всё пропускает — `./ops/state.sh set archive skipped`.

### 9. Итог
- Проверка: все шаги отмечены в `./ops/state.sh show`; `./ops/doctor.sh` — `ИТОГ: OK`.
- `./ops/backup.sh` — первая копия. Ожидаются строки «Копия готова» и «Копия базы готова». В копии есть каталог данных с файлом значений, введённых на странице, и файл `.env`: агент её не открывает.
- Сообщить человеку: версия «Штурмана» и режим; что работает; настроена ли переписка и сколько сообщений в архиве; чего в этом режиме нет (`docs/standalone.md`, «Чего нет…»); что отправка выключена; если шаг 7 сделан — что первое обращение к модели будет ночью (по умолчанию в 03:30 по его часам) и найденные обязательства придут в бота карточками, а если нет — что обязательства не разбираются; что из шагов 6–8 не сделано; где лежат данные (`data/`) и копии (`local/backups`); что копии делаются вручную.

## Если что-то не работает

| Строка `./ops/doctor.sh` | Что смотреть |
|---|---|
| `FAIL mode` | В `.env` неизвестное значение режима: `./ops/mode.sh set standalone` |
| `WARN hermes-leftover` | Остался контейнер Hermes от прежнего режима: `./ops/up.sh` его уберёт |
| `FAIL service: сервис переписки не развёрнут` | Контейнера нет: `./ops/up.sh` |
| `FAIL service` | `docker logs --tail 50 shturman-service` — причина отказа запуска названа в последних строках |
| `FAIL database` | `docker logs --tail 50 shturman-postgres`; свободное место — строка `disk` |
| `FAIL archive-mcp` | Сервис не отвечает на `/mcp` либо отвечает без токена. Второе — **стоп** |
| `FAIL archive: сервис не отдал состояние` | `docker logs --tail 50 shturman-service` |
| `WARN setup-page: …сервис прежней версии` | Образ сервиса не обновился: `./ops/up.sh` |
| `FAIL setup-page`, `WARN setup-page: …не запущена` | Сервис не отдаёт страницу на локальном адресе: `docker logs --tail 50 shturman-service` |
| `WARN setup-origin` | Остался внешний адрес страницы от режима с Hermes: `./ops/set-setup-url.sh --clear`, `./ops/up.sh` |
| `WARN setup-state` | Переписка не настроена или настроена не до конца: шаг 5 |
| `FAIL approvals-bot` | `docker exec shturman-service shturman bot-status`; разбор кодов — шаг 7б |
| `WARN approvals-owner` | Шаг 7в |
| `WARN model: …последнее обращение не удалось` | Код `http_401` или `http_403` — ключ неверен или не действует; `http_404` — нет такой модели или неверный адрес API; `connect:…` — нет маршрута к провайдеру. Значения меняет владелец: на странице «Переписка» либо удалить строку из `.env`, `./ops/init-env.sh`, `./ops/up.sh` |
| `WARN jobs` | Задания копятся: бот или модель не настроены либо не работают — строки `approvals-bot` и `model` |
| `FAIL embeddings` | `docker logs --tail 50 shturman-embeddings`; не хватает памяти — `./ops/embeddings.sh off` |
| `FAIL guard` | Модель защиты не отвечает, входящие видны модели и клиенту непроверенными: `docker logs --tail 50 shturman-guard`; `./ops/guard.sh on` запускает контейнер заново |
| `shturman call` напечатал «ЖДЁТ ПОДТВЕРЖДЕНИЯ В БОТЕ» | Это не ошибка: действие расширяет права и применится, когда владелец нажмёт «Да, сделать» в боте согласований (`docs/service.md`) |
| Сборка образа в `./ops/up.sh` завершилась ошибкой | Нет доступа в интернет к пакетам или не хватило места на диске. Повторить один раз; не помогло — стоп |
| Клиент пишет, что сервер отверг токен | В окружении клиента нет `SHTURMAN_MCP_TOKEN` или токен сменился: владелец повторяет шаг 6б |
| Клиент или страница «Переписка» не открываются с компьютера владельца | Не открыт туннель SSH либо порт слева в команде туннеля не 8765 |

В журналах сервиса нет текста сообщений, токенов и ключей, но есть виды событий и коды ошибок. Журнал показывать владельцу можно, пересылать куда-либо — нет. Две неудачи подряд — остановиться и описать проблему. Данные (`data/`) при разборе не трогать и не читать.

## Откат

Остановить стек без удаления данных. Сессии аккаунтов Telegram владелец завершает сам: «Настройки → Устройства». Бота в настройках Telegram Business, если его подключали, отключает человек. Подключение архива у клиента убирается командами из `docs/standalone.md`. Токен бота владелец может отозвать у @BotFather. Всё, что удаляет данные (`data/`, тома, `down -v`), — стоп-точка.

Переход на режим с Hermes — `docs/standalone.md`, «Переход между режимами».

## Что ещё должно появиться

Проход этого runbook на чистом сервере с настоящими аккаунтом, ботом и моделью; проверка ключа модели, заданного в `.env`, сразу после ввода, а не ночью (на странице она уже есть); `ops/restore.sh`, копии по расписанию.

## После базовой установки: отдельная приёмка

Базовое здоровье стека не доказывает качество памяти, источников и доставки. Если владелец выбрал сценарий ответов, настроить собственный бот сервиса и выбранную модель, затем пройти `docs/runbooks/validate-pilot.md` сначала без доставки. Повседневные решения — `/menu` и карточки в Telegram. Начальные входы в Telegram и у провайдера остаются действиями владельца в браузере или по QR. Отправку, источники и публичный доступ не включать из факта успешного `doctor.sh`.
