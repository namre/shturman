# Дополнительные источники для ответа

Версия 0.0.7, 2026-10-08. Сервисный посредник источников — отдельный путь от внешних инструментов полного Hermes. Он получает ограниченные фрагменты для задачи ответа; не переносит автоматически всю почту или документы в архив. Проверка конкретного внешнего источника с настоящими данными остаётся частью пилота.

## Два направления подключения

Архив «Штурмана» отдаёт данные клиенту владельца на чтение: локальный MCP и его ограничения описаны в `docs/standalone.md`. Обратное направление — сервис получает сведения из заранее настроенного источника, например поиска почты. Поддержка одного направления не означает приёмку другого.

Полный Hermes сохраняет штатные внешние инструменты. Его свободная работа с ними не проходит автоматически через описанное здесь согласование. Автоматическая модель ответа не получает credentials источника и не выбирает произвольный инструмент, URL или заголовки.

## Настройка оператором

Сервис читает JSON-реестр из файла `SHTURMAN_SOURCES_FILE` (`Config.sources_file`). Файл доступен только контейнеру сервиса, не Hermes, не git и не ответам API. При стандартном mount `./data/shturman:/data` можно разместить его человеком в защищённом каталоге данных и указать контейнерный путь `/data/sources.json`; другой путь требует отдельного mount. Compose передаёт имя пути, но не создаёт реестр. Он должен принадлежать root или пользователю сервиса, быть обычным файлом и иметь права без доступа группы/прочих, например `0600`. Максимальный размер — 64 КБ, максимум 30 источников. Настоящие credentials вводит человек; агент сопровождения их не читает.

Искусственный образец структуры, без секретов:

```json
{
  "sources": [
    {
      "source_id": "travel_demo",
      "name": "Билеты — тестовый источник",
      "url": "https://sources.example.org/mcp",
      "headers": {},
      "search_tool": "search_tickets",
      "read_tool": "read_ticket",
      "search_args": {
        "query": "query",
        "since": "since",
        "until": "until",
        "limit": "limit"
      },
      "read_args": {"resource_id": "id"},
      "revision": "1"
    }
  ]
}
```

Адрес в образце не является готовым сервисом. Нужен выбранный оператором совместимый сервер. У источника явно задаются два инструмента: поиск и чтение. При необходимости допустимы служебные headers `authorization`/`x-api-key` и `fixed_args`; их значения не выдаются модели. Отображаемые названия и непрозрачные идентификаторы доступны владельцу, адреса и credentials — нет. Добавление реестра с настоящими credentials — действие человека, а не изменение через HTTP от имени ассистента.

Транспорт — MCP 2.x Streamable HTTP, только публичный HTTPS. Адрес проверяется при настройке и при соединении, соединение привязывается к проверенному IP, endpoint — к настроенному пути. Перенаправления на другой путь запрещены. Ответ ограничен 1 МБ, событие SSE — 64 КБ, ожидание — 20 секунд. Вызовы редактирования и отправки не предусмотрены. На удалённых инструментах требуются `readOnlyHint=true` и отсутствие `destructiveHint=true`; это декларация удалённого сервера, а не независимое доказательство его безопасности. Оператор доверяет выбранному endpoint и проверяет его поведение.

Ожидаемый ответ инструмента — `structuredContent.items` с ограниченным набором записей `{id, text, revision, date}`; `date` нужна при запросе периода, должна содержать часовой пояс. Произвольный текст вместо этого контракта, изображения, встроенные resources и инструменты, выбранные моделью, не превращаются в данные ответа автоматически. Конкретные названия инструментов и фильтры источника проверяются на его стенде.

## Решения владельца

В задаче источником может быть определённый чат, память о человеке или зарегистрированный внешний источник. Разрешение связано с задачей, целевым разговором и темой, источником, запросом, периодом, числом и объёмом результатов. Предел — 10 фрагментов и 12 000 знаков на запрос. Область чтения и область раскрытия различаются. Дата без часового пояса и недопустимые пределы отклоняются; для страницы памяти период не используется.

Обычный путь — карточка в независимом боте согласований: разрешить определённый поиск или отказаться; после разрешения задача продолжается. Решение владельца поступает напрямую от привязанного пользователя в личном чате бота. Заявление ассистента по HTTP и строка в ответе модели не создают разрешение. `/sources` показывает настроенные источники; `/replytasks` показывает задачи; `/sourcerevoke ID` отзывает разрешение. Ручной `/sourcegrant JSON` — расширенная команда для точной области задачи, не повседневное требование.

Дополнительное автоматическое раскрытие требует отдельного разрешения владельца для целевого разговора и темы. Точный готовый черновик также можно согласовать вручную после проверки действительности источников. Постоянная ограниченная политика задаётся владельцем; срок не больше 30 дней, после него требуется новое решение. Разрешение задачи не переживает её срок. Изменение постоянной политики и отзыв не выполняются по указанию из найденного письма.

Каждый выданный фрагмент получает сервисное свидетельство источника. Перед согласованием и отправкой повторно сверяются права, отзыв, видимость и версия содержимого. Изменённый документ или скрытое сообщение нельзя отправить по старому согласованию. Искусственный секрет и чужую инструкцию проверять по `docs/runbooks/validate-pilot.md`, а не по обещанию классификатора.

## Что ещё нужно доказать в пилоте

Готовых универсальных подключений ко всем почтовым и документным провайдерам нет. Выбранный сервер должен действительно применять согласованный поиск, отдавать корректные версии и ограниченный текст. При запросе периода требуется поддержка его аргументов и дата каждого результата; сервис отказывает в записи без даты и вне периода. Смысловое соответствие запросу всё равно проверяется на выбранном источнике. Проверить это на тестовых билетах: неправильный пассажир, отменённый рейс, поздняя правка, данные вне периода, большой ответ, недоступный источник, отзыв и отказ раскрытия. Метка read-only сама по себе не доказывает правильность выдачи данных.

Credentials внешнего сервера могут давать ему более широкий доступ, чем конкретная задача. Поэтому узкий посредник ограничивает вызовы и выдачу, но не превращает широкий credential в технически узкий у самого провайдера. Ни общий Hermes, ни оператор с правами администратора не получают обещания иммунитета к утечкам из всех остальных путей.
