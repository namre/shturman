# Необязательный внешний архив на чтение

Версия 0.0.7, 2026-10-08. Код внешнего OAuth-входа реализован; настоящий облачный клиент, внешний сертификат, сеть владельца и отзыв на живом экземпляре проходят отдельный пилот. Локальный MCP по постоянному токену остаётся прежним путём для Hermes, Codex CLI и Claude Code. Сам факт реализации OAuth не доказывает совместимость любого облачного ChatGPT/Claude.

## Когда включать

Внешний доступ нужен, если выбранный клиент не может подключиться к серверу владельца через локальный адрес или SSH-туннель. Он по умолчанию выключен. Включение публичного адреса, прокси и firewall — отдельное решение владельца. В режиме без Hermes он тоже остаётся необязательным исключением из локальной установки, а не новым обязательным шагом.

Сервису задаётся `SHTURMAN_REMOTE_MCP_ORIGIN`: отдельный origin с HTTPS, без пути, отличный от дашборда Hermes и страницы настройки. Например, `https://archive.example.org`. Это образец адреса, не готовая установка. Origin передаётся сервису отдельно; пользователь задаёт клиенту полный адрес `https://archive.example.org/mcp`.

Обратный прокси обслуживает на этом отдельном адресе `/mcp`, необходимые OAuth-маршруты и discovery; весь остальной вход закрыт. Внутренние `/api/*`, `/health` и `/shturman-setup/*` не публикуются. Gateway перехватывает весь отдельный host и отвергает неизвестные пути, даже если кто-то ошибочно направит их в сервис. Не заменять это публикацией всего внутреннего API.

Публичные пути: `/.well-known/oauth-protected-resource`, `/.well-known/oauth-protected-resource/mcp`, `/.well-known/oauth-authorization-server`, `/oauth/register`, `/oauth/authorize`, `/oauth/continue`, `/oauth/token`, `/oauth/revoke` и `/mcp`. Метод каждого маршрута ограничен кодом. Авторизационные запросы ограничены по размеру и частоте; pending-запросов не больше десяти. Постоянный локальный MCP-токен и токен внутреннего API не дают вход через внешний gateway.

## Как владелец даёт доступ

Клиент запускает стандартный браузерный вход. Gateway проверяет зарегистрированный точный адрес возврата, `state`, PKCE S256 и ресурс `/mcp`. Затем независимый бот сервиса спрашивает владельца. Без собственного бота и привязанного владельца выдача доступа невозможна. Решение принимается только в личном чате привязанного пользователя; подтверждение ассистентом по HTTP не работает.

В карточке видны заявленное название клиента, точный адрес возврата и объём доступа. Название заявляет клиент: оно само по себе не доказывает, что подключается известный бренд. Разрешать только запрос, который владелец сам только что начал. Отклонение или истечение не выдают code или token.

Разрешение `archive:read` открывает **весь доступный архив и страницы памяти**, которые выдаёт внутренний read-only MCP, на срок до 30 дней. Это не доступ только к одному разговору или задаче. Скрытые и исключённые данные продолжают фильтроваться правилами архива. Каждое чтение отдельно не согласуется. Клиент не получает отправку, запись, setup-сессию или управление настройками; прочитанные сведения он может сохранить по собственным правилам. Отзыв прекращает новые чтения, но не стирает уже переданные сведения у клиента.

Код входа действует 120 секунд и используется один раз. Access token — 15 минут; refresh token ротируется. Повтор старого refresh закрывает семейство токенов. Разрешение проверяется при обращении, включая текущего владельца, отзыв, срок и точный ресурс. После смены владельца прежние подключения аннулируются. Секретные коды, cookie и токены хранятся в базе только в виде хешей.

Первый вход может открыть браузер; это внешняя авторизация, а не ежедневный интерфейс принятия решений. Ежедневные согласования и отзыв остаются в Telegram. `/mcpaccess` (алиас `/mcpclients`) показывает подключения; `/mcprevoke GRANT_ID` отзывает конкретное разрешение. Текущая справка — `/help` бота сервиса.

## Приёмка

На изолированном стенде проверить discovery, отказ без токена, отказ с локальным токеном, точный ресурс и redirect, PKCE, чужое нажатие, отказ владельца, повтор code/refresh, истечение и отзыв. Проверить весь внешний host: `/api/*`, setup page, неизвестные пути и WebSocket не открываются. После отзыва запрос с прежним токеном не читает архив. Read-only не заменяет проверки видимости и фильтрации данных.

Для выбранного облачного клиента отдельно пройти настоящий вход, запрос источников, отсутствие записи/управления, отзыв и повторный запрос. Указать точную версию или вид клиента и дату. Пока этого нет, статус — «OAuth реализован, живая совместимость не проверена», а не «облачные клиенты поддержаны». Не добавлять внешние credentials или личную переписку в тестовые отчёты. Полная процедура — `docs/runbooks/validate-pilot.md`.
