# Первая настройка: вход и мастер

Состояние: написано и проверено на стенде (Hermes 0.21.5 за Caddy, настоящий браузер). На живом боте и на эталонном сервере не пройдено. Что именно проверено, а что нет, сказано в конце.

Мастер покрывает помощника, модель, бота и бизнес-режим. Для переписки и памяти (версия 0.0.4) экранов ещё нет: эти действия пока делаются в терминале — раздел «Переписка и память: пока без экранов».

Документ описывает режим установки с Hermes. В режиме без Hermes ни мастера, ни входа нет: токены и ключи владелец вводит в терминале сервера — `docs/standalone.md`.

## Принцип

Владелец получает от ИИ-агента одну ссылку, открывает её и дальше идёт по мастеру в браузере. Ключи и токены из браузера уходят сразу в Hermes; через агента они не проходят.

Цель — чтобы владелец ничего не вводил в терминал. В версии 0.0.4 есть исключения: ключи приложения Telegram и вход в аккаунт по QR — для подключения аккаунтов Telegram; токен своего бота согласований и ключ своей модели сервиса — если владелец их заводит. Всё это выполняет сам владелец в своём терминале, не агент.

## Что видит владелец

| Шаг | Что делает владелец | Что происходит |
|---|---|---|
| Ссылка активации | Открывает ссылку от агента, нажимает «Начать настройку» | Одноразовый вход без пароля; сразу открывается мастер |
| 1. Помощник | Выбирает имя и характер, как к нему обращаться, как ассистент представляется другим | Выбор сохраняется; в `SOUL.md` записывается помеченный блок |
| 2. Модель | Вставляет ключ OpenRouter или OpenAI либо входит по подписке ChatGPT; выбирает модель | Ключ проверяется у провайдера и сохраняется в Hermes; мастер задаёт модели пробный вопрос |
| 3. Бот в Telegram | Создаёт бота у @BotFather, вставляет токен, нажимает «Открыть бота», в Telegram — «Запустить», в мастере — «Да, это я» | Бот выходит на связь; подтверждённый аккаунт становится единственным владельцем |
| 4. Бизнес-режим (по желанию) | Ставит защиту кнопкой, включает Business Mode у @BotFather, подключает бота в настройках Telegram | Плагин бизнес-режима ставится по полному SHA; инструкции открываются только после него |
| 5. Переписка и память | — | Экран пока только рассказывает, что появится. Сами действия — в терминале, см. ниже |
| 6. Готово | Нажимает «Завершить настройку» | Сводка: что работает, что осталось |

После шага 3 вход в дашборд идёт по коду, который присылает собственный бот владельца: на странице входа владелец нажимает «Получить код в Telegram». Ссылка активации больше не нужна.

У каждого действия вне мастера есть схема «куда нажать и что ввести»: кабинет провайдера, диалог с @BotFather, кнопка «Запустить», меню бизнес-режима. Это условные рисунки, не снимки экранов: подписи в приложениях меняются.

## Что делает ИИ-агент

| Шаг | Команда | Зачем |
|---|---|---|
| Сервер и служебные значения | `ops/preflight.sh`, `ops/init-env.sh --auto` | Как раньше |
| Внешний адрес | `ops/set-public-url.sh https://адрес` | Hermes включает вход и принимает запросы с этим именем |
| Обратный прокси | По образцу `config/Caddyfile.example` | Наружу — дашборд и страницы входа; стоп-точка (`sudo`, TLS) |
| Запуск | `ops/up.sh` | Поднимает стек с сервисом переписки и базой, включает плагин `shturman`, подключает архив к Hermes, запускает `ops/doctor.sh` |
| Ссылка владельцу | `ops/activation-link.sh` | Одноразовая ссылка на 30 минут |
| Проверка | `ops/doctor.sh` | Вход подключён, страница входа открывается, владелец привязан, мастер пройден |

Ссылку активации агент видит и передаёт владельцу. Это осознанное исключение из правила «секреты не через агента»: ссылка одноразовая, живёт 30 минут и отменяется выдачей новой. Сохранять её где-либо агенту запрещено (`AGENTS.md`).

## Как устроен вход

Используется штатный механизм Hermes для своих способов входа (`register_dashboard_auth_provider`). Отдельной программы рядом с Hermes нет.

1. Браузер без сессии обращается к дашборду. Hermes отправляет его к способу входа `shturman`, а тот — на страницу входа. На этом шаге плагин ничего не отправляет и ничего не сообщает о состоянии экземпляра.
2. Страница входа — статический файл из `plugins/shturman/public/`, его отдаёт обратный прокси по пути `/shturman-auth/`. Hermes до входа отдаёт только собственный фиксированный список адресов, поэтому страница лежит вне его.
3. Владелец нажимает «Получить код в Telegram». Страница передаёт на штатный адрес Hermes `/auth/callback` служебное значение «прислать код»; плагин отправляет код через бота владельца и отвечает отказом входа с причиной — это и есть итог отправки.
4. Владелец вводит код. Страница передаёт его на тот же адрес, плагин проверяет код и выдаёт сессию.

Код отправляется только по кнопке, а не при открытии адреса: иначе сообщение уходило бы владельцу от каждого поискового робота и проверки доступности.

Ссылка активации идёт тем же путём: вместо кода страница передаёт значение из ссылки. В самой ссылке значение стоит после знака `#`, и при её открытии браузер эту часть на сервер не отправляет. Серверу значение передаётся один раз, при входе, в строке запроса к `/auth/callback`, и сразу перестаёт действовать. В образце настройки прокси журнал запросов выключен; если его включают, строку запроса для этого адреса писать нельзя.

| Что | Значение | Почему так |
|---|---|---|
| Ссылка активации | 30 минут, один раз, новая отменяет старую | Окно, достаточное для передачи владельцу |
| Код входа | 8 цифр, 5 минут | 6 цифр на открытом адресе подбираются за обозримое время |
| Новый код | Только когда прежний истёк или использован | Действующий код никто не может обесценить, запросив новый; владельцу приходит не больше одного сообщения в 5 минут |
| Неудачная отправка | Повтор не раньше чем через минуту | Обращение к Telegram на время задерживает ответы дашборда (до 4 секунд) |
| Неверные попытки | 5 подряд — блокировка на 1, 5, 15, 60 минут; владельцу приходит уведомление | Счётчик не обнуляется новым кодом |
| Сессия | 12 часов, продление до 30 дней от входа, затем вход заново | Украденная сессия не живёт бесконечно |
| Выход | Завершает все сессии владельца | Владелец один; скопированные куки тоже гаснут |
| Потерян или захвачен Telegram | `ops/activation-link.sh` выдаёт ссылку восстановления; вход по ней отвязывает прежний аккаунт и завершает все сессии | Доступ к серверу — доказательство владения; бота привязывают заново |
| Потеряно устройство | `ops/logout-all.sh` завершает все сессии | Сессии не хранятся на сервере, отзываются сменой поколения |

В файлах состояния лежат только хеши кодов и ссылок.

## Как привязывается владелец

Мастер выдаёт ссылку `t.me/<бот>?start=<значение>`. Telegram по кнопке «Запустить» сам отправляет боту это значение. Обработчик плагина в процессе шлюза сверяет его и запоминает отправителя как кандидата. Мастер показывает имя и адрес этого аккаунта и спрашивает: «Это вы?». Только после ответа «Да, это я» — то есть из уже выполненного входа — аккаунт становится владельцем, а мастер штатными вызовами Hermes записывает `TELEGRAM_ALLOWED_USERS` и `TELEGRAM_HOME_CHANNEL` и перезапускает шлюз.

Владельцу не нужно знать свой числовой Telegram ID. Запасной путь — код из шести цифр, который можно отправить боту вручную; после пяти неверных кодов привязка отменяется.

Обработчик привязки включён только пока мастер ждёт сообщения (до 15 минут).

Пока у бота нет владельца, плагин перехватывает личные сообщения боту и отвечает короткой подсказкой по-русски, не чаще раза в час на чат. Без этого стоковый Hermes отвечал бы любому написавшему английским сообщением с кодом привязки и командой для терминала. Как только владелец привязан (или список разрешённых пользователей задан вручную), плагин в сообщения не вмешивается: посторонним Hermes не отвечает, сообщения владельца идут ассистенту.

## Защита бизнес-режима

Без плагина бизнес-режима ядро Hermes принимает сообщения собеседников владельца за его команды (issue NousResearch/hermes-agent #127430). Защита двойная:

- мастер показывает инструкции подключения только после установки плагина;
- плагин `shturman` перехватывает сообщения бизнес-режима и не пропускает их к ядру, пока плагин бизнес-режима не загружен на самом деле. Проверяется не запись в настройках, а то, что Hermes его поднял без ошибки, и проверяется на каждое сообщение: если плагин бизнес-режима выключат или он упадёт, защита вернётся сама.

Подключение бизнес-режима мастер засчитывает только от аккаунта владельца: подключить бота к себе может любой пользователь Telegram.

Плагин бизнес-режима ставится из официального репозитория `NousResearch/hermes-telegram-business` по SHA `98c60afc00d36c885bb040ebe973b1aa908886c0`. В эту ревизию входит исправление проверки владельца черновика от 2026-08-15, которого нет в ревизии из каталога Hermes 0.21.5.

## Если вход сломался

Дашборд с внешним адресом не запускается без способа входа. Поэтому, если плагин `shturman` не загрузился (например, после обновления Hermes) или его выключили на странице плагинов, дашборд перестаёт открываться. Это закрытый отказ: данные не раскрываются, но и владелец войти не может.

| Что случилось | Что делать |
|---|---|
| Плагин выключен | `ops/up.sh` включит его и перезапустит Hermes |
| Плагин не загружается | `ops/emergency-access.sh on`: Hermes запускается без внешнего адреса, дашборд доступен только через SSH-туннель и входа не требует; снаружи адрес закрыт. После починки — `ops/emergency-access.sh off` |
| Потерян или захвачен Telegram | `ops/activation-link.sh` — ссылка восстановления |

Перед любым обновлением — `ops/backup.sh`: копия каталога данных в `local/backups`.

## Переписка и память: пока без экранов

Адреса для будущих экранов в плагине уже есть, страниц нет. До их появления действия делаются так:

| Что нужно владельцу | Как сейчас | Кто выполняет |
|---|---|---|
| Загрузить историю из Telegram Desktop | `./ops/import-export.sh scan` и `import` | Владелец или агент по его просьбе: вывод показывает названия чатов |
| Задать ключи приложения Telegram | `./ops/init-env.sh`, затем `./ops/up.sh` | **Владелец** в своём терминале |
| Подключить аккаунт-помощник или основной аккаунт на чтение | `./ops/tg-login.sh assistant` или `owner` | **Только владелец**: QR сканируется телефоном. Агент скрипт не запускает и вывод не читает |
| Выбрать чаты аккаунта, исключить чат из архива | `docker exec shturman-service shturman call …` | Владелец или агент по его явной просьбе |
| Включить поиск по смыслу | `./ops/embeddings.sh on` | Агент после согласия владельца (стоп-точка: память и скачивание) |
| Включить защиту от внедрённых инструкций | `./ops/guard.sh on` | Агент после согласия владельца (стоп-точка: память и скачивание; сначала — что защита ловит и чего нет, `docs/guard.md`) |
| Завести свой бот согласований и свою модель сервиса | `./ops/init-env.sh`, затем `./ops/up.sh`; привязка — `./ops/bot-bind.sh` | **Владелец** в своём терминале; ссылку привязки агент выдаёт только по явной просьбе |
| Подтвердить действие, расширяющее права ассистента | Кнопка под карточкой «Подтвердите действие» в боте согласований | Владелец в Telegram; только при своём боте |
| Принять или отклонить найденные обязательства и новые страницы о людях | Кнопки под сообщением бота: в управляющем чате, а при своём боте согласований — в нём | Владелец в Telegram |
| Включить утреннюю сводку и обзор недели по расписанию | Кнопки в интерфейсе нет; адрес в плагине есть | — |
| Включить отправку сообщений | Не включать: `docs/architecture.md`, «Открытое ограничение». Без своего бота согласований она не включается вовсе | — |

Точные команды и их параметры — `docs/service.md`, раздел «Как пользоваться без веб-интерфейса».

**Ключи приложения Telegram.** Для сессий аккаунтов нужно собственное приложение владельца: `api_id` и `api_hash` с my.telegram.org (раздел API development tools). Владелец запускает `./ops/init-env.sh` без параметров в своём терминале. Скрипт спрашивает по очереди все ещё не заданные значения; на каждый лишний вопрос достаточно нажать Enter, на вопрос о часовом поясе — ввести свой. `api_hash` вводится скрыто. Затем `./ops/up.sh` — сервис перезапустится с новыми значениями. Агенту эти значения не сообщаются.

**Вход в аккаунт.** `./ops/tg-login.sh` показывает QR-код прямо в терминале. Владелец сканирует его в Telegram на телефоне: «Настройки → Устройства → Подключить устройство». Номер телефона и код из SMS сервис не запрашивает. Если на аккаунте включён облачный пароль, скрипт попросит его ввести; ввод скрыт, пароль уходит в Telegram и нигде не сохраняется. После входа ничего не читается, пока владелец не выбрал чаты.

**Свой бот согласований.** Это отдельный бот от @BotFather, не тот, с которым владелец разговаривает: его токен получает только сервис переписки, и нажатия кнопок приходят сервису мимо Hermes. Владелец создаёт бота, запускает `./ops/init-env.sh` в своём терминале и вводит токен скрыто; там же, если нужно, ключ и имя своей модели сервиса. Затем `./ops/up.sh` и привязка: `./ops/bot-bind.sh` печатает одноразовую ссылку, владелец открывает её в Telegram и нажимает «Запустить». С этого момента карточки приходят в бота согласований, а бизнес-режим подключается к нему, а не к боту Hermes; шаг мастера «Бизнес-режим» тогда пропускается. Подробно — `docs/service.md`, «Свой бот согласований и своя модель», и `docs/standalone.md`, «Привязка владельца к боту».

**Часовой пояс.** По нему считаются сроки обязательств, время ночной обработки и расписание сводок. По умолчанию `Europe/Moscow`. Значение хранится в `.env` строкой вида `SHTURMAN_TIMEZONE=Asia/Novosibirsk` и не секретное. Пока оно не задано, его спрашивает `./ops/init-env.sh` среди прочих вопросов; если уже задано — строку правит сам владелец. Затем `./ops/up.sh`. Одно значение получают и сервис, и Hermes.

## Где проходят секреты

| Секрет | Кто вводит | Куда попадает |
|---|---|---|
| Ключ модели | Владелец в мастере | Штатный вызов Hermes `PUT /api/env` → данные Hermes |
| Вход по подписке ChatGPT | Владелец на сайте OpenAI | Данные Hermes |
| Токен бота | Владелец в мастере | Плагин один раз спрашивает у Telegram имя бота и токен не сохраняет; затем штатный вызов Hermes → данные Hermes |
| Ссылка активации | Создаёт скрипт, передаёт агент | В состоянии плагина — хеш |
| Код входа | Создаёт плагин, получает владелец в Telegram | В состоянии плагина — хеш |
| Ключ подписи сессий | Создаётся плагином при первом запуске | `plugin-data/shturman/secret.key`, права 600 |
| Пароль базы, токен внутреннего API сервиса, токен архива для агента | Генерирует `./ops/init-env.sh --auto`, значения не печатаются | `.env` на сервере; оттуда — в окружение контейнеров |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | Владелец в своём терминале: `./ops/init-env.sh` | `.env` на сервере; оттуда — в окружение сервиса переписки |
| Токен бота согласований, ключ модели сервиса (по желанию) | Владелец в своём терминале: `./ops/init-env.sh`, скрытым вводом | `.env` на сервере; оттуда — только в окружение сервиса переписки, контейнеру Hermes не передаются |
| Ссылка привязки владельца к боту согласований | Создаёт `./ops/bot-bind.sh`; лучше, если его запускает сам владелец | В базе — только хеш; 15 минут, один раз |
| QR-код входа в аккаунт Telegram | Показывает `./ops/tg-login.sh` в терминале владельца | Нигде не сохраняется; действует около 30 секунд и обновляется сам |
| Облачный пароль Telegram | Владелец в терминале `./ops/tg-login.sh`, скрытым вводом | Уходит в Telegram; не сохраняется ни в файле, ни в базе, ни в журнале |
| Сессия аккаунта Telegram | Создаётся сервисом после входа | `data/shturman/sessions`; контейнеру Hermes каталог не подключён |

## Честные ограничения

- Мастер — вкладка внутри дашборда Hermes, его боковое меню видно. Скрыть меню плагину нечем.
- Токен внутреннего API сервиса переписки попадает в окружение Hermes и доступен его агенту. Чем это грозит, что закрывает свой бот согласований и почему отправка выключена — `docs/architecture.md`, «Открытое ограничение».
- Файл `.env` входит в резервную копию: в нём токен бота согласований и ключ модели сервиса, если они заданы.
- Агент с правами администратора на сервере может прочитать файлы с секретами и выдать себе ссылку активации. «Секреты не через агента» — порядок работы, а не непреодолимая граница.
- Тот, кто вошёл в дашборд, может увидеть сохранённые ключи: в Hermes есть функция показа значения.
- Страницей входа можно заблокировать вход владельцу, намеренно вводя неверные коды, и раз в пять минут вызывать сообщение с кодом в его Telegram. Выход — ссылка восстановления. Перед адресом можно поставить внешнюю защиту (например, единый вход), это не мешает.
- Посторонний, открывший страницу входа и нажавший кнопку, по ответу узнает, привязан ли владелец и закрыт ли сейчас вход.
- Ревизия сессий и счётчики блокировок лежат в файлах состояния. Если их стереть или восстановить из старой копии, оставив ключ подписи, завершённые сессии снова начнут действовать до истечения своего срока. При восстановлении из копии — `ops/logout-all.sh`.
- Названия пунктов Telegram для бизнес-режима в источниках расходятся (Business Mode или Secretary Mode, «Чат-боты» или Chat Automation). В подсказках указаны оба варианта.

## Проверено и не проверено

Проверено на стенде 2026-10-06 (Hermes 0.21.5 из исходников тега `v2026.9.24`, Caddy 2.10.2 с настройкой из `config/Caddyfile.example`, Chromium):

- вход по ссылке активации, одноразовость ссылки, отказ по неполной ссылке; страница входа ничего не отправляет и не раскрывает до нажатия кнопки;
- закрытость API и маршрутов плагина без сессии;
- страница входа под строгой политикой содержимого, без обращений к чужим серверам;
- все шесть шагов мастера; запись характера в `SOUL.md` штатным вызовом; привязка владельца через файл состояния с подтверждением в мастере;
- обработчики Telegram на настоящей библиотеке python-telegram-bot 22.8 без сети: привязка, подсказка на «/start», перехват сообщений бизнес-режима и его снятие, запись подключения только от владельца.

Код плагина прошёл отдельную проверку безопасности вторым агентом, не видевшим его написания; найденные замечания исправлены в этой же версии.

В браузерной проверке подменялись ответы провайдера модели, Telegram и перезапуск шлюза: настоящих ключа и бота на стенде нет.

Для версии 0.0.3 на стенде разработки проверен проход дашборда к сервису переписки, в том числе загрузка файла в 300 МБ потоком; серверная часть входа в аккаунт по QR покрыта тестами с подставным Telegram. Сама команда входа из терминала (`shturman tg-login`) тестами не покрыта и не запускалась.

Для версии 0.0.4 `./ops/import-export.sh` пройден под Docker на стенде разработки в режиме без Hermes; свой бот согласований и подтверждения владельца покрыты тестами с подставным Telegram.

Не проверено: вход в аккаунт Telegram по QR на настоящем аккаунте, с облачным паролем и без; `./ops/tg-login.sh` под Docker; привязка владельца к боту согласований на настоящем боте; отправка кода входа настоящим ботом; привязка нажатием «Запустить» в настоящем Telegram; перезапуск шлюза из мастера в официальном образе; вход по подписке ChatGPT; установка плагина бизнес-режима из мастера и подключение бота в Telegram; работа за внешним единым входом перед прокси.
