# Первая настройка: веб-интерфейс и ИИ-агент

Состояние: принятый сценарий, на живом сервере не пройден. Что проверено по документации и коду Hermes, а что нет, сказано в конце.

## Принцип

Владелец ничего не вводит в терминал. Токены, ключи и входы в аккаунты он делает в браузере; ИИ-агент готовит сервер, ставит несекретные настройки и проверяет результат по статусам. Значения секретов через агента не проходят.

## Что уже умеет дашборд Hermes

| Задача | Где в дашборде |
|---|---|
| Ключ модели и любые ключи окружения | Страница API Keys |
| Вход по подписке ChatGPT | Окно входа провайдера: код подтверждения на сайте OpenAI |
| Выбор провайдера и модели | Config → model |
| Токен Telegram-бота, разрешённые пользователи, проверка, перезапуск шлюза | Страница Channels |
| Установка, включение и выключение плагинов | Страница Plugins |

Чего в стоковом дашборде нет и что добавляет вкладка «Штурман» (плагин дашборда):

- вход в дополнительный Telegram-аккаунт: `api_id`, `api_hash`, QR-код, запасной путь — телефон, код и облачный пароль;
- загрузка экспорта Telegram Desktop и выбор чатов, которые не попадут в архив;
- имя и характер ассистента, уровни автономии, белые списки;
- очередь согласований и страницы памяти.

Сессия дополнительного аккаунта хранится в сервисе переписки. Вкладка только передаёт туда введённое; в данных Hermes сессия не появляется.

## Сценарий

| Шаг | Кто | Что происходит |
|---|---|---|
| 1 | Агент | Проверяет сервер (`ops/preflight.sh`), генерирует служебные значения (`ops/init-env.sh --auto`), поднимает стек с включённым дашбордом Hermes и HTTPS-прокси |
| 2 | Агент | Открывает «первую дверь» — см. ниже — и даёт владельцу адрес |
| 3 | Владелец, браузер | Входит в дашборд |
| 4 | Владелец, дашборд | API Keys или вход по подписке — доступ к модели. Channels — токен бота от @BotFather и свой Telegram ID. Перезапуск шлюза кнопкой |
| 5 | Агент | Ставит расширения «Штурмана» штатными командами Hermes, записывает адрес MCP-сервера переписки. Проверяет: бот отвечает владельцу, плагин бизнес-режима загружен |
| 6 | Владелец, вкладка «Штурман» | Имя и характер, вход в дополнительный аккаунт, загрузка экспорта, правила |
| 7 | Владелец, Telegram | Подключает бота в бизнес-режиме — только после зелёной проверки шага 5 |
| 8 | Агент | `ops/doctor.sh`, отчёт простыми словами: что работает, что осталось |

В режиме «агент ведёт, человек вставляет» шаги агента выполняет человек по подсказкам чата; шаги 3, 4, 6 и 7 не меняются.

## «Первая дверь»: как владелец попадает в дашборд в первый раз

Дашборд Hermes по умолчанию слушает только локальный адрес и без аутентификации наружу не открывается. Есть два способа, оба без ввода пароля в терминал.

**А. Единый вход перед прокси.** Перед прокси стоит внешний сервис аутентификации, порт 443 открыт файрволом только для его адресов. Владелец входит своей учётной записью этого сервиса. Агент пароля не видит вообще. Требует домена и учётной записи в таком сервисе.

Две вещи, которые надо учесть в этом способе. Сертификат сервера не сможет обновляться проверкой по HTTP, если сервис единого входа перехватывает и её: нужно исключение для пути `/.well-known/acme-challenge/` либо сертификат, выданный самим сервисом. И тот, кто управляет учётной записью этого сервиса, управляет и доступом к дашборду.

**Б. Одноразовая ссылка настройки.** Агент запускает `ops/setup-link.sh`; сервис переписки выдаёт ссылку, действующую 15–30 минут и один раз. Владелец открывает её и задаёт логин и пароль дашборда; после этого ссылка перестаёт существовать. Ссылку агент видит — это осознанный компромисс: она даёт право только один раз задать пароль и сгорает.

Чего не делаем: страницу «кто первый зашёл, тот и администратор»; окно настройки, которое открывается при каждом перезапуске; пароль администратора в переменных окружения; бота «создать по QR» из дашборда — в этом варианте токен бота проходит через сторонний сервис, поэтому бота владелец создаёт у @BotFather сам.

## Где проходят секреты

| Секрет | Кто вводит | Куда попадает |
|---|---|---|
| Ключ модели или вход по подписке | Владелец в дашборде | Данные Hermes |
| Токен бота | Владелец в дашборде | Данные Hermes |
| `api_id`, `api_hash`, код входа, облачный пароль | Владелец во вкладке «Штурман» | Сервис переписки; облачный пароль не сохраняется |
| Сессия дополнительного аккаунта | Создаётся при входе | Том сервиса переписки |
| Пароль базы и внутренние токены между контейнерами | Никто — генерируются | `.env`, права 600 |

Код входа в Telegram вводится только в веб-форму. Пересылать его сообщением в Telegram нельзя: клиенты Telegram обязаны такой код аннулировать.

## Честные ограничения

- Агент с правами администратора на сервере технически может прочитать файлы с секретами. «Секреты не через агента» — это порядок работы, закреплённый правилами и запретами в настройках репозитория, а не непреодолимая граница.
- В дашборде Hermes есть функция показа сохранённого значения ключа. Тот, кто вошёл в дашборд, может увидеть ключи.
- Вкладка «Штурман» исполняется в процессе дашборда Hermes, поэтому всё чувствительное она сразу передаёт сервису переписки и у себя не хранит.

## Проверено и не проверено

Проверено по документации и исходному коду Hermes на 2026-10-06: страницы API Keys, Channels, Plugins и выбор модели; вход по подписке ChatGPT из дашборда; формат плагина дашборда, свои маршруты, загрузка файлов и WebSocket в нём; способы аутентификации дашборда; несекретная настройка командами `hermes config set` и `hermes plugins`.

Проверено на живом стенде 2026-10-06 (Hermes 0.21.5, образ `v2026.9.24`): официальный образ с включённым дашбордом в сети хоста слушает только `127.0.0.1:9119`; через прокси с единым входом дашборд открывается снаружи только после аутентификации; напрямую порт 443 сервера недоступен.

Не проверено на живом стенде: перезапуск шлюза из дашборда в официальном образе; подхват пароля дашборда из настроек после перезапуска; вход по подписке за прокси; наличие всего перечисленного в выбранной версии образа; защита парольного входа от перебора.
