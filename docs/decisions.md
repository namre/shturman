# Решения

Запись добавляется при каждом решении, меняющем конструкцию. Формат: что решено, почему, что из этого следует. Отменённое решение не удаляется, а помечается.

## Р-01. Один экземпляр на владельца, отдельно от любых корпоративных платформ
2026-10-06. **Почему:** переписка владельца не должна зависеть от безопасности общей платформы; экземпляр должен быть пригоден людям вне одной организации. **Следствие:** общей многопользовательской базы нет; изоляция — граница сервера.

## Р-02. С системами организации экземпляр общается по MCP и только как клиент
2026-10-06. **Почему:** нужные операции узкие и типизированные; экземпляр без входящих интерфейсов нельзя опросить снаружи. **Следствие:** A2A и API-сервер Hermes выключены. Пересмотр — если организации понадобится принимать свободные поручения отдельным агентом.

## Р-03. Открытый код, MIT
2026-10-06. **Следствие:** компоненты под AGPL, LGPL, BSL в поставку не включаются без отдельного решения. Форк официального бизнес-плагина ведётся отдельным репозиторием, чтобы изменения можно было предлагать в исходный проект.

## Р-04. Поставка — «свой сервер»; развёртывание и сопровождение ведёт ИИ-агент
2026-10-06. **Почему:** владелец не обязан быть специалистом, но должен оставаться единственным, у кого есть доступ к данным. **Следствие:** правила для агента, runbook-и, скрипты и стартовые промпты — часть продукта и обновляются вместе с кодом. Поддерживаются два режима: агент исполняет на сервере; агент ведёт, человек вставляет команды.

## Р-05. Экземпляр ставится на новый чистый сервер
2026-10-06. **Следствие:** runbook не рассчитан на сосуществование с чужими сервисами; обнаружение посторонних контейнеров — стоп-точка.

## Р-06. Приложение Telegram (api_id) у каждого владельца своё
2026-10-06. **Почему:** блокировка общего приложения остановила бы все экземпляры сразу. **Следствие:** регистрация на my.telegram.org — шаг владельца в мастере подключения.

## Р-07. Модель по умолчанию — собственный доступ владельца к OpenAI
2026-10-06. **Следствие:** доступ настраивается в Hermes штатно — ключом API или входом по подписке (уточнено решением Р-15: все обращения к модели идут через Hermes). Ключ API устойчивее для сервера без присмотра. Провайдер остаётся сменным: OpenAI работает не во всех странах, и потеря аккаунта не должна останавливать экземпляр.

## Р-08. Telegram: бизнес-режим — плагином Hermes, дополнительный аккаунт — отдельным сервисом
2026-10-06. **Почему:** бизнес-обновления приходят в шлюз Hermes; сессия пользовательского аккаунта не должна лежать в процессе агента, где нет изоляции плагинов. Обоснование — `docs/architecture.md`.

## Р-09. Память: архив в Postgres + курируемые страницы Markdown в git
2026-10-06. **Почему:** два разных объёма требуют разных инструментов; файлы читаемы и правимы владельцем, история правок — в git; структурные данные требуют таблиц. **Следствие:** у каждого вида данных один источник истины, синхронизация односторонняя. Обоснование и отвергнутые варианты — `docs/memory.md`.

## Р-10. Эмбеддинги и распознавание голосовых по умолчанию локальные
2026-10-06, предварительно — подтверждается замером на спайке. **Почему:** иначе внешнему провайдеру уходит весь архив целиком. **Следствие:** полный локальный набор требует 8 ГБ памяти. Сервер на 4 ГБ — поддерживаемый вариант: распознавание голосовых остаётся локальным (лёгкий сервер GigaAM укладывается в 0,4–0,8 ГБ), а для эмбеддингов выбирается лёгкая локальная модель либо API — по замеру на проверочном наборе вопросов. Эталонный пилот работает именно на 4 ГБ.

## Р-11. Внешний доступ к архиву по MCP — необязательный режим, только чтение, по умолчанию выключен
2026-10-06. **Почему:** владельцу может быть удобно спрашивать свою переписку из стороннего ассистента (например, OpenAI Dots в приложении ChatGPT), а слой данных от движка агента не зависит. **Следствие:** при включении у экземпляра появляется входящий интерфейс за OAuth — это осознанное отступление от Р-02, о котором владелец предупреждается: сторонний ассистент запоминает прочитанное по своим правилам, и удалить это из него выборочно может быть нельзя. Отправка сообщений и черновики через этот интерфейс недоступны.

## Р-12. Размещение сервера выбирает владелец; эталонный экземпляр стоит в стране, где доступны Telegram и провайдер модели
2026-10-06. **Следствие:** исходящий прокси — необязательная настройка, а не часть базовой поставки. Где хранится переписка и что об этом говорит закон страны владельца — его ответственность; README говорит об этом прямо.

## Р-13. Продукт называется «Штурман», репозиторий — `shturman`
2026-10-06. **Почему:** имя объясняет отношения владельца и ассистента — владелец ведёт и решает, ассистент читает дорогу и подсказывает. Это совпадает с главным ограничением продукта: отправку решает владелец. Первая аудитория — русскоязычные руководители, для которых Telegram основной рабочий канал.

## Р-14. Имя и характер ассистента владелец выбирает при первом запуске
2026-10-06. Предлагаются Штурман (по умолчанию), Нестор, Савельич, Бэрримор, Дживс и своё. **Следствие:** характер действует только в разговоре с владельцем; на сообщения третьим лицам, на подпись дополнительного аккаунта, на содержание и на правила не влияет. Подробности — `docs/personas.md`.

## Р-15. Hermes остаётся стоковым; продукт — расширения и один сервис рядом
2026-10-06. **Почему:** владелец не должен терять ничего из того, что умеет Hermes, и должен получать его обновления штатным путём; у кого Hermes уже есть — тот ставит «Штурман» поверх. **Следствие:** своего образа Hermes нет, самообновление не выключается, версия Hermes не привязана к нашему релизу. Совместимость — список проверенных версий и предупреждение перед обновлением. Все обращения к модели идут через Hermes. Кабинет владельца — плагин дашборда, а не отдельное приложение. Подробно — `docs/deployment.md`.

## Р-16. Эталонное развёртывание — Compose с официальным образом Hermes
2026-10-06. **Почему:** одна команда поднимает всё; состояние описано в одном файле, который ИИ-оператор может прочитать, применить повторно и откатить; терминал агента ограничен контейнером без наших правок. **Следствие:** установка Hermes прямо в систему поддерживается как вариант «пристройка», но эталоном не является.

## Р-17. Токены, ключи и базовая настройка — через веб-интерфейс, а не через терминал
2026-10-06. **Почему:** владелец далёк от ИТ; секреты не должны проходить через ИИ-агента. **Следствие:** ключ модели, вход по подписке и токен бота вводятся в стоковом дашборде Hermes; вход в дополнительный аккаунт, загрузка экспорта и правила — во вкладке «Штурман»; агент ставит несекретное и проверяет по статусам. Первый вход в дашборд — через единый вход перед прокси либо по одноразовой ссылке. Терминальный ввод остаётся запасным путём. Подробно — `docs/setup.md`.

## Р-18. Готовое берём только под разрешительными лицензиями
2026-10-06. **Следствие:** проекты под AGPL, GPL и без лицензии — источник идей, не кода. Разбор по частям решения — `docs/reuse.md`.

## Р-19. Основной аккаунт можно подключить через сессию — только на чтение, необязательным режимом
2026-10-06. **Почему:** бизнес-бот не видит группы и прошлое; сессия основного аккаунта даёт и то и другое без выгрузки. **Следствие:** пути отправки для этой роли в сервисе нет вообще; от имени владельца пишет только бизнес-бот. Режим выключен по умолчанию и включается с предупреждением о риске для основного аккаунта.

## Р-20. Автоответ доверенным собеседникам — отдельный уровень автономии
2026-10-06. **Почему:** владельцу нужен ответ близкому кругу без подтверждения каждого сообщения. **Следствие:** уровень 2а: список доверенных по числовым идентификаторам, ограниченный набор инструментов без терминала и файлов, паузы и дневной лимит. Остальным сервис не отвечает. Подробно — `docs/service.md`.

## Р-21. Наблюдатель групп — часть продукта
2026-10-06. Ключевые слова → дешёвая модель → уведомление владельцу; в группе сервис не пишет и прочитанным её не отмечает.

## Р-22. Сервис переписки пишется на Python с asyncpg
2026-10-06. **Почему:** Telethon работает на asyncio; `asyncpg` под Apache-2.0, тогда как `psycopg` — под LGPL. **Следствие:** работа с базой асинхронная, миграции — пронумерованные SQL-файлы без отдельного инструмента.

## Р-23. Вход в дашборд — свой способ входа Hermes: ссылка активации и код от собственного бота
2026-10-06. **Почему:** владелец далёк от ИТ, паролей и терминала у него быть не должно; при этом Hermes с внешним адресом обязан иметь вход, а его встроенный парольный вход требует задать хеш пароля на сервере. **Следствие:** плагин `shturman` регистрирует способ входа штатным механизмом Hermes. Первый вход — по одноразовой ссылке, которую выдаёт `ops/activation-link.sh`; дальше — по коду из восьми цифр, который бот владельца присылает по кнопке на странице входа. Почты в первой версии нет: для неё нужен почтовый сервер. Отдельной программы для входа нет; страницы входа — статические файлы, которые отдаёт обратный прокси. Подробно — `docs/setup.md`.

## Р-24. Ссылку активации агент видит и передаёт владельцу
2026-10-06. **Почему:** другого канала от сервера к владельцу до настройки бота нет. **Следствие:** это единственное исключение из правила «секреты не проходят через агента». Ссылка одноразовая, живёт 30 минут, отменяется выдачей новой; значение стоит после `#` и в журналы прокси не попадает; агенту запрещено её сохранять. Та же команда выдаёт ссылку восстановления, если Telegram владельца потерян или захвачен: доступ к серверу считается доказательством владения, вход по такой ссылке отвязывает прежний аккаунт и завершает все сессии.

## Р-25. Владелец привязывается к боту кнопкой «Запустить», а не вводом своего Telegram ID
2026-10-06. **Почему:** числовой идентификатор владелец не знает; стоковая привязка Hermes отвечает по-английски и просит выполнить команду в терминале. **Следствие:** мастер выдаёт ссылку `t.me/<бот>?start=<значение>`; обработчик плагина в процессе шлюза запоминает отправителя как кандидата; владельцем он становится только после подтверждения в мастере, то есть из уже выполненного входа. Затем мастер штатными вызовами задаёт `TELEGRAM_ALLOWED_USERS` и `TELEGRAM_HOME_CHANNEL`. Обработчик активен только пока мастер ждёт сообщения.

## Р-26. Мастер настройки — вкладка дашборда Hermes, секреты идут в штатные вызовы Hermes
2026-10-06. **Почему:** так ключ модели и токен бота не проходят через наш код и не хранятся у нас; у плагина нет способа скрыть меню дашборда, а отдельная страница потребовала бы своего сервера с доступом к секретам. **Следствие:** серверная часть плагина хранит только выбор помощника, отметки шагов и состояние привязки. Исключение: токен бота один раз проходит через плагин, чтобы спросить у Telegram имя бота до сохранения; плагин его не записывает.

## Р-27. Плагин `shturman` перехватывает сообщения бизнес-режима, пока не включён плагин бизнес-режима
2026-10-06. **Почему:** порядок «сначала плагин, потом подключение бота» зависит от действий человека в Telegram, которые мы не контролируем; без плагина ядро Hermes отвечает собеседникам владельца (issue NousResearch/hermes-agent #127430). **Следствие:** защита не зависит от того, в каком порядке владелец выполнил шаги, и от того, поднялся ли плагин бизнес-режима: она снимается только когда Hermes сообщает, что он загружен без ошибки. Плагин бизнес-режима ставится из официального репозитория по SHA `98c60afc00d36c885bb040ebe973b1aa908886c0` (вершина `main` на 2026-10-06, включает исправление безопасности от 2026-08-15).

## Р-28. Плагин не привозит своих зависимостей
2026-10-06. **Почему:** `python-telegram-bot` распространяется под LGPL-3.0, в поставку мы такие компоненты не включаем (Р-18). **Следствие:** плагин пользуется библиотеками, которые уже есть в окружении Hermes (FastAPI, python-telegram-bot), и импортирует их только там, где они нужны. Логика плагина (`shturman_core/`) написана на стандартной библиотеке Python и проверяется без Hermes.

## Открытые вопросы

- Язык документации: сейчас русский; нужен ли английский как основной для сообщества Hermes.
- Способ подтверждения отправки, который агент не может подделать.
- Вход по почте: нужен ли, и чей почтовый сервер для него использовать.
- Как Telegram сейчас называет пункты бизнес-режима (Business Mode или Secretary Mode, «Чат-боты» или Chat Automation) — уточнить на живом боте и поправить подсказки мастера.
- Официальный поток «вход по подписке ChatGPT» в Hermes ещё не слит (PR NousResearch/hermes-agent #128926) — вернуться после слияния.
