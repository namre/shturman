# Архитектура

Состояние на версию 0.0.3: описанное ниже написано, кроме помеченного «запланировано». Что из написанного проверено и как — `docs/service.md` и `docs/deployment.md`. Версии сторонних компонентов и их поведение сверены с документацией на 2026-10-06.

## Принципы

0. **Hermes — стоковый.** Его код и образ не меняются, возможности не урезаются. Продукт — расширения Hermes (плагины, скиллы, MCP, настройки) и один сервис рядом. Подробно — `docs/deployment.md`.
1. **Один экземпляр — один владелец.** Граница изоляции — сервер. Общей многопользовательской базы нет.
2. **Экземпляр — только клиент.** Наружу он ходит сам (Telegram, провайдер модели, MCP-серверы организации) и не принимает запросов извне, кроме веб-кабинета за аутентификацией. Единственное исключение — необязательный режим внешнего доступа к архиву на чтение (решение Р-11), по умолчанию выключенный.
3. **Чужой текст — данные.** Входящие сообщения и ответы внешних серверов не исполняются как указания.
4. **Отправку решает не модель.** Агент может только создать черновик. Каждое исходящее сообщение проходит шлюз отправки в сервисе; от имени владельца — только после его подтверждения. Отправка целиком выключена, пока владелец не включит её на сервере (`docs/service.md`, «Отправка выключена»).
5. **Сырьё неизменяемо, знание пересобираемо.** Всё производное можно удалить и построить заново из архива.
6. **Никаких вшитых адресов.** Модель, эмбеддинги, распознавание голосовых и исходящий прокси — настройки экземпляра.

## Почему так разделено

**Бизнес-режим — плагин Hermes.** У бота один получатель обновлений, и это шлюз Hermes; перехватить бизнес-обновления можно только внутри него. Официальный плагин `NousResearch/hermes-telegram-business` готовит черновик и отправляет его владельцу с кнопками, автоотправки нет. Пока он не включён, сообщения бизнес-режима перехватывает плагин `shturman`, и до ядра Hermes они не доходят. Плагин `shturman` отдельным обработчиком, раньше всех остальных, пересылает каждое бизнес-сообщение в сервис переписки — так оно попадает в архив. Сейчас это две независимые системы черновиков: официальный плагин делает свои, со своими кнопками, мимо шлюза отправки сервиса; как их свести — открытый вопрос (`docs/decisions.md`). Скачивание медиа и голосовые не сделаны.

**Дополнительный аккаунт — отдельный сервис.** Плагины Hermes исполняются в процессе агента без изоляции, а у агента есть терминал. Сессия Telethon даёт полный доступ к аккаунту, поэтому хранится вне процесса агента, в каталоге, который контейнеру Hermes не подключён. Перезапуск и обновление Hermes не рвут сессию.

**Между Hermes и сервисом два пути, у каждого свой токен.** Агент читает архив по MCP (`/mcp`, только чтение). Плагин `shturman` ходит во внутренний API (`/api`): пересылает бизнес-сообщения и нажатия кнопок, забирает задания. У сервиса нет ни модели, ни бота — всё, для чего они нужны, он ставит в очередь, а плагин выполняет: спросить модель, написать владельцу, отправить через бизнес-бота. Перечень заданий — `docs/service.md`.

**Архив — отдельная база, а не память Hermes.** Хранилище сессий Hermes ищет только по собственным диалогам агента и по умолчанию удаляет завершённые сессии через 90 дней.

## Три канала Telegram

| | Бизнес-бот | Дополнительный аккаунт | Экспорт истории |
|---|---|---|---|
| Чей голос | Владельца | Отдельный «ассистент» | — |
| Чаты | Личные 1:1 по фильтру | Любые, где состоит | Что выгружено |
| Прошлое | Нет, только с момента подключения | Нет, аккаунт новый | Да |
| Писать первым | Нет (ответ в течение 24 часов после входящего) | Да | — |
| Статус у Telegram | Официальный механизм | Серая зона, риск ограничений | Официальная функция |

## Уровни автономии

| Уровень | Что может ассистент |
|---|---|
| 0. Наблюдатель | Читает, ищет, сводит. Ничего не отправляет |
| 1. Черновики | Готовит сообщения; отправка после «да» владельца |
| 2. Шаблонные действия | Сам отправляет типовые сообщения людям из белого списка |
| 2а. Автоответ доверенным | Сам отвечает людям из списка доверенных; ответ готовится без инструментов |
| 3. Свободная переписка | Ведёт диалог в заданных рамках |

Написаны уровни 0, 1 и 2а; уровни 2 и 3 запланированы. Для бизнес-бота (голос владельца) потолок — уровень 1, а для доверенных — 2а. Правила уровней — `docs/service.md`.

## Модель и вспомогательные сервисы

- Модель одна — та, что настроена в Hermes. Все обращения к LLM, включая ночную обработку, идут через Hermes: сервис ставит задание, плагин спрашивает модель. Сервису переписки ключ модели не нужен.
- Провайдера выбирает владелец. Ключ API — самый устойчивый вариант для сервера без присмотра. Вход по подписке тоже работает, но у него оконные лимиты, которые фоновые задачи делят с самим владельцем, и при сбое обновления токена нужен ручной повторный вход.
- Эмбеддинги и распознавание речи подписка не покрывает: они считаются локально либо по отдельному ключу API.
- Эмбеддинги — только локальные: модель `intfloat/multilingual-e5-small` в отдельном контейнере без выхода в интернет. По умолчанию выключены, включаются командой `./ops/embeddings.sh on`; без них поиск идёт по словам. Наружу уходят только фрагменты, нужные для конкретного ответа, а не весь архив.
- Распознавание речи не сделано.
- Фоновые задачи сервиса зарегистрированы в Hermes как вспомогательные задачи: владелец может закрепить за ними дешёвую модель в настройках Hermes, отдельно от интерактивного агента.

## Связь с системами организации

Организация публикует MCP-сервер с узким набором инструментов; экземпляр подключается к нему как клиент по OAuth с минимальными правами. В аргументы инструментов не попадает свободный текст из личной переписки — только структурированные поля. Уведомления в обратную сторону — опросом со стороны экземпляра. A2A не используется: во встроенной реализации Hermes входящая задача попадает в живую сессию со всеми инструментами и памятью.

## Угрозы и меры

| Угроза | Мера |
|---|---|
| Инъекция через входящее сообщение | Сообщения — данные: в ответах архива и инструментов чужой текст вычищен от невидимых символов и стоит в рамке; команды только из управляющего чата; автоответ готовится без инструментов. Мера неполная — см. «Открытое ограничение» |
| Самовольная отправка | Главный выключатель отправки и суточный потолок задаются только окружением сервиса; агент может лишь создать черновик; ассистент не пишет первым; отправляется только строка черновика, занятая нажатием владельца; лимиты и защита от повторов |
| Подделка нажатия владельца | Плагин передаёт сервису нажатие только от привязанного владельца и только из управляющего чата; в кнопке — номер черновика и случайная метка, текст берётся из базы. Мера неполная — см. «Открытое ограничение» |
| Отправка от основного аккаунта | Роль «только чтение»: клиент пропускает к Telegram только перечень запросов на чтение; остальные модули клиента не получают |
| Утечка сессии аккаунта | Сессия в каталоге сервиса, который контейнеру Hermes не подключён; сервис работает без лишних прав, база — в закрытой сети |
| Утечка кодов входа и токенов через архив | Служебные чаты Telegram и диалог «Коды подтверждения» в архив не принимаются и агенту не отдаются |
| Утечка архива через эмбеддинги | Контейнер эмбеддингов не имеет выхода в интернет; модель скачивается заранее с проверкой контрольных сумм |
| Копии переписки в служебных данных | Содержимое выполненных заданий стирается; текст завершённых черновиков стирается через 30 дней; загруженный экспорт удаляется после перезапуска сервиса и через сутки без использования |
| Отравление памяти | Ответ модели принимается, только если цитата и срок есть в тексте сообщения; новые обязательства и новые страницы — через одобрение владельца; блок владельца на странице код не меняет |
| Подмена зависимостей сервиса | Образ собирается из списка с точными версиями и контрольными суммами |
| Ошибка оператора-агента | Стоп-точки, резервная копия перед изменениями, закреплённые версии (`AGENTS.md`) |
| Блокировка аккаунта Telegram или провайдера | Провайдер сменный; риск описан владельцу до подключения |

## Открытое ограничение: токен внутреннего API доступен агенту

Плагин `shturman` работает внутри процесса Hermes и держит `SHTURMAN_API_TOKEN`. Hermes передаёт переменные окружения в терминал агента. Агент читает чужие сообщения и имеет терминал, поэтому внедрённая в сообщение инструкция может заставить его обратиться к внутреннему API напрямую, мимо инструментов плагина и их перечня разрешённых адресов.

Что тогда возможно:

- прочитать всё, что отдаёт внутренний API;
- исключить чаты и стереть их сообщения;
- записать в архив поддельные сообщения;
- перепривязать владельца;
- изменить лимиты, список доверенных, правила автоответа и наблюдателя;
- **если отправка включена** — подделать нажатие владельца и отправить сообщение через сервис. Ограничивают это только суточный потолок `SHTURMAN_SEND_DAILY_CAP` и правило «не писать первым»: черновик агента возможен только в чат, куда владелец уже писал.

Независимо от нашего сервиса тот же агент держит токен бота и может пользоваться бизнес-подключением напрямую через Bot API Telegram. Это ограничивает только право «может отвечать», которое владелец даёт боту в настройках Telegram Business.

Что из этого следует сейчас:

- **отправка остаётся выключенной** (`SHTURMAN_SENDING=off`). Включить её через API нельзя, только в `.env` на сервере;
- пока отправка выключена, право бота отвечать в Telegram Business стоит держать выключенным;
- перед включением любого уровня выше нулевого владелец должен знать об этом ограничении.

Планируемое исправление — отдельный бот согласований, которым владеет сервис: его токен не попадает в контейнер Hermes, и нажатие владельца приходит сервису мимо агента. Решение за владельцем (`docs/decisions.md`, «Открытые вопросы»).
