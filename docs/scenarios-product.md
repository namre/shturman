# Сценарии продукта

Что «Штурман» делает для владельца — только то, что есть в коде. Для каждой функции: основной сценарий, ожидаемое поведение, пограничные случаи, как проверить, где смотреть результат и как владелец оценивает результат. Последний столбец — **статус прохода**: его заполняет тот, кто проходит сценарий на своём экземпляре (словарь — `docs/runbooks/validate.md`, «Запись результата»); в репозитории записаны только результаты локальных проверок.

Источник каждого утверждения — документ или код, названный у функции. Чего в коде не нашлось, помечено «не проверено». Поведение на настоящем Telegram и настоящей модели почти везде **не измерено** (так сказано и в самих документах) — проход владельца на своём экземпляре как раз это и проверяет.

Общие условия почти всех функций: свой бот согласований заведён и владелец к нему привязан (`PASS approvals-bot`, `PASS approvals-owner` в `./ops/doctor.sh`); без него карточки не приходят, а решения не применяются (`docs/architecture.md`, «Открытое ограничение»). Отправка собеседникам выключена (`SHTURMAN_SENDING=off`) — ни одна функция ниже ничего собеседникам не пишет.

Сокращения в столбце «Где смотреть»: **бот** — бот согласований; **приложение** — «Штурман» в Telegram (`docs/miniapp.md`); **настройки** — страница «Настройки Штурмана»; **doctor** — строка `./ops/doctor.sh`.

## Общие правила, на которые опираются пограничные случаи

Эти правила одинаковы для уведомлений, разбора входящих, черновиков ответов (сами и «Подготовить ответ»), черновиков ассистента и автоответа (`docs/service.md`, «Пачки сообщений», «Уведомления владельцу», «Разбор входящих»):

- **Пачка.** Сообщения одного отправителя подряд в одном чате с паузами не больше `SHTURMAN_PACK_GAP` (90 секунд) — одно высказывание. Альбом — одна пачка при любой паузе. Пачка закрывается, когда написал кто-то другой (в том числе владелец) или прошла пауза; дольше 10 минут закрытия не ждут (`packs.HOLD_MAX`).
- **Пересланное** — слова третьего лица: модели подаётся цитатой, само по себе не повод для автоматического запуска репетиции и автоответа; по явной просьбе владельца («Подготовить ответ») ответ готовится и на него.
- **Правка** сообщения не порождает новых уведомлений, разбора и репетиции; задача автоответа при правке снимается. **Удаление** отмечается в архиве (`tg/live.py`, `_on_deleted`); удалённое не входит в пачку и не уходит модели.
- **Только живые и свежие.** Сообщение, пришедшее в живой сессии позже чем через 3 часа после отправки (догонялка после обрыва связи), уведомлений и разбора не порождает. Импорт и догрузка истории — тоже.
- **Тихие часы** — по поясу `SHTURMAN_TIMEZONE`, по умолчанию 23:00–08:00: уведомления копятся и уходят одной пачкой в конце; карточки разбора ждут утра, кроме «срочно» от важных; дневной разбор договорённостей не идёт; сводка договорённостей ночью не приходит.
- **Ответ владельца с другого устройства** виден сервису как исходящее сообщение основного аккаунта: ждущее уведомление снимается (`answered`), ожидание ответа в разборе входящих снимается молча, карточка репетиции помечается «вы ответили сами». В способе «Через бота и помощника» — по сообщениям бизнес-режима; на настоящем Telegram не проверено.
- **Скрытое защитой** не уходит модели ни поводом, ни справкой.

## П1. Утренняя сводка и обзор недели

Код: `plugins/shturman/skills/morning-brief/SKILL.md`, `weekly-review/SKILL.md`, задачи Hermes `shturman:morning-brief`, `shturman:weekly-review` (`plugins/shturman/shturman_core/cron_jobs.py`); выбор времени — `docs/service.md`, «Сводки по расписанию». Только режим с Hermes.

**Основной сценарий.** Каждый день в выбранное время (по умолчанию 08:27 по поясу владельца) ассистент в Hermes пишет владельцу в свой бот: сроки на сегодня, просроченное, кто ждёт ответа (из разбора входящих), предложения, ждущие решения. Обзор недели — раз в неделю (по умолчанию 17:47).

**Как оценивается.** Кнопок оценки под сводкой нет — пробел для эталона «Верно / Не так» (раздел «Чего не хватает для эталона» в конце).

| Случай | Ожидается | Как проверить | Где смотреть | Статус |
|---|---|---|---|---|
| Обычный день | Сводка приходит в выбранное время ±1 минута, пункты со ссылкой на источник | Дождаться времени сводки | Бот ассистента; doctor `cron-schedule` (время следующей) | |
| Пустой день: нет сроков, просроченного, ждущих ответа и предложений | Сводки **нет** — скилл отвечает `[SILENT]`. Владелец может принять это за сбой | В день без договорённостей проверить, что сводки нет, а `cron-schedule` показывает следующий запуск | doctor `cron-schedule`, `summaries` | |
| Разбор входящих выключен | Раздела «Ждут вашего ответа» нет (`list_awaiting_reply` отвечает `not_found`) | Выключить разбор, дождаться сводки | Бот ассистента | |
| Инструмент архива ответил ошибкой | Раздел пропущен, в конце строка «не удалось проверить …», ничего не выдумано | Учение «архив отказал Hermes» (`scenarios-ops.md`) в утро сводки | Бот ассистента; doctor `archive-mcp` | |
| Владелец сменил время в настройках или приложении | Плагин применяет меньше чем за минуту; в Hermes — то же время | Сменить время, через минуту — doctor | doctor `summaries` (`in_sync`), `cron-schedule` | |
| Расписание правили в самом Hermes | `WARN summaries … drift`, вернуть — кнопкой «Применить снова» | — | doctor `summaries` | |
| Часовой пояс Hermes не тот (известный дефект) | Сводка по UTC; `FAIL hermes-tz` или `WARN cron-schedule` | Учение «пояс сбит» (`scenarios-ops.md`) | doctor `hermes-tz`, `cron-schedule` | |
| Ассистент остановлен владельцем («Остановить всё») | Сводка **приходит**: остановка не закрывает Hermes архив (`docs/service.md`, «Остановить всё», «Ограничение») | Остановить, дождаться сводки | Бот ассистента; doctor `stopped` | |
| Задача сводки выключена (`hermes cron pause`) | `cron-schedule` показывает «выключена» как норму (`PASS`); если владелец выбрал «включена» — `WARN summaries drift` | Учение «сводка выключена» | doctor `cron-schedule`, `summaries` | |

## П2. Разбор входящих

Код: `service/src/shturman/triage/`, `docs/service.md`, «Разбор входящих» (Р-92). Включает только владелец (настройки → «Уведомления» и «Да, сделать» в боте). Новые входящие уходят модели.

**Основной сценарий.** Человек пишет владельцу в личку или обращается к нему в группе. Модель читает пачку и до 10 предыдущих сообщений; владелец получает карточку, только если это требует внимания: «🔴 Срочно / Петров: … / Личный чат · 10:42». Если вопрос ждёт ответа и владелец молчит 2 рабочих часа — одно напоминание «⏰ … ждёт ответа 2 ч».

**Как оценивается.** Кнопка «Не важно» (ступень тише для человека или группы), «Не сообщать об этом чате». Пропущенное важное (модель решила «не говорить») владелец не видит вовсе — отметить его нечем.

| Случай | Ожидается | Как проверить | Где смотреть | Статус |
|---|---|---|---|---|
| Обычное сообщение от обычного человека | Тишина; напоминание, если ждёт ответа и владелец не ответил 2 рабочих часа | Попросить знакомого задать вопрос и не отвечать | Бот; приложение «Сейчас» | |
| «Срочно» от важного ночью | Карточка сразу, даже в тихие часы | Отметить человека ⭐, ночью — срочная просьба | Бот | |
| «Срочно» от обычного ночью | Карточка утром с пометкой «Пришло в тихие часы — показываю утром» | Так же, без ⭐ | Бот | |
| Пересылка без комментария | Разбор читает её как слова третьего лица и решает, сказать ли | Переслать владельцу чужое сообщение с просьбой | Бот | |
| Альбом / фото с подписью отдельным сообщением | Одна карточка на пачку; если вложения не успели разобраться — строка «чего не видел» | Прислать 3 фото и подпись | Бот | |
| Голосовое | При включённой расшифровке — по тексту; иначе модель видит «голосовое, не слушал» | Прислать голосовое с вопросом | Бот | |
| Правка сообщения | Нового разбора нет | Исправить отправленный вопрос | Бот (тишина) | |
| Удаление до разбора | Удалённое модели не уходит | Отправить и сразу удалить | Бот (тишина) | |
| Группа: обращение по @имени, ответом на сообщение владельца, «Сергей Петрович, …» (обращение владельца в начале реплики) | Разбирается; обычный текст группы без обращения — нет | Три вида обращения в тестовой группе | Бот | |
| Владелец ответил с другого устройства | Ожидание снимается молча, напоминания нет | Ответить с компьютера до истечения 2 часов | Бот (тишина) | |
| Сообщение пришло после 3 часов обрыва связи | Не разбирается | Учение «сервис остановлен» дольше 3 часов | doctor `triage` (счётчики) | |
| 10 сообщений подряд от одного человека | Одна карточка на пачку; не больше 3 карточек на чат и 20 всего в час | Отправить 10 сообщений с паузой меньше 90 с | Бот; doctor `triage` | |
| Сбой модели | Сообщения приходят обычным уведомлением; одно сообщение о сбое не чаще раза в 6 часов | Учение «кончился лимит модели» | Бот; doctor `triage` (`WARN` со сбоями) | |
| «Остановить всё» | Разбор не идёт, сообщения приходят простым уведомлением; после «Продолжить» напоминания возвращаются | Остановить, получить сообщение | Бот; doctor `stopped` | |

## П3. Уведомления «Вам написали» и «Вас упомянули»

Код: `service/src/shturman/notify/`, `docs/service.md`, «Уведомления владельцу» (Р-84). Включены по умолчанию; пока разбор входящих работает, о разбираемых сообщениях не приходят.

**Основной сценарий.** Новое личное сообщение или прямое обращение в группе — уведомление в бот: кто, где, когда, начало текста до 300 знаков, метка вложения, кнопки «Подготовить ответ», «Напомнить через час», «Не сообщать об этом чате».

**Как оценивается.** «Не сообщать об этом чате». Уведомление о каждом сообщении оказалось малополезным (известный дефект) — его заменяет разбор входящих.

| Случай | Ожидается | Как проверить | Где смотреть | Статус |
|---|---|---|---|---|
| Пачка из текста, пересланного и двух фото | Одно уведомление: «3 сообщения: ↪ пересланное от … · 🖼 фото (2) · …» | Отправить подряд | Бот | |
| Тихие часы | Копится, уходит одной пачкой в 08:00 | Написать ночью | Бот | |
| Владелец ответил раньше отправки | Уведомление снимается (`answered`) | Ответить в течение 90 секунд | Бот (тишина) | |
| Сообщение скрыто защитой | Уведомление без текста: «скрыто защитой — решите в карточке защиты» | Учение защиты (П10) | Бот | |
| Нет своего бота согласований | Уведомлений нет вовсе | — | doctor `approvals-bot`, `notify` | |

## П4. «Черновик ответа» и «Подготовить ответ» (с 0.0.12, Р-105; до этого — репетиция и `/prepare`)

Код: `service/src/shturman/rehearsal/`, `service/src/shturman/replies/delivery.py`, `docs/service.md`, «Черновик ответа на основном аккаунте» (Р-85, Р-89, Р-93, Р-105). В обоих способах работы. Основной аккаунт подключён только на чтение; отправить можно только нажатием «Отправить» и только через бизнес-бота.

**Основной сценарий.** Человек из списка `/drafts` пишет владельцу. Когда пачка закрылась, приходит карточка «✍️ Черновик ответа — ничего не отправлено» с тем, что ассистент предлагает ответить. Тот же черновик — кнопкой «Подготовить ответ» под уведомлением или карточкой разбора, на любого собеседника.

**Как оценивается.** По делу: «Отправить» — годится, «🎙 Наговорить свой» — почти, «Не годится» — не годится. Счётчики — `replies.drafts` в `GET /api/status` (`sent_7d`, `voice_7d`, `bad_7d`, `unrated_7d`), строка `replies` в `./ops/doctor.sh`, вкладка «✍️ Черновики» приложения, `/drafts`.

| Случай | Ожидается | Как проверить | Где смотреть | Статус |
|---|---|---|---|---|
| Вопрос от человека из списка | Одна карточка на пачку с текстом ответа моноширинным блоком | Попросить знакомого из списка написать | Бот; приложение «Согласования» → «Черновики ответов» | |
| Отправка выключена или нет бизнес-подключения | «Отправить» нет; строка в карточке называет почему; «Скопировать» у короткого текста | Как есть по умолчанию | Бот; строка «Ответы» в `/status` | |
| Бизнес-бот подключён, отправка включена, человек писал в последние сутки | «Отправить» есть; нажатие — одна отправка от имени владельца | `docs/runbooks/validate.md`, «Первая настоящая доставка» | Бот; приложение «История» | |
| Окно суток закрылось до нажатия | «Пока нельзя: …», черновик ждёт, «Отправить» исчезает | Нажать «Отправить» через сутки | Бот | |
| «Не годится» | Черновик снят, ничего не отправлено; остаются «Наговорить свой» и «Открыть чат» | Нажать | Бот | |
| Пачка из одних пересланных | Автоматически — нет; по «Подготовить ответ» — да, пересланное подаётся как слова третьего лица (PR #44) | Переслать чужое сообщение, нажать «Подготовить ответ» | Бот | |
| Фото без подписи | Повод для ответа после разбора фото; если разбор фото выключен — «Фото не смотрел: разбор выключен» | Прислать фото | Бот | |
| Альбом и подпись отдельными сообщениями | Одна карточка на всю пачку (PR #44) | Прислать 3 фото и текст | Бот | |
| Голосовое | С расшифровкой — по тексту; без — «Голосовое не слушал» | Прислать голосовое | Бот | |
| Собеседник исправил или удалил сообщение до карточки | Карточки нет (перед карточкой всё проверяется заново) | Исправить сразу после отправки | Бот (тишина) | |
| Владелец ответил до карточки | Карточка с пометкой «вы ответили сами — можно сравнить» | Ответить сразу | Бот | |
| Сообщение старше суток | «Подготовить ответ» отвечает «Не получилось: …» словами, кнопки может не быть | Нажать под старым уведомлением | Бот | |
| Группа | Черновика нет (только личные) | — | — | |
| Дневной предел исчерпан | Одно сообщение в сутки с кнопками «Поднять до …»; предел меняется в приложении, в боте (`/drafts cap`) и на странице (PR #45) | Поставить предел 1, получить две карточки | Бот; приложение «Черновики» | |
| Тихие часы | Карточка приходит без звука | Сообщение ночью | Бот | |
| `/prepare` | Ответ, что команды больше нет и что вместо неё | Написать `/prepare on` | Бот | |

## П6. Договорённости

Код: `service/src/shturman/processing/`, `docs/memory.md`, «Расписание прогонов», «Договорённости: что предлагается владельцу» (Р-96). Нужна модель (своя модель сервиса или задания через Hermes).

**Основной сценарий.** Разбор переписки днём раз в час (вне тихих часов) и ночью в 03:30 находит обещания: кто, кому, что, срок. Новое сразу видно в «Согласованиях» приложения; сводка с кнопками «N — верно / N — не так» приходит в бот в 13:00 и 19:00. Принятые — во вкладке «Договорённости» («Я обещал» / «Мне обещали»), обещания между другими — в «В команде».

**Как оценивается.** «Верно» / «Не так» с причиной («не обещание», «не тот человек», «неверно что», «неверный срок», «дубль», «уже сделано»). Это главная эталонная разметка этапа. Числа — `./ops/commitments.sh stats` (только агрегаты).

| Случай | Ожидается | Как проверить | Где смотреть | Статус |
|---|---|---|---|---|
| Обещание со сроком «к пятнице» | Предложено с датой, «обещано ДД.ММ» | Дождаться сводки после разговора | Бот 13:00/19:00; приложение | |
| Обещание выполнено до показа | Не предлагается, записано тихо (`done_before_shown`), видно только в `stats` (PR #48) | Пообещать и выполнить в том же чате в течение часа | `./ops/commitments.sh stats` | |
| Быстрое обещание «сейчас скину» | Показ через сутки, только если не сделано | Пообещать и не сделать | Бот через сутки | |

## Чего не хватает для эталона «Верно / Не так»

Разметка владельца есть у договорённостей, репетиции, памяти, защиты и (частично) разбора входящих. Нет у: утренней сводки и обзора недели, ответов ассистента на вопросы по архиву, черновиков, пересказа фото и документов, расшифровки голосовых. Нет у разбора входящих и защиты и способа отметить **пропущенное** — то, о чём система промолчала. Какие из этих функций размечать, решает владелец.
