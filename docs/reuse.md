# Что берём готовое, а что пишем сами

Обзор открытых проектов на 2026-10-06; таблица приведена к тому, что на деле сделано в версии 0.0.3. Правило отбора: в поставку под MIT попадает только код под MIT, Apache-2.0, BSD и лицензией PostgreSQL. Проекты под AGPL, GPL и без лицензии — только источник идей; их код и схемы не копируются.

Где в коде использованы чужие фрагменты, в шапке файла стоит строка «Основано на …» с проектом, лицензией, файлом и коммитом. Полный перечень с лицензиями — `THIRD_PARTY_NOTICES.md`.

## По частям решения

| Часть | Решение | На что опираемся |
|---|---|---|
| Настройка ключей, бота, модели | **Готовое, свой мастер поверх** | Штатные вызовы дашборда Hermes (ключи, модель, канал Telegram, вход по подписке, перезапуск шлюза); страница мастера — своя, в плагине `shturman` |
| Вход в дашборд | **Написан свой, по образцу** | Механизм своих способов входа Hermes; формат сессии — как у встроенного парольного входа (`plugins/dashboard_auth/basic`, MIT) |
| Сводка, недельный обзор, расписание | **Написаны свои скиллы на готовом cron** | Cron Hermes; скиллы `shturman:morning-brief` и `shturman:weekly-review` — свои, на русском, читают только архив и обязательства |
| Бизнес-режим Telegram | **Готовое** | Официальный `NousResearch/hermes-telegram-business` (MIT) ставится как есть, по SHA. Запись бизнес-сообщений в архив — свой обработчик в плагине `shturman` |
| Импорт экспорта Telegram Desktop | **Написан свой** | Потоковое чтение на `ijson` по официальной схеме экспорта. Имена полей и значений сверены с исходным кодом экспортёра Telegram Desktop (GPL-3.0) — **только как со справочником формата; код из него не брался** |
| Сессии аккаунтов, приём и загрузка истории | **Написано своё из фрагментов** | Telethon 1.x. Готового демона «Telethon → Postgres» под разрешительной лицензией не нашлось. Порядок запросов и курсоры синхронизации, разбор вложений — по `j2h4u/mcp-telegram` (MIT); состояния входа по QR — по `leshchenko1979/fast-mcp-telegram` (MIT); блокировка «одна сессия — один процесс» и разбор сообщений — по `chigwell/telegram-mcp` (Apache-2.0); поиск удалённого сообщения без указания чата — идея `kawaiiDango/telegram-delete-logger` (Apache-2.0) |
| Архив и его схема | **Написаны свои** | Словарь значений — как в экспорте Telegram Desktop. Образцы модели данных: `j2h4u/mcp-telegram`, `mukhanov/telemcp` |
| MCP-сервер архива | **Написан свой** | Официальный SDK `mcp` 2.x, класс `MCPServer` (FastMCP в SDK 2.x больше нет). Описания инструментов и состав полей — по `mukhanov/telemcp` (MIT) и `j2h4u/mcp-telegram` (MIT); чистка чужого текста и рамка вокруг него — по `chigwell/telegram-mcp` (Apache-2.0) и `j2h4u/mcp-telegram` |
| Эмбеддинги | **Готовое, отдельным контейнером** | HuggingFace TEI (Apache-2.0) с моделью `intfloat/multilingual-e5-small` (MIT). Не `bge-m3`: её веса занимают 2,27 ГБ и на сервер с 4 ГБ памяти не помещаются. Переранжирования нет |
| Гибридный поиск | **Написан свой по примеру** | pgvector (тип `halfvec`), штатный полнотекстовый поиск Postgres с конфигурацией `russian`; слияние рангов — по примеру из `pgvector/pgvector-python` (MIT) |
| Сопоставление людей | **Готовые библиотеки + свой реестр** | `pymorphy3`, `pytrovich`, `rapidfuzz` (все MIT), `pg_trgm`; транслитерация — своя таблица. `natasha` не используется |
| Обязательства и сроки | **Написано своё на основе** | `VsevaTech/promise-tracker` (MIT): разбор сроков, инструкция модели, проверка «срок есть в исходном тексте». На нашей таблице из 38 русских деловых формулировок его разбор сроков дал 25 верных, `dateparser` — 14; наш после доработки — 38 из 38, ни одной неверной даты. Отбор дублей и жизненный цикл — идеи `getzep/graphiti` (Apache-2.0) и `nearai/ironclaw` (MIT / Apache-2.0), без кода |
| Страницы памяти | **Написаны свои** | Формат «сводка переписывается, хронология дописывается» — идея `garrytan/gbrain` (MIT); шапка и перечень проверок — идея встроенного скилла Hermes `llm-wiki` (MIT). Сам скилл `llm-wiki` не используется: страницы собирает сервис |
| Черновики и согласование | **Написано своё на основе** | `NousResearch/hermes-telegram-business` (MIT): жизненный цикл черновика и разбор нажатий. Исправлены четыре недостатка оригинала: черновик занимается до отправки, а не после; срок годности проверяет фоновая работа; в кнопке есть случайная метка; правки текста «следующим сообщением» нет вовсе. Подтверждение вне хода модели и исход «отправлено, но ответ потерян» — замысел `tolboy/telegram-mcp-tdlib` (Apache-2.0), без кода |
| Правила отправки | **Написаны свои** | Запрет по умолчанию по чатам — замысел `Prgebish/mcp-telegram` (MIT); окно на чат, поиск повторов, дневной предел — замысел `tolboy/telegram-mcp-tdlib` (Apache-2.0). Без кода |
| Наблюдатель групп | **Написан свой на основе** | Нормализация текста и разбор ответа модели — по форку `Luan-X/hermes-telegram-business` (MIT); цикл «чат → слова → уведомление» — по образцу `paulpierre/informer` (MIT) и `aahnik/tgcf` (MIT) |
| Ночная обработка | **Написана своя** | Модуль сервиса; к модели обращается через очередь заданий и плагин |
| Кабинет во вкладке дашборда | **Не сделан** | Образцы: `hermes-example-plugins/example-dashboard`, встроенный плагин `kanban` |
| Распознавание голосовых | **Не сделано** | Кандидаты: GigaAM-v3 (MIT), `ekhodzitsky/gigastt` (MIT), `speaches` (MIT) |
| Проверочный набор вопросов | **Не сделан** | Кандидаты: `promptfoo` или `deepeval`; типы вопросов — из LongMemEval |

## Чем не пользуемся и почему

| Проект | Причина |
|---|---|
| `GeiserX/Telegram-Archive` | GPL-3.0. Самый зрелый архиватор на Postgres, но ни код, ни схему в продукт под MIT переносить нельзя |
| `groupultra/telegram-search`, `iyear/tdl` | AGPL-3.0 |
| `AIast0r/hermes-telegram-user` | Лицензии нет. По замыслу ближе всего к нам (пользовательский аккаунт как платформа Hermes на Telethon с архивом) — имеет смысл написать автору |
| Встроенный Kanban Hermes — для обязательств | Нет поля срока; исполнитель — профиль агента, а не человек; диспетчер сам запускает задачу. Подходит для очереди работ самого агента |
| Honcho, OpenViking, Basic Memory, Khoj | AGPL-3.0 |
| ParadeDB, VectorChord | AGPL-3.0 |
| `jina-reranker-v2` | Только некоммерческое использование |
| `rutimeparser` | Заброшен, лицензия в репозитории и в PyPI расходится |
| `python-telegram-bot` внутри сервиса переписки | LGPL-3.0. На нём стоит сам Hermes и его плагины — там это обычная зависимость. Сервису Bot API не понадобился: с ботом работает только плагин |
| `bge-m3`, `bge-reranker-v2-m3` | Не помещаются на сервер с 4 ГБ памяти |
| `natasha`, `petrovich` | Не понадобились: падежи имён даёт `pytrovich`, начальные формы — `pymorphy3` |
| Сторонние транслитераторы под GPL | Лицензия; таблица транслитерации своя |
| Создание бота «по QR» из дашборда Hermes | Токен бота проходит через сторонний сервис |

## Опыт работающего юзербота на Telethon

Разобран действующий самодельный юзербот (личный аккаунт, автоответ в личных сообщениях доверенным людям и наблюдение за группами). Ниже — что из его устройства переносим, а что делаем иначе.

**Берём как есть — проверенные практикой правила:**

| Правило | Зачем |
|---|---|
| Доверенных людей различать только по числовому идентификатору, не по имени пользователя | Имя пользователя можно сменить и занять |
| Свои исходящие отсекать по флагу сообщения, а не по свойству объекта | Свойство есть не во всех типах событий |
| Не обрабатывать сообщения, пришедшие через ботов | Исключает петли и чужие вставки |
| Один экземпляр на аккаунт, с блокировкой от повторного запуска | Двойной запуск ведёт к ограничению со стороны Telegram |
| Пауза между ответами и дневной лимит на аккаунт | Защита от ограничений и от разгона при сбое |
| Индикатор «печатает…» обновлять каждые 4 секунды, пока готовится ответ | Telegram гасит его примерно через 5 секунд |
| Ответ одним сообщением; длиннее ~3500 знаков — резать по абзацам | Предел сообщения — 4096 знаков |
| Посторонним не отвечать вообще | Ответ выдаёт само существование ассистента |
| В наблюдаемых группах не писать и не отмечать прочитанным | Наблюдение не должно быть заметным |
| Запрос кода входа не повторять чаще раза в час | Иначе Telegram надолго блокирует запросы; ключи приложения привязаны к приложению, смена приложения не помогает. У нас код не запрашивается вовсе: вход только по QR |
| Диагностика: проверка ключей, «что я вижу», список групп | Становятся проверками `ops/doctor.sh` и экраном в кабинете |

**Берём как возможность продукта — наблюдатель групп.** Двухступенчатый отбор: сначала ключевые слова, затем дешёвая модель со строгим форматом ответа, и только при «да» — уведомление владельцу. Со своими лимитами и защитой от повторов. Годится не только для вакансий: упоминания компании, объекта, конкурента, фамилии.

**Делаем иначе:**

| Как в юзерботе | Как у нас | Почему |
|---|---|---|
| Ответ готовит полный цикл агента со всеми инструментами — терминал, файлы, веб | Автоответ готовится вообще без инструментов: сервис сам собирает справку из архива и просит у модели только текст | Сообщение собеседника, даже доверенного, — чужой текст; с терминалом это прямой путь от внедрённой инструкции к серверу |
| Файл сессии лежит в рабочем каталоге, который наследует агент | Сессия в отдельном сервисе, недоступном агенту | Сессия — полный доступ к аккаунту |
| Вход через терминал; телефон и одноразовый код в файле настроек | Вход только по QR; номер и код не запрашиваются, пароль не сохраняется. Пока экрана нет, QR показывается в терминале владельца | `docs/setup.md` |
| Агент вызывается командой `hermes chat -q` из процесса бота | Сервис ставит задание в очередь, плагин в Hermes спрашивает модель и возвращает ответ | Сервис и Hermes в разных контейнерах; у сервиса нет ключа модели |
| Автоответ от имени владельца без подтверждения | По умолчанию — черновик на согласование; автоответ доверенным — отдельный уровень автономии, включается владельцем | `docs/architecture.md`, уровни автономии |

## Что стоило прочитать до начала разработки

1. `j2h4u/mcp-telegram` — разделение «демон с сессией ↔ MCP», структура хранилища синхронизации.
2. `NousResearch/hermes-telegram-business` и форк `Luan-X` — регистрация обработчиков, жизненный цикл черновика.
3. `mdemyanov/tg-parser` — модели экспорта и потоковое чтение.
4. `tolboy/telegram-mcp-tdlib` — модель согласования, устойчивая к внедрённым инструкциям.
5. В самом Hermes: скилл `llm-wiki`, плагин `kanban` (вкладка дашборда), `example-dashboard`.

## Оговорки

Даты последних изменений многих репозиториев проверить не удалось; звёзды и лицензии сняты 2026-10-06. У нескольких ключевых образцов один автор и почти нет звёзд — это образцы для чтения, а не зависимости. Перед включением любой зависимости её лицензия сверяется заново и вносится в `THIRD_PARTY_NOTICES.md`.

Одна лицензия требует повторной сверки: пакет словарей `pymorphy3-dicts-ru`, который ставится вместе с `pymorphy3`.
