# Что берём готовое, а что пишем сами

Документ актуализирован для 0.0.7 (2026-10-08). Числа измерений и стендовые результаты ниже относятся к указанным рядом версиям и датам; их повторная проверка в личном пилоте не подразумевается. Границы источников и согласований — `docs/target-model.md`, приёмка — `docs/runbooks/validate-pilot.md`.

Обзор открытых проектов на 2026-10-06, дополнен 2026-10-07 и 2026-10-10 (раздел «Разобрано 2026-10-10»); таблица приведена к тому, что на деле сделано в версии 0.0.4. Правило отбора: в поставку под MIT попадает только код под MIT, Apache-2.0, BSD и лицензией PostgreSQL. Проекты под AGPL, GPL и без лицензии — только источник идей; их код и схемы не копируются.

Где в коде использованы чужие фрагменты, в шапке файла стоит строка «Основано на …» с проектом, лицензией, файлом и коммитом. Полный перечень с лицензиями — `THIRD_PARTY_NOTICES.md`.

## Опыт работающего юзербота на Telethon

Разобран действующий самодельный юзербот (личный аккаунт, автоответ в личных сообщениях доверенным людям и наблюдение за группами). Ниже — что из его устройства переносим, а что делаем иначе.

**Берём как есть — проверенные практикой правила:**

| Правило | Зачем |
|---|---|
| Доверенных людей различать только по числовому идентификатору, не по имени пользователя | Имя пользователя можно сменить и занять |
| Свои исходящие отсекать по флагу сообщения, а не по свойству объекта | Свойство есть не во всех типах событий |
| Не обрабатывать сообщения, пришедшие через ботов | Исключает петли и чужие вставки |
| Один экземпляр на аккаунт, с блокировкой от повторного запуска | Двойной запуск ведёт к ограничению со стороны Telegram |
| Пауза между ответами и дневной лимит на аккаунт | Защита от ограничений и от разгона при сбое |
| Индикатор «печатает…» обновлять каждые 4 секунды, пока готовится ответ | Telegram гасит его примерно через 5 секунд |
| Ответ одним сообщением; длиннее ~3500 знаков — резать по абзацам | Предел сообщения — 4096 знаков |
| Посторонним не отвечать вообще | Ответ выдаёт само существование ассистента |
| В наблюдаемых группах не писать и не отмечать прочитанным | Наблюдение не должно быть заметным |
| Запрос кода входа не повторять чаще раза в час | Иначе Telegram надолго блокирует запросы; ключи приложения привязаны к приложению, смена приложения не помогает. У нас код не запрашивается вовсе: вход только по QR |
| Диагностика: проверка ключей, «что я вижу», список групп | Становятся проверками `ops/doctor.sh` и экраном в кабинете |

**Берём как возможность продукта — наблюдатель групп.** Двухступенчатый отбор: сначала ключевые слова, затем дешёвая модель со строгим форматом ответа, и только при «да» — уведомление владельцу. Со своими лимитами и защитой от повторов. Годится не только для вакансий: упоминания компании, объекта, конкурента, фамилии.

**Делаем иначе:**

| Как в юзерботе | Как у нас | Почему |
|---|---|---|
| Ответ готовит полный цикл агента со всеми инструментами — терминал, файлы, веб | Автоответ готовится вообще без инструментов: сервис сам собирает справку из архива и просит у модели только текст | Сообщение собеседника, даже доверенного, — чужой текст; с терминалом это прямой путь от внедрённой инструкции к серверу |
| Файл сессии лежит в рабочем каталоге, который наследует агент | Сессия в отдельном сервисе, недоступном агенту | Сессия — полный доступ к аккаунту |
| Вход через терминал; телефон и одноразовый код в файле настроек | Вход только по QR; номер и код не запрашиваются, пароль не сохраняется. Пока экрана нет, QR показывается в терминале владельца | `docs/setup.md` |
| Агент вызывается командой `hermes chat -q` из процесса бота | Сервис ставит задание в очередь, плагин в Hermes спрашивает модель и возвращает ответ | По умолчанию задания выполняет плагин Hermes; при настроенном собственном ключе их выполняет клиент сервиса |
| Автоответ от имени владельца без подтверждения | По умолчанию — черновик на согласование; автоответ доверенным — отдельный уровень автономии, включается владельцем | `docs/architecture.md`, уровни автономии |

## Разобрано 2026-10-10: идеи без кода

Два проекта, из которых код не берётся (строки в таблице выше). Ниже — что из их устройства стоит обдумать. Ничего из этого не сделано и не решено: это кандидаты, а не план; каждый при взятии в работу получает запись в `docs/decisions.md`.

Что читалось: у `crow-hq/llm-wiki-v2` — README и `docs/wiki/crow.md` (10 звёзд, 45 коммитов на дату разбора); код, статья авторов и каталог `benchmarks` не читались. У Kanban Pro — README репозитория, сайт и статья «The Agent Memory Layer»; программа не запускалась. Числа авторов `llm-wiki-v2` (89 % против 62 % попаданий в нужную заметку, вдвое быстрее, на 68 % меньше токенов) — их собственный замер, нами не повторён.

| № | Идея | Откуда | Что у нас уже есть | Что было бы новым |
|---|---|---|---|---|
| 1 | Запись о каждом автоматическом решении обработки: шаг, кто решил, что выбрано, был ли откат. При сомнении — безопасное действие (новая запись, а не слияние) и вопрос владельцу | `llm-wiki-v2`: `Decision(step, decider, choice, confidence, fallback)` | Журнал действий владельца и страницы настройки (`memory.*`, `setup.*`). Что проходит без вопроса, решает код по виду правки, а не модель | Такая же запись для решений ночной сборки: сопоставление человека с реестром, «это тот же факт или новый», отбор дублей обязательств. **Пороги по числовой уверенности модели расходятся с правилом 4 формата страницы** («числовая „уверенность“ не используется», `docs/memory.md`) — брать их можно только отдельным решением и только для выбора маршрута, не для утверждений на страницах |
| 2 | Проверочные вопросы из собственных данных: по одному вопросу на документ, правильный ответ — страница, которая на него ссылается; часть вопросов отложена для проверки | `llm-wiki-v2`, порядок калибровки в `docs/wiki/crow.md` | Синтетический набор для поиска (`docs/search.md`); набора по переписке владельца нет | Способ быстро собрать часть набора из строки «Проверочный набор вопросов»: ссылки на сообщения у утверждений уже есть, вопрос к каждому пишет модель, владелец отбраковывает. Покрывает только тип «факт»; «время», «изменение» и «отсутствие» так не получить |
| 3 | Однострочное описание страницы в шапке — оглавление для агента | Open Knowledge Format v0.2 (Google, Apache-2.0) через `llm-wiki-v2` | Шапка `entity_id`, `type`, `aliases`, `updated`; источники — ссылкой у каждого утверждения | Поле `description`, которое пишет код из действующих фактов (должность, компания, роль в проекте), а не модель. Авторы `llm-wiki-v2` отмечают: расплывчатые описания ломают навигацию. Полная совместимость с OKF не цель; обязательные поля спецификации не сверялись |
| 4 | Обязательства доской: колонки — состояния | Kanban Pro | Состояния обязательства в базе (`proposed`, `open`, `done`, `cancelled`, `rejected`, `expired`) , переходы пишутся в хронологию страницы; список «Ждут решения» на экране «Память» | Вид для экрана обязательств: «ждёт решения → в работе → просрочено → закрыто»; «просрочено» вычисляется по сроку, нового состояния не нужно. Перетаскивание карточки — это решение владельца, идёт тем же кодом, что кнопки |
| 5 | Состояние «остановлено» с причиной, чтобы не повторять неудавшееся действие | Kanban Pro, колонка Blocked | Отправка выключена; напоминания людям о сроках — в целях (`README.md`), не сделаны | Понадобится вместе с напоминаниями: «напомнили дважды, ответа нет, передано владельцу» — и больше не напоминать, пока владелец не решит |

Попутно, без отдельной строки: раздельный учёт токенов по видам вызовов модели (у `llm-wiki-v2` — два счётчика, на модель и на классификатор).

Что из разбора не следует. Статья Kanban Pro утверждает, что смешанные хранилища (таблицы и векторный индекс вместе) хуже своих частей; замеров в ней нет, и основанием менять гибридный поиск она не служит (`docs/search.md`). Классификатор, на котором стоит режим CROW, по умолчанию облачный (TypeSafe Jev через OpenRouter): фрагменты переписки уходили бы ещё одному провайдеру. Локальный вариант (Laya) упомянут в документации; помещается ли он на сервер с 4 ГБ памяти и как работает на русском — неизвестно. Сами авторы называют его слабым на числах и датах.
