# Что берём готовое, а что пишем сами

Обзор открытых проектов на 2026-10-06. Правило отбора: в поставку под MIT попадает только код под MIT, Apache-2.0, BSD и лицензией PostgreSQL. Проекты под AGPL, GPL и без лицензии — только источник идей; их код и схемы не копируются.

## По частям решения

| Часть | Решение | На что опираемся |
|---|---|---|
| Настройка ключей, бота, модели | **Готовое** | Дашборд Hermes: API Keys, Channels, вход по подписке |
| Сводка, недельный обзор, расписание | **Готовое + русские версии** | Cron и готовые сценарии Hermes `morning-brief`, `weekly-review`; скилл `meeting-action-items` |
| Бизнес-режим Telegram | **За основу** | Официальный `NousResearch/hermes-telegram-business` (MIT); слой оценки риска — из форка `Luan-X/hermes-telegram-business` (MIT). Историю переписки и медиа дописываем |
| Импорт экспорта Telegram Desktop | **За основу** | `mdemyanov/tg-parser` (MIT): модели схемы экспорта и потоковое чтение; `ijson`. Запись в базу и склейку дописываем |
| Распознавание голосовых | **Готовое, отдельным контейнером** | GigaAM-v3 (MIT) — по данным авторов заметно точнее Whisper на русском; `ekhodzitsky/gigastt` (MIT) укладывается в 0,4–0,8 ГБ памяти. Универсальная альтернатива — `speaches` (MIT) |
| Эмбеддинги и переранжирование | **Готовое, отдельным контейнером** | HuggingFace TEI (Apache-2.0) с `bge-m3` и `bge-reranker-v2-m3` |
| Гибридный поиск | **За основу** | pgvector, штатный полнотекстовый поиск Postgres с конфигурацией `russian`, пример слияния рангов из `pgvector-python` |
| Страницы памяти | **За основу** | Встроенный скилл Hermes `llm-wiki`: раскладка и проверки. Блок владельца, хронологию и проверки кодом дописываем; идея «итог сверху, хронология снизу» — из `gbrain` |
| Кабинет во вкладке дашборда | **За основу** | `hermes-example-plugins/example-dashboard`, встроенный плагин `kanban` как образец загрузки файлов и WebSocket; редактор — Milkdown или CodeMirror 6 (MIT) |
| Сопоставление людей | **Готовые библиотеки + свой реестр** | `natasha`, `pymorphy3`, `petrovich`, `rapidfuzz` (все MIT), `pg_trgm` |
| Проверочный набор вопросов | **Готовое** | `promptfoo` или `deepeval`; типы вопросов — из LongMemEval |
| Сессия дополнительного аккаунта и приём сообщений | **Пишем сами** | Telethon 1.x. Образцы: `j2h4u/mcp-telegram` (демон синхронизации, владеющий сессией), `leshchenko1979/fast-mcp-telegram` (вход по QR в вебе) |
| Архив и его схема | **Пишем сами** | Готового демона «Telethon → Postgres» под разрешительной лицензией не нашлось. Образцы модели данных: `j2h4u/mcp-telegram`, `mukhanov/telemcp` |
| MCP-сервер архива | **Пишем сами** | Все популярные MCP-серверы для Telegram — прокси к живому API без архива |
| Шлюз отправки и согласований | **Пишем сами** | Образцы: `tolboy/telegram-mcp-tdlib` (подтверждение вне хода модели, отказ по умолчанию), `Prgebish/mcp-telegram` (запрет по умолчанию по чатам, ограничение частоты) |
| Обязательства и сроки | **Пишем сами** | Образец схемы — `VsevaTech/promise-tracker` (MIT). Сроки считает наш код: `dateparser` разобрал 11 из 20 русских формулировок вроде «к пятнице» и «до конца месяца» |
| Ночная сборка | **Пишем сами** | Плагин на доступе к модели Hermes; перечень шагов — из `gbrain` |

## Чем не пользуемся и почему

| Проект | Причина |
|---|---|
| `GeiserX/Telegram-Archive` | GPL-3.0. Самый зрелый архиватор на Postgres, но ни код, ни схему в продукт под MIT переносить нельзя |
| `groupultra/telegram-search`, `iyear/tdl` | AGPL-3.0 |
| `AIast0r/hermes-telegram-user` | Лицензии нет. По замыслу ближе всего к нам (пользовательский аккаунт как платформа Hermes на Telethon с архивом) — имеет смысл написать автору |
| Встроенный Kanban Hermes — для обязательств | Нет поля срока; исполнитель — профиль агента, а не человек; диспетчер сам запускает задачу. Подходит для очереди работ самого агента |
| Honcho, OpenViking, Basic Memory, Khoj | AGPL-3.0 |
| ParadeDB, VectorChord | AGPL-3.0 |
| `jina-reranker-v2` | Только некоммерческое использование |
| `rutimeparser` | Заброшен, лицензия в репозитории и в PyPI расходится |
| `python-telegram-bot` внутри сервиса переписки | LGPL-3.0. На нём стоит сам Hermes и его плагины — там это обычная зависимость; в своём сервисе берём `aiogram` (MIT), если понадобится Bot API |
| Создание бота «по QR» из дашборда Hermes | Токен бота проходит через сторонний сервис |

## Что прочитать до начала разработки

1. `j2h4u/mcp-telegram` — разделение «демон с сессией ↔ MCP», структура хранилища синхронизации.
2. `NousResearch/hermes-telegram-business` и форк `Luan-X` — регистрация обработчиков, жизненный цикл черновика.
3. `mdemyanov/tg-parser` — модели экспорта и потоковое чтение.
4. `tolboy/telegram-mcp-tdlib` — модель согласования, устойчивая к внедрённым инструкциям.
5. В самом Hermes: скилл `llm-wiki`, плагин `kanban` (вкладка дашборда), `example-dashboard`.
