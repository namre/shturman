# Сервис переписки

Единственная часть «Штурмана» вне Hermes: держит сессии Telegram, ведёт архив и отдаёт его агенту. Этот документ — что сервис делает, какие у него режимы и что из этого уже написано.

## Что готово

| Срез | Состояние |
|---|---|
| 1. Схема архива, импорт экспорта Telegram Desktop, полнотекстовый поиск, команды `shturman` | **Написано, покрыто тестами** (18 тестов на Postgres 16) |
| 2. Сессии Telegram и приём сообщений в реальном времени | Запланировано |
| 3. MCP-сервер архива для Hermes | Запланировано |
| 4. Запись бизнес-сообщений из плагина Hermes | Запланировано |
| 5. Шлюз отправки и согласований, автоответ доверенным, наблюдатель групп | Запланировано |
| 6. Вкладка «Штурман» в дашборде | Запланировано |
| Векторный поиск, страницы памяти, обязательства | Запланировано |

Замер среза 1 на синтетическом экспорте: 300 000 сообщений в 300 чатах, файл 184 МБ — импорт за 24 секунды при 31 МБ памяти; повторный импорт того же файла дублей не создаёт; база после импорта — 422 МБ. Замер сделан на тестовой машине, не на эталонном сервере.

## Аккаунты и источники

«Аккаунт» в архиве — это точка зрения, с которой пронумерованы чаты и сообщения. У основного аккаунта владельца три возможных источника, и все они дают одни и те же идентификаторы, поэтому складываются в одни строки без дублей.

| Аккаунт | Источник | Что даёт | Может ли отправлять |
|---|---|---|---|
| Основной (владелец) | Экспорт Telegram Desktop | Прошлое: всё, что выгружено | — |
| Основной (владелец) | Бизнес-бот | Новые личные чаты по фильтру владельца | Да — ответ в личном чате в течение 24 часов после входящего |
| Основной (владелец) | Сессия Telethon **только на чтение** — необязательный режим | Группы и каналы основного аккаунта, история без выгрузки | **Нет.** В сервисе нет пути отправки для этой роли |
| Дополнительный (помощник) | Сессия Telethon | Чаты и группы, где состоит помощник | Да — через шлюз отправки |

Режим «основной аккаунт на чтение» включается владельцем отдельно, с предупреждением: на сервере появляется сессия основного аккаунта, и риск ограничений со стороны Telegram ложится на него, а не на запасной номер. От имени владельца сервис пишет только через бизнес-бота — официальным путём.

## Уровни автономии

| Уровень | Что делает ассистент | Где |
|---|---|---|
| 0. Наблюдатель | Читает, ищет, сводит | Любой источник |
| 1. Черновики | Готовит ответ, отправляет после «да» владельца | Бизнес-бот, помощник |
| 2. Шаблонные действия | Сам отправляет типовые сообщения людям из белого списка | Помощник |
| 2а. Автоответ доверенным | Сам отвечает людям из списка доверенных, без подтверждения | Бизнес-бот (голос владельца), помощник |
| 3. Свободная переписка | Ведёт диалог в заданных рамках | Помощник |

Правила уровня 2а:

- доверенные задаются только числовыми идентификаторами Telegram;
- ответ готовится с **ограниченным набором инструментов**: поиск и чтение архива, без терминала и файлов сервера — сообщение даже доверенного человека остаётся чужим текстом;
- только личные чаты, только входящие, не через ботов; свои исходящие отсекаются по флагу сообщения;
- пауза между ответами и дневной лимит на аккаунт (по умолчанию 5 секунд и 300 ответов);
- пока ответ готовится, показывается «печатает…» с обновлением каждые 4 секунды;
- ответ одним сообщением, длинный режется по абзацам;
- всем, кто не в списке, сервис не отвечает вообще.

## Наблюдатель групп

Для выбранных групп и каналов: совпадение по ключевым словам → проверка дешёвой моделью со строгим форматом ответа → уведомление владельцу в управляющий чат. В самой группе сервис не пишет и прочитанным её не отмечает. Свои пауза и дневной лимит, защита от повторов. Работает на любом аккаунте, который состоит в группе.

## Общие правила работы с Telegram

- один экземпляр на аккаунт, с блокировкой от повторного запуска;
- запрос кода входа — не чаще раза в час; при ограничении со стороны Telegram сервис ждёт указанное время и не повторяет запрос раньше;
- вход — по QR в веб-интерфейсе; облачный пароль не сохраняется;
- сессия хранится в томе сервиса и недоступна Hermes.

## Модель данных архива

| Таблица | Что хранит |
|---|---|
| `accounts` | Точки зрения: основной аккаунт и помощник |
| `peers` | Люди, боты, группы, каналы — по идентификаторам Telegram, общие для всех аккаунтов |
| `chats` | Чат с точки зрения аккаунта; признак «исключён» |
| `messages` | Сообщения дословно: текст, разметка, ответ-на, пересылка, вложение, из каких источников известно |
| `message_versions` | Прежние формулировки отредактированных сообщений |
| `imports` | Журнал импортов с итогами |

Правила, зашитые в схему и проверенные тестами:

- **Без дублей.** Сообщение определяется парой «чат, идентификатор сообщения»; повторный приход из любого источника дополняет запись, а не создаёт новую.
- **Правки не теряются и не затираются.** Более свежая правка заменяет текст, прежний уходит в историю. Старый экспорт, загруженный после новой правки, текст не перезаписывает.
- **Исключённый чат не попадает в архив** ни из одного источника; запрет запоминается.
- **Время — из точной отметки экспорта**, а не из местного времени компьютера, на котором делали выгрузку.

## Команды

```
shturman migrate                       привести схему базы к текущей версии
shturman scan result.json              показать чаты экспорта с объёмом и периодом, ничего не записывая
shturman import result.json            импортировать; --exclude user:123 — не принимать чат; --owner-id — для экспорта одного чата
shturman search "смета по фасадам"     поиск с учётом русских словоформ
```

Строка подключения — в переменной окружения `SHTURMAN_DSN`. Команда `scan` — основа экрана, на котором владелец до импорта снимает галочки с личных чатов.

## Что ещё не проверено

- совпадают ли идентификаторы сообщений в экспорте, в бизнес-потоке и в сессии одного аккаунта — на этом держится склейка без дублей;
- как Hermes ограничивает набор инструментов для ответа на чужое сообщение;
- поведение на настоящем экспорте: проверено только на синтетических данных, составленных по официальной схеме.
