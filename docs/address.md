# Адрес ассистента: свой домен, IP-адрес сервера или посредник

В режиме с Hermes владелец открывает в браузере два адреса: дашборд (мастер, вход) и страницу «Переписка». Обоим нужен HTTPS. Способов три, и выбирает из них владелец: агент проверяет сервер, рекомендует и спрашивает, но молча не выбирает (`AGENTS.md`, решение Р-71). Проверки, рекомендация и сам вопрос — `docs/runbooks/server-prepare.md`, шаг 5; подключение выбранного способа — `docs/runbooks/deploy.md`, шаг 5.

В режиме без Hermes («Только архив и согласования») адрес не нужен: экземпляр наружу ничего не публикует, страница «Переписка» и архив открываются с компьютера владельца через туннель SSH (`docs/standalone.md`).

## Три способа рядом

| | **Свой домен** | **По IP-адресу сервера** | **Через посредника `sh.namre.app`** |
|---|---|---|---|
| Что нужно владельцу | Домен или поддомен, которым он управляет, и доступ к его DNS (у регистратора, в Cloudflare, у хостинга) | Ничего, кроме сервера с белым IPv4-адресом | Код приглашения от держателя посредника; доверие держателю (риски ниже) |
| Что нужно серверу | Входящие 80, 443 и 8443 из интернета | Входящие 80, 443 и 8443 из интернета; порт 80 не закрывать и потом | Входящих — никаких (только SSH для агента); исходящие к `relay.sh.namre.app` на 443 и 7000 |
| Адрес ассистента | `https://assistant.example.ru` | `https://203.0.113.10` | `https://ivan.sh.namre.app` |
| Страница «Переписка» | `https://assistant.example.ru:8443` (или отдельное имя) | `https://203.0.113.10:8443` | `https://setup-ivan.sh.namre.app` |
| Сертификат | Let's Encrypt на имя, Caddy получает и продлевает сам | Let's Encrypt на IP-адрес, только короткий — 160 часов (профиль `shortlived`); Caddy 2.11 или новее продлевает примерно за двое суток до конца | Let's Encrypt на два имени посредника; получает Caddy самого экземпляра, ключ не покидает сервер |
| Кто ещё участвует | Регистратор и DNS-провайдер; по желанию — Cloudflare перед адресом | Только Let's Encrypt | Держатель посредника и зоны `sh.namre.app`: видит, какие имена открывают, когда, с каких адресов и сколько данных, но не содержимое страниц |
| Главные риски | Посторонних нет; если перед адресом поставить Cloudflare в режиме прокси, он расшифровывает трафик страниц | Адрес из цифр; сменится, если хостинг сменит серверу IP или сервер переедет; закрыли порт 80 — через несколько дней сертификат истечёт; только IPv4; Cloudflare перед адресом не поставить | Держатель посредника технически может направить имя владельца на свой сервер и показать поддельную страницу «Переписка» (риск 1 в `docs/relay.md`); пока `sh.namre.app` нет в Public Suffix List, другие подключённые владельцы могут мешать входу и, узнав номер подключения, захватить имя (риски 8 и 9); посредник — одна точка отказа на всех |
| Сколько стоит | Домен — по тарифу регистратора | Ничего сверх сервера | Со стороны «Штурмана» — ничего сверх сервера; условия посредника — у его держателя |
| Когда перестаёт открываться | Истёк домен, сломана запись DNS, закрыты порты | Сменился IP-адрес, закрыт порт 80 (через несколько дней), закрыты 443 и 8443 | Посредник недоступен, держатель отключил экземпляр, сеть сервера закрыла исходящий порт 7000 |
| Caddy | Из официального репозитория Caddy | 2.11 или новее (проверено с 2.11.7) | Проверено с 2.11.7 |
| Подробно | `docs/runbooks/server-prepare.md`, шаг 7б | `docs/deployment.md`, «Без домена» (Р-67) | `docs/relay.md` (Р-69, Р-70) |

Во всех трёх случаях бот в Telegram работает и без веб-адреса: он сам ходит в Telegram исходящими запросами. Перестают открываться только две веб-страницы.

## Коротко: какой рекомендовать

- Есть домен с доступом к DNS, и порты до сервера доходят — **свой домен**: постоянный адрес, никого постороннего.
- Домена нет, у сервера белый адрес, и порты доходят — **по IP**: без посторонних и без DNS. Посредник — запасной вариант.
- Входящие соединения до сервера не доходят и открыть их нельзя (сервер дома, в офисе, за общим NAT) — **через посредника**, если владелец доверяет его держателю.

Точные проверки и таблица рекомендаций — `docs/runbooks/server-prepare.md`, шаг 5.

## Как сменить способ позже

Ссылки, выданные по прежнему адресу, перестанут работать; новую ссылку входа даёт `./ops/activation-link.sh`. Правка прокси и firewall — стоп-точки.

- **На свой домен** (с IP или посредника): владелец создаёт запись DNS (`server-prepare.md`, шаг 7б); `./ops/set-public-url.sh https://новое-имя`; прокси — основной вариант `config/Caddyfile.example`; порты 80, 443 и 8443 — в firewall сервера и хостинга; `./ops/up.sh`; `./ops/state.sh set address domain`.
- **На IP-адрес** (с домена или посредника): `./ops/set-public-url.sh https://<IP>`; прокси — вариант «без домена»; порты 80, 443 и 8443; `./ops/up.sh`; `./ops/state.sh set address ip`.
- С посредника на домен или IP — сначала `./ops/relay.sh off --forget`, а после `set-public-url.sh` ещё `./ops/set-setup-url.sh https://новое-имя:8443` (или `https://<IP>:8443`): адрес страницы на имени посредника скрипт адреса дашборда сам не переносит.
- **На посредника** (с домена или IP): решение владельца после пересказа рисков; `./ops/relay.sh check КОД ИМЯ` и `join КОД ИМЯ` (`deploy.md`, шаг 5а); прокси — `./ops/relay.sh caddyfile`; `./ops/up.sh`; `./ops/state.sh set address relay`. Открытые раньше 80, 443 и 8443 можно закрыть.

Имя на посреднике после `off --forget` остаётся занятым, пока его не освободит держатель.

## Что проверено вживую (2026-10-12)

Временный сервер Amazon Lightsail (4 ГБ, Ubuntu 24.04; внешний IPv4 ведёт на сервер через NAT облака — у самого сервера только адрес закрытой сети), репозиторий на коммите этой проверки. Шаги `server-prepare.md` и `deploy.md` выполнялись по тексту, с компьютера владельца через SSH; один и тот же сервер последовательно переводился с одного способа на другой (как в «Как сменить способ позже»), основная установка — один раз.

- **Шаг 5 подготовки.** 5а: `ip_kind` — `public`, в `ip -4 -brief addr` только `172.26.…` — «внешний адрес через NAT». 5б: при закрытых в панели хостинга портах — `curl: (28)` на 80 и 443, после открытия 80, 443 и 8443 в панели — `200` на всех трёх. 5в: `{"ok": true, "version": "0.3.0"}` и `port-7000-ok`.
- **Свой домен** (имя в зоне, которой управляет держатель проверки, запись `A` на адрес сервера): `./ops/set-public-url.sh https://ИМЯ` — страница настройки на том же имени с портом 8443; прокси — основной вариант образца; `./ops/up.sh` — `ИТОГ: OK` (`public-url`, `login-page`, `setup-origin`, `setup-page-public`, `setup-isolation`). С компьютера владельца (Windows, сеть в России): дашборд → 302 на вход Hermes, `/shturman-auth/login.html` → 200, `/shturman-setup/` по адресу дашборда → 404, страница «Переписка» на `:8443` → 200.
- **По IP**: `./ops/set-public-url.sh https://<IP>` перенёс и адрес страницы на `https://<IP>:8443`; прокси — вариант «без домена» с `default_sni`; `./ops/up.sh` — `ИТОГ: OK`, `PASS proxy-cert` на 443 и 8443 (настоящий Let's Encrypt, 160 часов; сервер дотянулся до своего внешнего адреса через NAT облака), `PASS proxy-version`. С компьютера владельца: дашборд → 302, **вход Hermes по адресу из IP** → 302 на страницу входа «Штурмана» (Hermes принял IP-адрес как адрес дашборда), страница входа → 200, `/shturman-setup/` по адресу дашборда → 404, страница «Переписка» на `:8443` → 200, `http://` → 308 на https. Сертификаты проверены системным хранилищем Windows.
- **Через посредника**: порты 80, 443 и 8443 снова закрыты (ufw и панель хостинга); `./ops/relay.sh check` — служебное имя `relay` (выход 3, три свободных варианта), неверное имя (выход 2, до обращения к посреднику), свободное имя (выход 0, код не израсходован); занятое имя — `taken` и три варианта; `join` — подключён, код израсходован; прокси — файл `./ops/relay.sh caddyfile`; `./ops/up.sh` — `ИТОГ: OK` со строками `relay*`. С компьютера владельца: дашборд → 302, вход Hermes → 302, страница входа → 200, `/shturman-setup/` по адресу дашборда → 404, страница «Переписка» на своём имени → 200, прямое соединение на IP сервера — таймаут. После проверки имя освобождено (`relayctl revoke`, `release`), сервер и запись DNS удалены.

Не проверено: вход в дашборд до конца (ссылку активации не выдавали), продление сертификатов, домашняя сеть и роутер (NAT облака пропускает все порты, домашний — обычно нет: на шаге 5б это показал бы таймаут).
