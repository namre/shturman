Что из правил `AGENTS.md` защищено **технически** — скрипт отказывает, требует человека или подтверждения, права файлов не пускают, — а что держится **только на тексте**, который агент обязан соблюдать. Сверено с `ops/*.sh`, `compose.yaml`, `docs/runbooks/server-prepare.md` и кодом сервиса на 2026-10-16 (после PR #48). Предложения в конце — без реализации.

## Сначала — честный предел

Оператор (Codex на компьютере владельца) заходит на сервер пользователем `shturman` (`ssh shturman-app`). По `docs/runbooks/server-prepare.md` у этого пользователя:

- `sudo` без пароля на всё (`/etc/sudoers.d/shturman`: `shturman ALL=(ALL) NOPASSWD:ALL`, шаг 4);
- группа `docker` (шаг 6; runbook сам говорит владельцу: «членство в группе `docker` равно правам администратора»);
- он же — владелец каталога `/opt/shturman`: `.env` (права 600), `data/` (700), `local/backups` (700) принадлежат ему. Права файлов от него ничего не закрывают.

Доступ к Docker — это root: можно подключить любой каталог сервера в контейнер, прочитать окружение контейнеров (`docker inspect` показывает переменные с токенами), выполнить `psql` в контейнере базы. Поэтому **против оператора сегодня технически не защищено почти ничего**. Замки в скриптах защищают от ошибки и от «случайной» команды — например, навязанной внедрённой инструкцией, — но не от агента, который решил их обойти. Технические границы, которые в стеке есть, проведены против **ассистента в Hermes**, а не против оператора.

Чтобы замки работали и против оператора, нужно лишить его группы `docker` и `sudo` на всё — решение «а» в `decisions-options.md`.

## Стоп-точки и запреты `AGENTS.md`

Оценка — против оператора с правами выше. «Только текст» — скрипт выполняет действие без подтверждения человека.

| Правило | Что есть в скриптах и правах | Оценка |
|---|---|---|
| Секреты вводит человек (`init-env.sh` без `--auto`) | Скрипт без `--auto` отказывает, если ввод не из терминала (`[ ! -t 0 ]`); `ssh -t` это обходит. Сами секреты лежат в `.env` и `data/shturman/setup`, читаемых оператором | частично |
| Ссылка активации (`activation-link.sh`) — только по просьбе | Скрипт печатает ссылку любому, кто запустил | только текст |
| Ссылка на страницу настройки (`setup-link.sh`) — только по просьбе | То же | только текст |
| Ссылка привязки к боту (`bot-bind.sh`) — только по просьбе | То же | только текст |
| Токен архива (`mcp-token.sh`) запускает только человек | (Р-98) Все режимы — показ, `--pipe`, `--out ФАЙЛ` — требуют терминала человека: stdin — терминал и есть управляющий терминал `/dev/tty`; иначе отказ с кодом 2 до чтения `.env`. Команда агента с перехватом вывода (Codex, Claude Code) терминала не имеет — проверено тестом (`ops/tests/mcp_token.sh`). Обходится псевдотерминалом (`script`, `ssh -t` из агента) — это уже намеренный обход. Токен по-прежнему строка `.env` | частично (против случайной команды — технически) |
| Вход в Telegram (`tg-login.sh`) — только человек | Скрипт требует терминал (обходится `ssh -t`); вход без телефона владельца не завершить | частично (вход — технически, вывод QR — текст) |
| Правка прокси, firewall, порт 8443, `sudo`, пакеты, SSH, TLS | `sudo` без пароля на всё | только текст; последствия видит `doctor` (`setup-isolation`, `service-bind`, `dashboard-bind`) |
| DNS | У оператора нет доступа к регистратору | технически |
| Смена адреса страницы (`set-setup-url.sh`) | Без подтверждения; совпадающий с дашбордом адрес не принимается | частично |
| Посредник: `relay.sh join` | Нужен одноразовый код от владельца | технически для `join`; `on`, `off` — только текст |
| `SHTURMAN_BOT_MANAGER_API` | Строка `.env` | только текст |
| Смена режима (`mode.sh set`) | Без подтверждения | только текст |
| Создание бота согласований, бизнес-режим | Аккаунт владельца в Telegram | технически |
| Удаление и перезапись данных (`down -v`, `prune`, восстановление, `git reset --hard`) | (Р-100) Восстановление, откат базы (`./ops/restore.sh`, автоматический откат `./ops/update.sh`), удаление копий (`./ops/cleanup.sh --backups`) — только после нажатия владельца «Разрешить» в боте согласований: нажатие приходит из его аккаунта Telegram, а не с сервера; агенту нажать нечем. Это **сильнее** прежней фразы в терминале (Р-97), которую тот же пользователь мог набрать псевдотерминалом. Фраза осталась только запасным путём, когда бота нет — и только тогда псевдотерминал снова обход. Против оператора с `docker` — запись в таблицу `ops_consents` или подмена копии владельца, это уже намеренный обход прав. `down -v`, `prune`, `git reset --hard` — ничего | частично (восстановление, откат, копии — нажатием в боте); остальное — только текст |
| Миграции базы | `./ops/up.sh` сверяет файлы миграций с `schema_migrations` и без свежей копии останавливается (Р-97); обход `--skip-backup-check` — только нажатием владельца в боте (Р-100; без бота — фразой человека). Сами миграции по-прежнему применяются при запуске сервиса | частично |

| Включение отправки, `SHTURMAN_SEND_DAILY_CAP` | Через API не меняются; нужен свой бот; каждый черновик — нажатие владельца. Оператор меняет `.env` и базу | частично (против ассистента — технически) |

| Поиск по смыслу, защита, расшифровка голосовых: включение, выключение, смена модели | Без подтверждения; (Р-100) порог защиты (`guard.sh threshold`) — только нажатием владельца в боте | только текст; порог — частично |
| Повтор после сбоя (`retry-failed`) | Есть `--dry-run`, но запуск без него не спрашивает | только текст |
| Перепроверка договорённостей (`commitments.sh recheck`) | Без подтверждения; потолок `--limit` (300) и один раз на версию правил без `--force` | частично (ограничен расход) |
| Публикация `/mcp`, `/api/*` наружу | `sudo` на прокси | только текст; `doctor` видит `service-bind` |
| Сообщение от имени владельца | Отправка выключена, нужен свой бот и нажатие владельца — против ассистента; оператор может включить в `.env` | частично |
| Не запускать агента без подтверждений под root | Настройки Codex на компьютере владельца, в репозитории ничего | только текст |
| `docker compose config` только с `--quiet` | Ничего | только текст |
| Не открывать приложение «Штурман», не подделывать данные входа Telegram | Подпись входа — токеном бота согласований, который оператор может прочитать | только текст (против ассистента — технически) |
| Не заходить на страницу настройки | Вход — по ссылке, которую оператор может выпустить | только текст |
| Не читать `data/shturman`, базу, копии | Права файлов — оператора | только текст |
| Не извлекать токены из окружения контейнеров | `docker inspect` их показывает | только текст |
| Не подтверждать за владельца | Против API — технически; против прямой записи в базу — нет | частично |
| Не обходить провал проверки | Ничего | только текст |
| Лицензии AGPL, LGPL, BSL | Проверки в CI нет | только текст |
| Код приглашения и ключи посредника | Строки `.env` | только текст |
| Hermes не изменяем | Официальный образ по версии, своего образа Hermes нет; права контейнера сверяет `doctor` | технически (против случайной правки) |
| «Остановить всё» снимает только владелец | Против API и ассистента — технически; триггеры базы — тоже, но оператор с `psql` может снять флаг | частично |

**Итог.** Из примерно сорока правил против оператора технически защищены только те, что требуют телефона или аккаунта владельца (Telegram, @BotFather, OpenAI, DNS, код посредника), и несколько проверок вида записи. Всё остальное — текст.
