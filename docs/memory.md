## Два слоя под два объёма

| | Архив | Курируемый слой |
|---|---|---|
| Объём | Сотни тысяч сообщений | Сотни–тысячи страниц |
| Что это | Переписка дословно | Страницы о людях, проектах, решениях; обязательства; профиль и правила владельца |
| Кто пишет | Приём сообщений, без LLM | LLM ночной сборкой + владелец |
| Где лежит | Postgres | Markdown в git + таблицы Postgres |
| Как ищется | Полнотекстовый поиск с русской морфологией + векторный | Тот же индекс Postgres + чтение файлов агентом |

Память самого Hermes (`MEMORY.md`, `USER.md`) используется только под короткий профиль и постоянные правила: она ограничена парой тысяч символов и всегда находится в системном промпте.

## Кто чему хозяин

У каждого вида данных один источник истины, синхронизация только в одну сторону.

| Данные | Источник истины | Производное |
|---|---|---|
| Сообщения | Postgres, неизменяемо | Индексы |
| Люди: идентификаторы, имена, алиасы | Postgres | Шапка страницы человека |
| Обязательства: кто, кому, что, срок, статус | Postgres | Блок на страницах людей и проектов |
| Датированные факты с периодом действия | Postgres | Хронология на странице |
| Проза: кто этот человек, контекст проекта, как принято общаться | Markdown-файл | Индекс в Postgres |
| Заметки владельца | Markdown-файл, блок владельца | Индекс в Postgres |

Обязательство меняется командой («закрой», «перенеси срок»), а не правкой таблицы в тексте страницы: блок с таблицей перерисовывается из базы при каждой сборке.

## Страница

```markdown
---
entity_id: person:123456789
type: person
aliases: [Иван Петров, Петров, Ваня]
updated: 2026-10-06
---
# Иван Петров

<!-- summary: пересобирается ассистентом из хронологии и таблиц -->
Руководитель подрядчика по фасадам. Отвечает медленно, сроки называет с запасом…

<!-- owner: ассистент этот блок не трогает -->
Не писать ему после 19:00.

<!-- commitments: перерисовывается из базы -->
| Что | Срок | Статус | Источник |
|---|---|---|---|
| Прислать смету | 2026-10-10 | ждём | [сообщение](msg:…) |

<!-- timeline: только дописывается -->
- 2026-09-12 — согласовали перенос монтажа на октябрь [сообщение](msg:…)
```

Четыре правила формата:

1. **Сводку ассистент переписывает, хронологию только дописывает.** Сводка собирается из хронологии и таблиц, а не из прежней сводки — так ошибка не закрепляется.
2. **Блок владельца неприкосновенен.**
3. **У каждого утверждения — ссылка на сообщение** и пометка происхождения: сказал владелец, сказал собеседник, вывела модель.
4. **Противоречие помечается, а не разрешается.** Старое утверждение получает дату окончания действия и остаётся в хронологии. Числовая «уверенность» не используется.

## Ночная сборка

1. Взять сообщения, пришедшие после прошлой сборки.
2. Нарезать на эпизоды; из эпизодов активных чатов извлечь кандидатов — факты, обязательства, решения — с идентификаторами сообщений.
3. Сопоставить людей с реестром; при вероятном совпадении новую запись не создавать.
4. Записать обязательства и факты в базу; дописать хронологию страниц.
5. Пересобрать сводку только затронутых страниц.
6. Перерисовать блоки из базы.
7. Проверки: страницы без ссылок на источники, битые ссылки, дубли по алиасам, слишком длинные страницы, страницы-сироты.
8. Коммит в git.
9. Переиндексировать изменённые страницы.
10. Отправить владельцу сводку изменений; рискованные правки — кнопками на одобрение.

В версии 0.0.6 через одобрение идут новые обязательства и новые страницы для людей, которых владелец ещё не подтвердил; слияние людей — тоже только по решению владельца. Ниже — правило целиком, как задумано.

Автоматически проходят только дописывание датированных фактов в уже существующие страницы. Через одобрение владельца идут: создание и слияние страниц, смена роли человека, новые обязательства, любые правки профиля и правил.

Срок в обязательстве модель копирует дословно («к среде»), а дату вычисляет код от времени сообщения. Оговорки вроде «постараюсь» обязательствами не считаются.

## Как владелец читает и правит

- **Веб-кабинет** — основной способ: страницы открываются с телефона, блок владельца редактируется, очередь одобрений там же.
- **Фразой в управляющем чате:** «неверно, Петров теперь в другой компании» — ассистент вносит правку отдельным коммитом.
- **Obsidian — по желанию.** Страницы — обычные файлы Markdown, каталог открывается как хранилище Obsidian. Синхронизация с телефоном (Obsidian Sync с серверным клиентом или собственный сервер синхронизации) в базовую поставку не входит: это платная зависимость от стороннего сервиса.

## Удаление

Каждая производная запись хранит идентификаторы сообщений-источников. Удаление сообщения или чата каскадно удаляет выведенные из него факты, обязательства и строки хронологии; затронутые сводки пересобираются. Чаты из списка исключений не попадают в архив вообще.

## Проверка качества

Набор из 50–100 вопросов по переписке владельца с известными ответами четырёх типов: факт, время, изменение, отсутствие. Прогоняется после каждого изменения поиска, схемы извлечения или сборки страниц. Опубликованные бенчмарки систем памяти для выбора решений не используются: это почти всегда самооценка вендоров на диалогах, которые на порядки меньше архива переписки.

Этого набора ещё нет. Пока его заменяет синтетический набор для поиска (`service/tests/search/data/`, скрипт `service/tools/search_eval.py`): 165 вопросов к коротким сообщениям и 78 — к длинным текстам, один правильный ответ на вопрос. По нему выбирались модели поиска по смыслу; что он показал и чего по нему сказать нельзя — `docs/search.md`.

## Что рассмотрено и не взято

| Вариант | Почему нет |
|---|---|
| Notion и другие зарубежные облачные сервисы | Нельзя разместить у себя; данные и доступ зависят от сервиса и региона; ограничения API |
| Вики без поиска, только оглавление | Перестаёт работать на 100–200 страницах |
| Двусторонняя синхронизация страниц и базы | Нет данных, что она работает надёжно; у проектов с опытом — одно направление |
| Графовая память на весь архив | Вызов LLM на каждое сообщение: дорого на сотнях тысяч сообщений; решение — только после сравнения на собственном наборе вопросов |
| Извлечение фактов из каждого сообщения при записи | Дорого, факт отрывается от контекста |
| Отдельный поисковый движок для страниц | Гибридный индекс в Postgres уже есть |
| Готовая вики с собственной базой (Outline, AppFlowy, SiYuan, Trilium, Docmost) | Не файлы Markdown и/или лицензии AGPL, BSL |
