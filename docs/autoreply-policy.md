# Где ассистент может отвечать автоматически

**Статус:** обязательное требование владельца от 2026-10-08, решение Р-61. Политика зафиксирована для реализации; новая проверка обращения/разрешения чата и групповые автоответы в 0.0.6 ещё не реализованы. Текущий сервис умеет автоответ доверенным в личных чатах; отправка по умолчанию выключена. Наблюдатель групп только уведомляет владельца.

## Основное правило

**Если сообщение не обращено прямо к владельцу или его ИИ-ассистенту, автоматический ответ допускается только в конкретном чате или группе, явно выбранных владельцем для такого режима. В остальных местах ассистент молчит.**

Прямое обращение и явно выбранный чат — два возможных основания рассмотреть сообщение для ответа. Они не отменяют выключатель отправки, права канала, ограничения адресата/участников, согласованную политику, защиту входящих и лимиты. Разрешение означает возможность ответить, а не обязанность отвечать на каждое сообщение.

Автоматические чтение, индексирование, память, извлечение фактов/задач и сводки продолжаются в разрешённых источниках независимо от права писать в эти чаты. Выбор чата для чтения, наличие его истории или добавление человека в доверенные не включает автоответы без обращения.

## Прямое обращение

Сервис должен установить, что адресат — именно владелец этого экземпляра или зарегистрированный им ассистент, а не одноимённый человек или чужой бот. Основания:

- Telegram mention/text-mention, однозначно разрешённый в числовой ID владельца или ассистента;
- reply на доступное исходное сообщение, автор которого — владелец или ассистент;
- явное обращение по заранее заданной владельцем форме имени/псевдонима, использованной как обращение: например «Бэрримор, посмотри…». Неоднозначное совпадение не считается достаточным;
- личное сообщение, адресованное проверенному аккаунту владельца или зарегистрированному ассистенту. Один лишь тип `private` у произвольного импортированного диалога не доказывает адресата.

Формы имени/псевдонима привязывает к проверенной идентичности сам владелец; правила их распознавания и отрицательные примеры должны быть определены до включения этого признака. Один вывод модели «это обращение» не заменяет проверку адресата и не расширяет область автоответов.

Само упоминание имени в третьем лице, общий вопрос группе, цитата, пересылка чужого обращения, подпись, код или текст во вложении не являются прямым обращением. Упоминание внутри цитаты/пересылки не наследует право на автоответ. Если адресат неясен либо автор исходника reply неизвестен, применяется правило «нет доказанного обращения»: нужен явно разрешённый чат, иначе ответ не отправляется.

Прямое обращение не делает собеседника владельцем, не превращает его текст в команду настройки и не даёт доступа к чужим чатам, секретам или закрытым данным. Проверки identity и полномочий команд выполняются отдельно.

## Явное разрешение чата или группы

- По умолчанию список пуст: автоответы без обращения нигде не разрешены.
- Владелец отдельно выбирает конкретные чаты/группы для ответов без обращения. Нет общего разрешения «во всех читаемых чатах» и нет автоматического наследования из списка доверенных.
- Ключ разрешения — контекст аккаунта/бота, тип peer и числовой Telegram peer ID. Имя группы, username и найденный моделью текст не являются ключом согласия.
- Если владелец выбрал всю форумную группу, интерфейс явно показывает охват всех её тем; разрешение одной темы хранится отдельно по topic ID и не распространяется на остальные.
- Владелец может задать пределы: какие участники/виды сообщений допускаются, расписание, частота и допустимые типы ответов. Настройка не означает разрешение на команды от всех участников.
- Переименование чата не меняет разрешение; новый peer, миграция группы или смена контекста аккаунта не получают его молча. Владелец подтверждает новый охват.
- Разрешение записывается из независимого owner channel. Ассистент может предложить чат, но не включить его за владельца из сообщения, результата модели или внутреннего API token.
- Отзыв разрешения блокирует уже подготовленные, ещё не отправленные ответы. Перед отправкой повторно проверяются актуальные настройки, доступность сообщения и исключения чата.

## Связь с отправкой и действующим кодом

Порядок решений:

1. Источник доступен; событие действительно входящее, пригодно для ответа и не скрыто защитой.
2. Есть доказанное прямое обращение **или** действующее owner-разрешение ответов без обращения для этого чата/темы.
3. Включён соответствующий режим ответа; канал и адресат разрешены существующей политикой, выполнено требуемое согласование владельца.
4. Выключатель отправки допускает действие, лимиты соблюдены, нет дубля/цикла и устаревшего ответа.
5. Перед фактической отправкой условия проверяются повторно.

Для сервисной отправки `SHTURMAN_SENDING=off` имеет приоритет: ни прямое обращение, ни выбранная группа не включают отправку. Основной аккаунт с ролью только чтения остаётся только читающим. Бот Hermes не подключается в бизнес-режиме от имени владельца.

Проверки собственных сообщений, известных ботов/автоматических ответов, повторной доставки, правок/удалений и возраста сообщения сохраняются. Совпадение двух оснований создаёт один кандидат, не два ответа. Вызов модели не является разрешением отправки.

В 0.0.6 `outbox/autoreply.py` разрешает только личные чаты с доверенными людьми и не умеет новый отбор по обращению/списку чатов. Эта политика добавляется поверх существующих проверок; выбор группы пока не делает её поддерживаемым каналом отправки. Наблюдатель групп остаётся только уведомляющим, пока отдельная реализация не пройдёт приёмку.

Штатный диалог владельца с ботом Hermes сохраняется. Правило регулирует участие ассистента в переписке; оно не ограничивает терминал, интернет, MCP, плагины и обновление памяти. Выключатель сервиса не управляет произвольными внешними инструментами отправки Hermes; подключённые каналы требуют отдельной настройки своей политики.

## Приёмка реализации

- Группа не выбрана, персонального обращения нет: нет ответа; память и сводки продолжаются.
- Группа не выбрана, есть обращение к владельцу/ассистенту: один кандидат; отправка только при разрешённом канале и остальных выполненных условиях.
- Чат/группа явно выбраны: отсутствие персонального обращения не мешает ответу в пределах заданной политики.
- Разрешено только чтение либо человек добавлен в доверенные: это не заменяет отдельного выбора чата для ответов без обращения.
- Имя в третьем лице, forwarded mention или неизвестный reply author: обращения нет.
- Разрешена одна forum topic: другие темы не получают разрешения.
- Разрешение отозвано во время подготовки ответа: отправка отменяется.
- `SHTURMAN_SENDING=off`: нет сервисной отправки при обоих основаниях.
- Собственное/ботовое сообщение, дубль, правка, удаление и устаревший результат не создают цикл или повторный ответ.
- Существующие настройки 0.0.6 не превращаются автоматически в новые chat permissions; их миграция и подтверждение владельцем описаны до включения нового режима.
