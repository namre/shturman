# Сервис переписки — устройство для разработчика

Что сервис делает для владельца, описано в `docs/service.md`. Здесь — как устроен код и по каким правилам он расширяется.

## Один процесс, один порт

`shturman serve` поднимает на локальном адресе сервера:

| Путь | Кто обращается | Токен | Что можно |
|---|---|---|---|
| `/health` | проверки | нет | только «жив» |
| `/api/*` | плагин «Штурмана» в Hermes; оператор командой `shturman call` | `SHTURMAN_API_TOKEN` | запись сообщений бизнес-бота, очередь заданий, нажатия кнопок, аккаунты Telegram, загрузка выгрузки, правила отправки, обязательства, люди, страницы |
| `/mcp` | агент Hermes | `SHTURMAN_MCP_TOKEN` | только чтение архива; принимаются только запросы POST |

Токены разные и не взаимозаменяемы; сервис не запустится, если они совпали или короче 32 знаков. Любой другой путь — 404, соединения WebSocket закрываются. В том же процессе живут сессии Telegram и фоновая работа: сессией владеет ровно один процесс.

## Границы, которые нельзя размывать

1. **Сервис не ходит к модели и не владеет ботом.** И модель, и бот есть только у Hermes. Всё, что требует модели, сообщения владельцу или отправки через бизнес-бота, ставится в очередь заданий (`bridge.py`), а плагин выполняет задание и возвращает результат. Плагин умеет пять видов заданий и не знает, зачем они: `llm.structured`, `llm.text`, `notify.owner`, `notify.edit`, `business.send`. Договор — в шапке `bridge.py`.
2. **Отправку решает не модель.** Модель и агент могут только создать черновик. Отправка происходит после нажатия кнопки владельцем либо по правилу автоответа доверенным, которое включил владелец. Главный выключатель `SHTURMAN_SENDING` и потолок `SHTURMAN_SEND_DAILY_CAP` читаются только из окружения (`config.py`); маршрута, который их меняет, быть не должно.
3. **Основной аккаунт владельца — только чтение.** Клиент этой роли пропускает к Telegram только разрешённый перечень запросов на чтение; пути отправки для неё в коде нет.
4. **Остальные модули не трогают Telethon.** Они получают `state.extras["tg"]` с интерфейсом `tg/gateway.py`.
5. **Текст сообщений — данные.** В промпт он попадает только как помеченный чужой текст; из него ничего не исполняется. Всё, что отдаётся агенту, проходит чистку управляющих и невидимых символов.
6. **Служебные чаты Telegram исключены всегда** (`store.BLOCKED_USER_IDS`, `BLOCKED_USERNAMES`, `BLOCKED_CHAT_TYPES`): в них лежат коды входа и токены ботов.
7. **Дату считает код.** Модель копирует формулировку срока дословно; дату от времени сообщения вычисляет разборщик. Срок, которого нет в исходном тексте, отбрасывается.
8. **Секреты не пишутся в журнал и не возвращаются из API**: токены, пароль облачного хранения Telegram, содержимое сессии. Пароль 2FA не сохраняется нигде.

## Как добавить модуль

Модуль перечислен в `app.MODULES` и может определить (пути начинаются с `/api/`; `/mcp` отдаёт только `mcp_server.py`):

```python
def routes() -> list[BaseRoute]: ...          # пути начинаются с /api/
@asynccontextmanager
async def lifespan(state: AppState): ...      # запуск и остановка фоновой работы
```

Состояние в обработчике — `state_of(request)`: `config`, `pool` (чтение и запись), `ro_pool` (только чтение), `events`, `extras`, `spawn(coro, name=...)`. Разбор тела и ошибок — помощники из `api_core.py` (`handler`, `body`, `need_int`, `need_str`, `BadRequest`).

## Общие части

| Файл | Что в нём |
|---|---|
| `app.py` | сборка приложения, проверка токенов по пути, перечень модулей `MODULES`, состояние `AppState` |
| `api_core.py` | общие маршруты: состояние, владелец, очередь заданий, нажатия кнопок; помощники разбора запроса |
| `config.py` | настройки из переменных окружения |
| `cli.py` | команды `shturman`: `serve`, `migrate`, `scan`, `import`, `search`, `call`, `tg-login` |
| `records.py` | `MessageRecord`, `ChatRecord` — запись в словаре экспорта Telegram Desktop |
| `store.py` | единственный путь записи в архив: `ensure_account`, `ensure_chat`, `upsert_messages`, `mark_deleted`, `mark_deleted_without_chat`; перечень всегда исключённых чатов |
| `jobs.py` | очередь заданий с арендой и защитой от повторов; закрытие невостребованных и стирание содержимого выполненных |
| `bridge.py` | постановка заданий плагину (`notify_owner`, `edit_owner_message`, `request_structured`, `request_text`, `request_business_send`), разбор результатов (`on_result`, `on_failure`) и нажатий кнопок (`on_callback`, `button`); владелец |
| `events.py` | события внутри процесса: `message.live`, `messages.deleted`, `chat.excluded` |
| `archive.py` | запросы чтения архива с правилами видимости — из них собираются ответы агенту |
| `sanitize.py` | чистка чужого текста и рамка `[untrusted]` перед выдачей агенту |
| `retrieval.py` | единая точка поиска для ответов агенту |
| `search.py` | полнотекстовый и гибридный поиск; вызывать через `retrieval.find` |

## Модули

| Файл или каталог | Что в нём |
|---|---|
| `telegram_export.py`, `importer.py` | разбор экспорта Telegram Desktop и потоковый импорт |
| `botapi_normalize.py` | сообщение Bot API → запись архива |
| `ingest_api.py` | приём бизнес-сообщений от плагина, список чатов и исключения, загрузка и импорт экспорта |
| `mcp_server.py` | MCP-сервер архива на `MCPServer` из SDK 2.x; основа для инструментов других модулей |
| `embeddings.py` | клиент сервера эмбеддингов и фоновый счётчик векторов |
| `tg/` | сессии аккаунтов на Telethon: клиент с перечнем разрешённых запросов, вход по QR, блокировка, загрузка истории, живые события, шлюз для остальных модулей |
| `processing/` | реестр людей, разбор сроков, извлечение обязательств, ночной прогон, страницы памяти (`pages*.py`), инструменты чтения для агента |
| `outbox/` | черновики и отправка, правила, автоответ доверенным, наблюдатель групп |

## Соглашения

- **База.** Только asyncpg, без ORM. Параметры `jsonb` передаются строкой (`json.dumps(..., ensure_ascii=False)`) с приведением `$n::jsonb`; при чтении — `json.loads`, если пришла строка. Время — `timestamptz`, в коде — `datetime` с часовым поясом.
- **Миграции** — файлы `migrations/NNNN_имя.sql`, применяются по порядку имён, каждая в своей транзакции. Применённую миграцию не правят — добавляют следующую.
- **Сообщения в архив пишет только `store.py`.** Производные данные хранят идентификаторы сообщений-источников (`messages.id`) и удаляются вместе с ними.
- **Язык.** Комментарии, документация, тексты для владельца — на русском. Имена в коде — на английском.
- **Зависимости** — только под MIT, Apache-2.0, BSD, лицензией PostgreSQL. Заимствованный код — с указанием источника в шапке файла и записью в `THIRD_PARTY_NOTICES.md`.

## Тесты

```
cd service && pip install -e '.[dev]' && pytest
```

Нужен Postgres 16 с расширениями `pg_trgm` и `vector`; адрес — в `SHTURMAN_TEST_DSN`. Тесты пересоздают схему `public`, поэтому база должна быть отдельной тестовой. Тестам страниц памяти нужен установленный git. В сеть тесты не ходят: Telegram, модель и сервер эмбеддингов заменены подставными объектами. Сервис в тесте поднимает фикстура `make_client` (см. `tests/conftest.py`).

Образ для сервера собирается из `Dockerfile`: зависимости ставятся из `requirements.lock` с проверкой контрольных сумм. Список обновляется командой из его шапки.
