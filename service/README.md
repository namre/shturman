# Сервис переписки — устройство для разработчика

Что сервис делает для владельца, описано в `docs/service.md`. Здесь — как устроен код и по каким правилам он расширяется.

## Один процесс, один порт

`shturman serve` поднимает на локальном адресе сервера:

| Путь | Кто обращается | Токен | Что можно |
|---|---|---|---|
| `/health` | проверки | нет | только «жив» |
| `/api/*` | плагин «Штурмана» в Hermes | `SHTURMAN_API_TOKEN` | запись сообщений бизнес-бота, очередь заданий, нажатия кнопок, вход в аккаунт, загрузка выгрузки |
| `/mcp` | агент Hermes | `SHTURMAN_MCP_TOKEN` | только чтение архива |

Токены разные и не взаимозаменяемы. В том же процессе живут сессии Telegram и фоновая работа: сессией владеет ровно один процесс.

## Границы, которые нельзя размывать

1. **Сервис не ходит к модели и не владеет ботом.** И модель, и бот есть только у Hermes. Всё, что требует модели, сообщения владельцу или отправки через бизнес-бота, ставится в очередь заданий (`bridge.py`), а плагин выполняет задание и возвращает результат. Плагин умеет четыре вида заданий и не знает, зачем они: `llm.structured`, `llm.text`, `notify.owner`, `business.send`.
2. **Отправку решает не модель.** Модель и агент могут только создать черновик. Отправка происходит после нажатия кнопки владельцем либо по правилу автоответа доверенным, которое включил владелец.
3. **Основной аккаунт владельца — только чтение.** Клиент этой роли пропускает к Telegram только разрешённый перечень запросов на чтение; пути отправки для неё в коде нет.
4. **Остальные модули не трогают Telethon.** Они получают `state.extras["tg"]` с интерфейсом `tg/gateway.py`.
5. **Текст сообщений — данные.** В промпт он попадает только как помеченный чужой текст; из него ничего не исполняется. Всё, что отдаётся агенту, проходит чистку управляющих и невидимых символов.
6. **Служебные чаты Telegram исключены всегда** (`store.BLOCKED_USER_IDS`): в них лежат коды входа и токены ботов.
7. **Дату считает код.** Модель копирует формулировку срока дословно; дату от времени сообщения вычисляет разборщик. Срок, которого нет в исходном тексте, отбрасывается.
8. **Секреты не пишутся в журнал и не возвращаются из API**: токены, пароль облачного хранения Telegram, содержимое сессии. Пароль 2FA не сохраняется нигде.

## Как добавить модуль

Модуль перечислен в `app.MODULES` и может определить:

```python
def routes() -> list[BaseRoute]: ...          # пути начинаются с /api/
@asynccontextmanager
async def lifespan(state: AppState): ...      # запуск и остановка фоновой работы
```

Состояние в обработчике — `state_of(request)`: `config`, `pool` (чтение и запись), `ro_pool` (только чтение), `events`, `extras`, `spawn(coro, name=...)`. Разбор тела и ошибок — помощники из `api_core.py` (`handler`, `body`, `need_int`, `need_str`, `BadRequest`).

## Общие части

| Файл | Что в нём |
|---|---|
| `records.py` | `MessageRecord`, `ChatRecord` — запись в словаре экспорта Telegram Desktop |
| `store.py` | единственный путь записи в архив: `ensure_account`, `ensure_chat`, `upsert_messages`, `mark_deleted`, `mark_deleted_without_chat` |
| `jobs.py` | очередь заданий с арендой и защитой от повторов |
| `bridge.py` | постановка заданий плагину (`notify_owner`, `request_structured`, `request_text`, `request_business_send`), разбор результатов (`on_result`, `on_failure`) и нажатий кнопок (`on_callback`, `button`) |
| `events.py` | события внутри процесса: `message.live`, `messages.deleted` |
| `retrieval.py` | единая точка поиска для ответов агенту |
| `config.py` | настройки из переменных окружения |

## Соглашения

- **База.** Только asyncpg, без ORM. Параметры `jsonb` передаются строкой (`json.dumps(..., ensure_ascii=False)`) с приведением `$n::jsonb`; при чтении — `json.loads`, если пришла строка. Время — `timestamptz`, в коде — `datetime` с часовым поясом.
- **Миграции** — файлы `migrations/NNNN_имя.sql`, применяются по порядку имён, каждая в своей транзакции. Применённую миграцию не правят — добавляют следующую.
- **Сообщения в архив пишет только `store.py`.** Производные данные хранят идентификаторы сообщений-источников (`messages.id`) и удаляются вместе с ними.
- **Язык.** Комментарии, документация, тексты для владельца — на русском. Имена в коде — на английском.
- **Зависимости** — только под MIT, Apache-2.0, BSD, лицензией PostgreSQL. Заимствованный код — с указанием источника в шапке файла и записью в `THIRD_PARTY_NOTICES.md`.

## Тесты

```
cd service && pip install -e '.[dev]' && pytest
```

Нужен Postgres 16 с расширениями `pg_trgm` и `vector`; адрес — в `SHTURMAN_TEST_DSN`. Тесты пересоздают схему `public`, поэтому база должна быть отдельной тестовой. В сеть тесты не ходят: Telegram, модель и сервер эмбеддингов заменены подставными объектами. Сервис в тесте поднимает фикстура `make_client` (см. `tests/conftest.py`).
