# Браузерная проверка страницы настройки

Ручная проверка: в CI не запускается. Проходит в настоящем браузере (Playwright, Chromium) весь путь владельца на странице `/shturman-setup/`: ссылка входа → вход → каждый раздел → выход → вход по коду от бота. Запускать после изменений в `src/shturman/setup_page/` и в том, чем страница пользуется: вход в аккаунты (`tg/`), бот согласований (`executor/`), загрузка выгрузки (`ingest_api.py`).

| Файл | Что это |
|---|---|
| `stand.py` | Стенд: настоящий сервис переписки (все модули, uvicorn, Postgres) с подставными Telegram, Bot API и сервером модели из `tests/tg` и `tests/executor`. В сеть не ходит. Рядом поднимает «пульт» — им сценарий делает то, что в жизни делает человек в Telegram: сканирует QR, нажимает «Запустить», подключает бизнес-режим |
| `setup_page.mjs` | Сценарий. Печатает строки `PASS`/`FAIL`, завершается с кодом 1, если есть `FAIL`. Сохраняет снимки экрана |

## Что нужно

- Окружение Python сервиса (`pip install -e '.[dev]'`) и Postgres 16 с `pg_trgm` и `vector`. **База — отдельная тестовая: стенд пересоздаёт в ней схему `public`.**
- Node.js 20+ и Playwright с Chromium: `npm install playwright` в этом каталоге (`node_modules` в git не попадает) либо уже установленный — тогда его каталог называется в `NODE_PATH`.
- По желанию — Python с OpenCV (`opencv-python`): сценарий распознаёт QR-коды со снимков страницы и сверяет их со ссылками. Без него эти две проверки пропускаются.

## Запуск

```
# 1. стенд (в отдельном терминале; работает, пока не остановить)
cd service
PYTHONPATH=src SHTURMAN_TEST_DSN=postgresql://postgres@127.0.0.1:5432/shturman_e2e \
  E2E_PORT=8765 python tests/e2e/stand.py

# 2. сценарий
SHTURMAN_TEST_DSN=postgresql://postgres@127.0.0.1:5432/shturman_e2e \
  E2E_PORT=8765 \
  E2E_PYTHON=/путь/к/окружению/сервиса/bin/python \
  E2E_QR_PYTHON=/путь/к/python/с/opencv \
  E2E_OUT=/куда/сохранять/снимки \
  node tests/e2e/setup_page.mjs
```

`PYTHONPATH=src` нужен, если пакет сервиса установлен из другого каталога (например, проверка идёт из git worktree). Стенд каждый раз начинает с пустой базы; перед повторным запуском сценария стенд перезапускают.

| Переменная | Зачем |
|---|---|
| `SHTURMAN_TEST_DSN` | Тестовая база — и стенду, и сценарию (им команда `shturman setup-link` пишет ссылку входа) |
| `E2E_PORT` | Порт сервиса; пульт занимает следующий. По умолчанию 8765 |
| `E2E_PYTHON` | Интерпретатор, которым сценарий запускает `shturman setup-link` и `setup-logout-all` |
| `E2E_QR_PYTHON` | Интерпретатор с OpenCV для распознавания QR; пусто — проверки пропускаются |
| `E2E_OUT` | Каталог снимков; по умолчанию — во временном каталоге |
| `E2E_ORIGIN` | Только стенду: «внешний адрес» страницы, если её открывают не по `127.0.0.1` |

## Что проверяется

- без входа: страница открывается и не содержит данных; строгие заголовки; маршруты страницы закрыты; токен внутреннего API входом не служит; чужое имя узла отвергается;
- вход по ссылке из `shturman setup-link`: значение уходит телом POST и убирается из адреса; ссылка одноразовая, новая отменяет прежнюю; cookie `HttpOnly`, `SameSite=Strict`; запрос с чужого сайта отвергается;
- бот согласований: неверный токен, токен бота, которого уже опрашивает другая программа, сохранение с применением без перезапуска, привязка владельца по ссылке и QR;
- ключи приложения; вход в оба аккаунта по QR, облачный пароль; список чатов — страницы, поиск, отбор по виду, включение, исключение, глубина истории;
- загрузка выгрузки, выбор чатов, импорт; бизнес-режим; своя модель; «Что собрано» и журнал действий;
- секреты не появляются ни в разметке, ни в ответах сервера, ни в журнале действий; страница не обращается к чужим серверам; в консоли нет ошибок;
- выход, вход по коду от бота, `shturman setup-logout-all`;
- вёрстка: компьютер и телефон, светлая и тёмная тема — страница не шире экрана. Снимки нужно **посмотреть глазами**: сценарий проверяет только ширину.

Чего сценарий не проверяет: настоящий Telegram и настоящую модель (их здесь нет), работу за обратным прокси и по https.
