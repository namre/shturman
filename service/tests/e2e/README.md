# Браузерная проверка страницы настройки

Ручная проверка: в CI не запускается. Проходит в настоящем браузере (Playwright, Chromium) весь путь владельца на странице `/shturman-setup/`: ссылка входа → вход → бот согласований → способ «Через ваш аккаунт» → ключи, вход, чаты → выгрузка → смена способа на «Через бота и помощника»: бизнес-режим, аккаунт помощника → блок «Дополнительно» (ключ модели, подписка ChatGPT вставкой адреса) → попытки подставного «дашборда» с соседнего порта → выход → вход по коду от бота. Запускать после изменений в `src/shturman/setup_page/` и в том, чем страница пользуется: вход в аккаунты (`tg/`), бот согласований (`executor/`), загрузка выгрузки (`ingest_api.py`).

| Файл | Что это |
|---|---|
| `stand.py` | Стенд: настоящий сервис переписки (все модули, uvicorn, Postgres) с подставными Telegram, Bot API, сервером модели и OpenAI для подписки ChatGPT из `tests/tg` и `tests/executor`. В сеть не ходит. Рядом поднимает «пульт» (порт + 1) — им сценарий делает то, что в жизни делает человек в Telegram: сканирует QR, нажимает «Запустить», подключает бизнес-режим, входит в ChatGPT (`/chatgpt/authorize`) — и подставной «дашборд» (порт + 2): страницу и service worker на том же имени узла, но на другом порту |
| `setup_page.mjs` | Сценарий. Печатает строки `PASS`/`FAIL`, завершается с кодом 1, если есть `FAIL`. Сохраняет снимки экрана |

## Что нужно

- Окружение Python сервиса (`pip install -e '.[dev]'`) и Postgres 16 с `pg_trgm` и `vector`. **База — отдельная тестовая: стенд пересоздаёт в ней схему `public`.**
- Node.js 20+ и Playwright с Chromium: `npm install playwright` в этом каталоге (`node_modules` в git не попадает) либо уже установленный — тогда его каталог называется в `NODE_PATH`.
- По желанию — Python с OpenCV (`opencv-python`): сценарий распознаёт QR-коды со снимков страницы и сверяет их со ссылками. Без него эти две проверки пропускаются.

## Запуск

```
# 1. стенд (в отдельном терминале; работает, пока не остановить)
cd service
PYTHONPATH=src SHTURMAN_TEST_DSN=postgresql://postgres@127.0.0.1:5432/shturman_e2e \
  E2E_PORT=8765 python tests/e2e/stand.py

# 2. сценарий
SHTURMAN_TEST_DSN=postgresql://postgres@127.0.0.1:5432/shturman_e2e \
  E2E_PORT=8765 \
  E2E_PYTHON=/путь/к/окружению/сервиса/bin/python \
  E2E_QR_PYTHON=/путь/к/python/с/opencv \
  E2E_OUT=/куда/сохранять/снимки \
  node tests/e2e/setup_page.mjs
```

`PYTHONPATH=src` нужен, если пакет сервиса установлен из другого каталога (например, проверка идёт из git worktree). Стенд каждый раз начинает с пустой базы; перед повторным запуском сценария стенд перезапускают.

| Переменная | Зачем |
|---|---|
| `SHTURMAN_TEST_DSN` | Тестовая база — и стенду, и сценарию (им команда `shturman setup-link` пишет ссылку входа) |
| `E2E_PORT` | Порт сервиса; пульт занимает следующий, подставной «дашборд» — ещё через один. По умолчанию 8765. Страница открывается как `http://localhost:<порт>`, «дашборд» — как `http://localhost:<порт + 2>`: одно имя, разные origin |
| `E2E_PYTHON` | Интерпретатор, которым сценарий запускает `shturman setup-link` и `setup-logout-all` |
| `E2E_QR_PYTHON` | Интерпретатор с OpenCV для распознавания QR; пусто — проверки пропускаются |
| `E2E_OUT` | Каталог снимков; по умолчанию — во временном каталоге |
| `E2E_REHEARSAL_OUT` | Каталог снимков раздела «Репетиция ответов»; по умолчанию — `E2E_OUT` |
| `E2E_TRIAGE_OUT` | Каталог снимков блока «Разбор входящих» и сообщений бота (макет чата Telegram); по умолчанию — `E2E_OUT` |
| `E2E_PULT_OUT` | Каталог снимков пульта (пакет 3): страница целиком на компьютере и телефоне 360, «Сейчас», «Готово»; по умолчанию — `E2E_OUT` |
| `E2E_ORIGIN`, `E2E_DASHBOARD` | Только стенду: «внешний адрес» страницы и адрес «дашборда», если нужны не `localhost` |

## Что проверяется

- без входа: страница открывается и не содержит данных; строгие заголовки; маршруты страницы закрыты; токен внутреннего API входом не служит; чужое имя узла отвергается;
- вход по ссылке из `shturman setup-link`: значение уходит телом POST и убирается из адреса; ссылка одноразовая, новая отменяет прежнюю; ключ сессии — в `localStorage` страницы, cookie нет вовсе; перезагрузка сохраняет вход; запрос с чужого сайта и с соседнего порта отвергается даже с ключом;
- первый экран: строка «что уже сделано» и счётчик собранного; первый шаг — бот согласований, второй — выбор способа, остальные шаги до выбора скрыты; у шагов есть «что это даст» и свёрнутые вопросы;
- бот согласований: неверный токен, токен бота, которого уже опрашивает другая программа, сохранение без перезапуска, привязка владельца по ссылке и QR; шаг отмечен готовым;
- способ «Через ваш аккаунт»: ключи, вход и чаты под номерами 3–5, бизнес-режима и аккаунта помощника нет; ключи приложения; вход в основной аккаунт по QR; список чатов — первые 20 и «Показать ещё» (ещё 20, вторичной кнопкой), «Читается N чатов из M в вашем Telegram», включение нажатием на название чата, поиск, отбор по виду, включение, исключение (подтверждение в строке: «Только перестать сохранять», красная «Перестать и стереть сохранённое», «Отмена» — снимок `chat-exclude-ask-desktop-light.png`), глубина истории; следующий шаг открывается, когда готов предыдущий; уведомление не ловит нажатия;
- список чатов большого аккаунта (Р-81; пульт `POST /dialogs/big` — ещё 4 000 диалогов, страница списка «думает» 0,6 с, на 25-м запросе «подождите 25 с»; `GET /dialogs/seen` — какие страницы отдал подставной Telegram): «Обновить» отвечает сразу, прежний список виден, «Загружено N из ~M», отсчёт ожидания, после него — продолжение с той же страницы (каждая страница по одному разу), поиск по концу длинного списка; снимки шага в четырёх видах на время загрузки и ожидания — в `E2E_LOAD_OUT` (по умолчанию `E2E_OUT`);

- пульт (пакет 3 ревизии удобства). Основной сценарий работает внутри шагов, поэтому его вкладки заранее отмечают шаги раскрытыми (`OPEN_STEPS`, отметка `sessionStorage` — как нажатие «Изменить»); раздел «пульт» открывает чистую вкладку: заголовок «Штурман — ваш пульт» при вкладке «Настройки Штурмана», быстрые ссылки, вступление в «Частых вопросах»; «Сейчас» — сразу под заголовком, что ждёт решения, аккаунты, последнее сообщение, сбои модели, отправка, без текста переписки и без «Остановить всё»; готовые шаги — строкой «✓ … — … · Изменить», опасные кнопки скрыты; «Изменить» раскрывает шаг и это помнится после перезагрузки; «Готово: что дальше» в конце шагов — раскрыто один раз; строка прогресса и «Журнал» — ссылки; порядок «шаги → Повседневное»; на телефоне 360 в обеих темах — флажки от 24 px, строки от 44 px, контраст текста не ниже 4,5:1, длина страницы (строка `NOTE`). В разделе сфер — «Связать со сферой…» без сферы по умолчанию; у своей модели — действующий способ и «Сменить способ…»; в способе «сотрудник» — «Какие чаты читать» по желанию, вкладки «Группы помощника» и «Ваш аккаунт». Вопрос «Не сохранять» в строке не пропадает, пока список перечитывается во время загрузки (сбой пакета 1);
- «дашборд» на соседнем порту в том же браузере: `fetch` к API страницы ничего не читает и ничего не меняет, `localStorage` «дашборда» ключа не видит, подложенные cookie не мешают и ничего не дают, окно и рамка со страницей не читаются, service worker «дашборда» страницу не контролирует и её запросов не видит. Если среда не даёт запустить service worker, сценарий пишет строку `NOTE` и ограничивается проверкой на уровне HTTP (файл под service worker страница не отдаёт);
- секреты и ключ сессии не появляются ни в разметке, ни в ответах сервера (кроме единственного ответа на вход), ни в журнале действий; страница не обращается к чужим серверам; в консоли нет ошибок;
- выход стирает ключ из хранилища; вход по коду от бота; `shturman setup-logout-all`;
- вёрстка: компьютер и телефон, светлая и тёмная тема, первый экран, шаги обоих способов и раскрытое «Дополнительно» — страница не шире экрана. Снимки нужно **посмотреть глазами**: сценарий проверяет только ширину.

Чего сценарий не проверяет: настоящий Telegram и настоящую модель (их здесь нет), работу за обратным прокси и по https.

```
E2E_PORT=8775 E2E_OUT=/куда/сохранять/снимки node tests/e2e/miniapp.mjs
```

Что проверяется: вне Telegram — просьба открыть в Telegram; заголовок рамки только для `https://web.telegram.org`; вход владельца по подписанным данным; данные входа убраны из адресной строки; ключ — только в `sessionStorage`, cookie и `localStorage` пусты; цвета темы Telegram; список (черновик, подтверждение действия, страница памяти) с кнопками как в боте, без «Изменить»; «Отправить» при выключенной отправке отвечает «Пока нельзя», черновик ждёт; «Нет» отклоняет действие, пункт исчезает; вход переживает перезагрузку; «Завести страницу» — тем же обработчиком, что под сводкой; ключ приложения не открывает страницу «Настройки Штурмана»; нет обращений к чужим адресам и ошибок в консоли; ключ сессии — только в ответе на вход, токена бота нет нигде; чужой пользователь, данные старше 10 минут и повтор использованных данных не входят; выдана ровно одна сессия; журнал без имён и текстов; чужой сайт не открывает приложение в рамке; страница не шире экрана телефона. Затем — что видит человек: карточки всех восьми видов (в том числе длинный черновик, три настоящих подтверждения действий, обе задачи ответа, скрытое сообщение, обязательства и изменение обязательства) без дат ISO, кодов кнопок, `None`/`null`, словарей и английских слов в заголовках; заголовок не повторяет вид карточки; срок решения словами; в светлой и тёмной теме Telegram, на 360 и 390 пикселях — кнопки не обрезаны и не налезают, карточка отличима от фона, страница не шире экрана (снимки — всего списка и каждой карточки); сбой сервера при загрузке списка — экран «Повторить», при входе — так и сказано; пустой список; вне Telegram и отказ входа (снимки); адреса API приложения и страницы, неверные пути и чужое имя узла в обычном браузере — страница по-русски, а не JSON, а запрос скрипта — по-прежнему JSON; адрес приложения без «/» — относительное перенаправление.

Экран «Чаты» (Р-80): открытие без запроса к Telegram, выбран ваш аккаунт, первые 20 чатов и «Показать ещё», служебный чат помечен, глубина по умолчанию из настройки аккаунта, поиск, включение с выбранной глубиной — сообщение владельцу и запись в журнале без названия, отбор по виду и «только выбранные», «Не сохранять» с подтверждением без стирания и «Вернуть в архив», «Список ещё не загружен», список большого аккаунта (Р-81; пульт `POST /chats/big`, `GET /chats/pages`): «Обновить» отвечает сразу, «Загружено N из ~M», второе окно видит ту же загрузку, «Telegram просит подождать» с отсчётом и продолжение с той же страницы, снимки в светлой и тёмной теме — в `E2E_LOAD_OUT`, аккаунт на паузе, «аккаунт не подключён» и сбой сервера (подставным ответом), телефон 360 и 390 пикселей в обеих темах — страница не шире экрана, ничего не обрезано. Ожидаемые отказы (429, 409) браузер пишет в консоль как «Failed to load resource» — их сценарий ошибками не считает.

Пакет 3: на экране «Согласования» в светлой и тёмной теме Telegram, на 360 и 390 пикселях — контраст текста не ниже 4,5:1 (содержимое карточек, вкладки, кнопки); на экране «Чаты» — «Читается N чатов из M в вашем Telegram», по 20 и «Показать ещё» по 20, строки переключателей и флажков не ниже 44 px; на вкладке «Сферы» — «Связать со сферой…» без сферы по умолчанию и с флажком «Предлагать новые чаты папки».

Раскладки и сферы (Р-82; пульт `POST /spheres/seed?role=owner`, `POST /spheres/folder-new?role=owner`, `GET /spheres/seen` — как у стенда страницы): выбор раскладки, разделы папок и «Не в папках», «Включить все» в приложении нет, «Выключить все» — с подтверждением, сообщением владельцу в бот и записью `app.bulk_off`; сферы чата из строки; вкладка «Сферы» — завести сферу, связать папку, новый чат папки предлагается и принимается; журнал «из приложения» без названий; 360 и 390 пикселей в обеих темах — страница не шире экрана, кнопки не выходят за край. Снимки — в `E2E_SPHERES_OUT` (по умолчанию `E2E_OUT`).

Пакет 4а (Р-94; пульт `POST /pack4a/seed` — договорённости основного аккаунта во всех группах срока, одна скрытая защитой, сфера у чата; `GET /pack4a/seen` — статусы, сроки, последние события и журнал `app.commitment_*`; `POST /bot/text?text=…` — владелец пишет боту; `E2E_PACK4A_OUT` — каталог снимков): «Сейчас» над «Согласованиями» — разделы со счётчиками, «Договорённости на сегодня», что работает, без текста переписки; нажатие на раздел — к нему; свёрнутый раздел после перезагрузки; «Скоро истечёт»; вкладка «Договорённости» — «Я обещал» и «Мне обещали» по группам срока, без цитат и скрытой, «Выполнено» → «Вернуть», «Перенести на завтра», «Не так» с подтверждением; `?open=commitments`; `/today` в боте (снимок `bot-today.png`); 360 и 390 пикселей в обеих темах — ширина и контраст.

Чего сценарий не проверяет: настоящий Telegram (телефон, Desktop, Web), сообщения приложения Telegram'у («готово», «развернуть», «на главный экран») — отправлять их здесь некому, работу за обратным прокси и по https.
