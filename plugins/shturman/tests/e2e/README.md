# Ручные проверки плагина

Два набора: мост к сервису переписки (Python) и вход с мастером в браузере (Playwright). В CI не запускаются.

## Мост к сервису переписки

Запускать после изменений исполнителя заданий, обработчиков Telegram, инструментов агента и прохода дашборда к сервису. Нужен интерпретатор, в котором установлен Hermes (см. «Стенд», пункт 1). Настоящий бот и модель не нужны: вместо Telegram и модели работают подставные.

| Файл | Что настоящее | Что проверяет |
|---|---|---|
| `bridge_service.py` | Сервис переписки с Postgres, код плагина, python-telegram-bot | Подключение и сообщения бизнес-режима доходят до архива; черновик через инструмент → карточка владельцу → нажатие → отправка → черновик `sent`; разбор переписки моделью и инструменты обязательств и людей; проход дашборда, в том числе загрузка 300 МБ потоком |
| `bridge_adapter.py` | Адаптер Telegram из Hermes, загрузка плагина самим Hermes | Исполнитель запускается из `connect()`, один на процесс, переживает переподключение; сообщения бизнес-режима не доходят до ядра; кнопки `sh:` достаются плагину, остальные — ядру |
| `bridge_hermes.py` | Процесс Hermes, его реестры и `ctx.llm` | Инструменты, вспомогательные задачи и скиллы зарегистрированы; инструменты видны только с подключённым сервисом; задачи по расписанию создаются один раз |

```
# сервис: отдельная тестовая база (схема public пересоздаётся) и окружение Python сервиса
SHTURMAN_TEST_DSN=postgresql://postgres@127.0.0.1:5432/shturman_test \
E2E_SERVICE_PYTHON=/путь/к/окружению/сервиса/bin/python \
python bridge_service.py

# адаптер и регистрация: каждый раз новый пустой каталог стенда (см. «Стенд», пункт 2)
HERMES_HOME=/путь/к/новому/каталогу python bridge_adapter.py
HERMES_HOME=/путь/к/новому/каталогу python bridge_hermes.py
```

`bridge_service.py` печатает строки «ok» и «FAIL» и завершается с кодом 1, если есть «FAIL». Два других печатают, что произошло на каждом шаге. Главное в выводе `bridge_adapter.py`: задачи моста появляются после `connect()` и их всегда четыре; «ядро Hermes передало агенту» — только обычное сообщение владельца; после повторного `connect()` «исполнитель взял» новое приложение.

Каталог стенда для `bridge_adapter.py` нужен новый при каждом запуске: Hermes запоминает номера принятых обновлений и повторные отбрасывает.

## Вход и мастер в браузере

Три сценария на Playwright против настоящего Hermes за Caddy. В CI не запускаются: им нужен установленный Hermes и собранный дашборд. Запускать вручную после изменений входа, страниц входа или мастера.

| Файл | Что проверяет |
|---|---|
| `auth.mjs` | Вход по ссылке активации, одноразовость ссылки, закрытость API без сессии |
| `login.mjs` | Страница ввода кода: сбой отправки, формат ввода, узкий экран |
| `wizard.mjs` | Все шаги мастера, в том числе шаг «Переписка» в состояниях «сервиса нет», «сервис прежней версии», «ничего не настроено», «всё настроено», и состояние экземпляра, прошедшего прежний мастер. Ответы провайдера модели, Telegram, перезапуск шлюза и состояние страницы настройки переписки подменяются; сама страница (`/shturman-setup/`) не открывается |

## Стенд

1. Hermes той версии, для которой написан плагин (`git clone --branch v2026.9.24`), установленный в отдельное окружение Python: `pip install -e 'hermes-agent[web,messaging]'`.
2. Пустой каталог `HERMES_HOME`; в нём `plugins/shturman` — ссылка на этот плагин, а в `config.yaml` — `plugins: {enabled: [shturman]}`.
3. Имя `shturman.test`, указывающее на `127.0.0.1`.
4. Caddy с настройкой из `config/Caddyfile.example`: адрес `http://shturman.test:8080`, каталог страниц входа — `plugins/shturman/public` этого репозитория. Проверено с Caddy 2.10.2. Сервис переписки стенду не нужен: блок `/shturman-setup/*` остаётся в настройке, но сценарии по нему не ходят.
5. Дашборд: `HERMES_DASHBOARD_PUBLIC_URL=http://shturman.test:8080 hermes dashboard --host 127.0.0.1 --port 9119 --no-open`.

## Запуск

Нужны Node.js и Playwright с Chromium (`npm install playwright` в этом каталоге; `node_modules` в git не попадает).

```
export HERMES_HOME=/путь/к/каталогу/стенда
export E2E_PYTHON=/путь/к/окружению/bin/python
export E2E_OUT=/куда/сохранять/снимки
node auth.mjs && node wizard.mjs && node login.mjs
```

Порядок важен: `login.mjs` рассчитывает, что владелец уже привязан — это делает `wizard.mjs`. Каждый сценарий печатает строки `PASS`/`FAIL` и завершается с кодом 1, если есть `FAIL`.

`auth.mjs` и `wizard.mjs` в начале удаляют состояние плагина в `HERMES_HOME/plugin-data/shturman`. На рабочем экземпляре не запускать.
