# Изменения

## 0.0.3 — 2026-10-06

- Сервис переписки стал одним работающим процессом: `shturman serve` на локальном адресе, порт 8765 — `/health`, внутренний API `/api/*` для плагина и архив `/mcp` для агента Hermes, у каждого свой токен.
- Общий путь записи в архив для экспорта, бизнес-бота и сессий; служебные чаты Telegram и диалог «Коды подтверждения» в архив не принимаются.
- Приём сообщений бизнес-бота из плагина; загрузка экспорта через внутренний API; исключение чата из архива с удалением сохранённого.
- Сессии аккаунтов Telegram на Telethon: вход по QR, основной аккаунт владельца — только чтение, аккаунт-помощник, выбор чатов владельцем, загрузка истории на 12 месяцев по умолчанию, приём новых, изменённых и удалённых сообщений, сверка.
- MCP-сервер архива для агента: девять инструментов только на чтение, чужой текст — в рамке.
- Поиск по смыслу: эмбеддинги `intfloat/multilingual-e5-small` в отдельном контейнере без выхода в интернет, гибридный поиск. По умолчанию выключено; `ops/embeddings.sh on|off|status`.
- Обработка: реестр людей, разбор сроков кодом, извлечение обязательств с одобрением владельца, ночной прогон.
- Страницы памяти о людях: файлы Markdown и история в git в каталоге данных сервиса.
- Шлюз отправки: черновики с согласованием кнопкой, автоответ доверенным, наблюдатель групп. **Отправка выключена по умолчанию** и включается только в `.env` на сервере: `SHTURMAN_SENDING`, потолок `SHTURMAN_SEND_DAILY_CAP`.
- Плагин `shturman`: мост к сервису — исполнитель заданий (модель, сообщение владельцу, отправка через бизнес-бота), пересылка бизнес-сообщений в архив, кнопки согласования; инструменты агента `shturman_draft_message`, `shturman_commitments`, `shturman_commitment_update`, `shturman_people`; скиллы `shturman:morning-brief` и `shturman:weekly-review`; проход дашборда к сервису. Экранов для этого в кабинете пока нет.
- `compose.yaml`: сервис переписки, Postgres 16 с pgvector в закрытой сети, профиль эмбеддингов. Образ сервиса собирается на сервере, зависимости — из списка с контрольными суммами (`service/requirements.lock`).
- `ops/up.sh` собирает и запускает сервис, подключает архив к Hermes; `ops/doctor.sh` проверяет сервис, базу, очередь заданий и эмбеддинги; `ops/backup.sh` дополнительно выгружает базу.
- `ops/import-export.sh` — импорт экспорта без веб-интерфейса; `ops/tg-login.sh` — вход в аккаунт Telegram, запускает человек.
- Известное ограничение: токен внутреннего API доступен агенту Hermes, поэтому отправку включать не следует (`docs/architecture.md`).
- Не проверено: настоящий Telegram, настоящая модель, запуск под Docker, эталонный сервер (`docs/service.md`, `docs/deployment.md`).
- Решения Р-29–Р-42. Изменены правила для агента: включение отправки, вход в аккаунт Telegram, команды `shturman call`, данные сервиса (`AGENTS.md`).
- **Требует действий при обновлении** — `UPGRADING.md`.

## 0.0.2 — 2026-10-06

- Плагин Hermes `shturman` (`plugins/shturman/`): вход в дашборд по одноразовой ссылке активации и по коду от собственного бота владельца; привязка владельца кнопкой «Запустить»; мастер первой настройки из шести шагов со схемами «куда нажать и что ввести»; перехват сообщений бизнес-режима, пока не включён плагин бизнес-режима.
- Выбор того, как ассистент представляется другим людям: помощник, бизнес-ассистент, ИИ-ассистент, секретарь или свой вариант.
- Пока у бота нет владельца, посторонним вместо стокового ответа Hermes уходит короткая подсказка по-русски.
- `ops/backup.sh` — копия данных; `ops/emergency-access.sh` — аварийный вход через SSH-туннель, если обычный не работает.
- `ops/set-public-url.sh`, `ops/activation-link.sh`, `ops/logout-all.sh`; `ops/up.sh` включает плагин; `ops/doctor.sh` проверяет вход, страницу входа, привязку владельца и мастер.
- `compose.yaml`: плагин подключён из репозитория только для чтения, внешний адрес передаётся Hermes.
- `config/Caddyfile.example` — образец настройки обратного прокси.
- Предложения имени и характера переехали из `config/personas.yaml` в `plugins/shturman/personas.json`.
- Решения Р-23–Р-28. Изменены правила для агента: ссылка активации, страницы входа (`AGENTS.md`).
- **Требует действий при обновлении** — `UPGRADING.md`.
