## 0.0.7 — 2026-10-08

### Ограниченные ответы и повседневные решения

- Сохраняемые задачи ответа: модель предлагает ответ, запрос определённого источника, вопрос владельцу или отказ. После решения владельца задача продолжается с прежними адресатом и целью; отказ, отмена, истечение и ошибка имеют явные состояния.
- Раздельные разрешения чтения и раскрытия для чатов, памяти и зарегистрированного внешнего источника. Сервисные свидетельства связывают фрагменты с точной задачей, запросом и версией; перед доставкой проверяются отзыв, видимость и актуальность. Готовый текст без права автоматического раскрытия ждёт точного просмотра владельца.
- Карточка источника в Telegram показывает название, получателя и тему, точный запрос, даты и пределы; кнопка «Этот поиск — на 30 дней» сохраняет только точное разрешение чтения для той же области без повторного вопроса. Однократное чтение и отказ остаются отдельными кнопками.
- Ограниченный внешний MCP-посредник поиска/чтения. Реестр и credentials — только у сервиса; модель не выбирает URL, headers или произвольный tool. Публичный HTTPS, проверка адресов, ограничение ответа и времени. Это контракт подключения, не готовая универсальная интеграция любой почты (`docs/external-sources.md`).
- Независимый бот сервиса принимает меню и команды текущего привязанного владельца только в личном чате: задачи, источники, отзыв, правила и группы. Поддельное поручение через HTTP не получает owner authority. Свободный разговор остаётся в полном штатном Hermes.
- Подготовка без доставки: режим `prepare_only` и явное решение владельца `/prepare on|off`. Начальная отправка остаётся выключенной; репетиционный черновик не становится доставляемым от последующего включения отправки.
- Групповые кандидаты — только аккаунт-помощник, достоверное новое входящее сообщение обычного пользователя, точная область аккаунта/чата/темы либо проверенное прямое обращение. Цитаты, код, пересылки, правки, боты и неизвестные признаки не создают обращения. Источники и право отправки проверяются отдельно; наблюдатель групп остаётся уведомлением владельцу.
- Исключение служебного собеседника очищает связанные копии контекста задач, задания модели и черновики; производная память помещается в карантин. Уже переданные наружу данные этим не отзываются.
- Внешний MCP одинаково проверяет эквивалентные записи Host (регистр, завершающая точка и стандартный HTTPS-порт); неоднозначные повторные заголовки отклоняются.
- Успешная доставка имеет конечный статус `completed`. Позднее подтверждение прежней неизвестной доставки исправляет связанную запись результата, не создаёт повторную отправку.
- Решение проверенного владельца может продолжить точную задачу в пределах её срока; пятиминутная свежесть сохраняется для автоматической работы без такого решения.
- Усиление привязки черновика: неизменяемые текст, получатель, тема, исходное сообщение, задача, источники и версия политики. Неизвестная доставка не повторяется автоматически.

Код реализован, конкретный облачный клиент требует живого пилота (`docs/remote-mcp.md`).

**Вторая модель поиска по смыслу**

- К `intfloat/multilingual-e5-small` добавлена вторая поддерживаемая модель — русскоязычная `deepvk/USER2-small` (Apache-2.0, 384 измерения, схема базы та же). Модель по умолчанию прежняя. - `ops/embeddings.sh` скачивает выбранную модель по закреплённой ревизии и сверяет контрольную сумму каждого файла — раньше сверялись только веса и токенизатор. У каждой модели свой каталог: смена туда и обратно ничего не перекачивает.

Имя модели сервису теперь передаёт `compose.yaml`, той же строкой, что и контейнеру.
- Смена модели — пересчёт всех векторов. Векторы двух моделей в выдаче не смешиваются: до конца пересчёта поиск по смыслу видит только уже пересчитанные сообщения, поиск по словам — весь архив. Прежние векторы не стираются, пока контейнер не подтвердил, что отдаёт новую модель.
- `GET /api/status` и `./ops/doctor.sh` показывают модель, сколько сообщений посчитано и сколько осталось; `GET /api/embeddings/status` — ещё и сколько посчитано прежней моделью. Доступность сервера эмбеддингов сервис проверяет обращением к нему, а `ops/doctor.sh` даёт контейнеру до полуминуты на прогрев, прежде чем сообщить о неполадке.
- Пачка для сервера эмбеддингов ограничена по объёму текста (`SHTURMAN_EMBEDDINGS_BATCH_CHARS`, по умолчанию 8000 знаков): пачка из длинных сообщений больше не может считаться дольше срока ожидания и застревать в очереди.
- Исправлено: `./ops/embeddings.sh off` оставлял контейнер эмбеддингов работать и занимать память — Compose не останавливает контейнер выключенного профиля сам. Теперь скрипт убирает его явно; файлы моделей и посчитанные векторы остаются. `ops/doctor.sh` раньше судил о поиске по смыслу по одному состоянию контейнера и после `off` показывал его включённым; теперь он спрашивает сервис.
- Набор и скрипт измерения поиска перенесены в репозиторий: `service/tests/search/data/`, `service/tools/search_eval.py`. Скрипт меряет и «только модель», и настоящий путь сервиса — запись в архив, фоновый счётчик, гибридный поиск. Числа и оговорки — новый документ `docs/search.md`.
- Смена модели — стоп-точка в `AGENTS.md`: только по явной просьбе владельца.

## 0.0.4 — 2026-10-07

Всё новое в этой версии по умолчанию выключено: экземпляр, который просто обновили, ведёт себя как раньше. Исключения названы в конце раздела.

**Свой бот согласований и своя модель сервиса**

- У сервиса переписки может быть свой бот — «бот согласований» (`SHTURMAN_BOT_TOKEN`). Его токен есть только в контейнере сервиса. Карточки с кнопками приходят в этого бота, а нажатие владельца сервис получает от Telegram напрямую, мимо Hermes. Владелец привязывается к боту одноразовой ссылкой: `./ops/bot-bind.sh`.
- Своя модель сервиса (`SHTURMAN_LLM_API_KEY`, `SHTURMAN_LLM_MODEL`, API, совместимый с OpenAI): сервис сам спрашивает модель при ночной обработке, сборке страниц, автоответе и в наблюдателе.
- Со своим ботом бизнес-режим Telegram подключается к нему, а не к боту Hermes; отправка от имени владельца идёт через него же.
- Со своим ботом плагину закрыты маршруты, через которые можно было подделать владельца: `/api/owner`, `/api/callbacks/telegram`, `/api/ingest/business/*` отвечают 403 с кодом `own_bot`. Задания, которые сервис выполняет сам, по HTTP закрыть нельзя: `/api/jobs/{id}/complete` и `/fail` трогают только задания плагина.
- Плагин в Hermes при своём боте уходит в спокойный режим: не привязывает владельца, не передаёт нажатия, не пересылает бизнес-сообщения. О режиме он узнаёт из `GET /api/status` и из отказа `own_bot`, переспрашивает раз в 5 минут. На старую кнопку в чате Hermes владелец получает ответ «Теперь согласования приходят в отдельного бота».
- Команды `shturman bot-bind` и `shturman bot-status`, маршрут `GET /api/executor/status`. Миграции `0013_executor.sql` и `0015_executor_bot.sql`.
- Бот и модель ходят в сеть через `EGRESS_PROXY_URL`, в том числе через прокси SOCKS (`httpx[socks]`, пакет `socksio`).

**Подтверждения владельца**

- Со своим ботом изменения, которые расширяют права ассистента или необратимо стирают данные, по HTTP не применяются: маршрут отвечает 202 `pending_confirmation`, владелец получает карточку «Подтвердите действие» и решает кнопкой. На решение час. Ужесточения применяются сразу. Что именно ждёт — таблица в `docs/service.md`.
- Маршруты `GET /api/confirmations`, `GET /api/confirmations/{id}`, `POST /api/confirmations/{id}/cancel`. Подтвердить действие по HTTP нельзя.
- `shturman call` на ответ 202 печатает «ЖДЁТ ПОДТВЕРЖДЕНИЯ В БОТЕ». `./ops/tg-login.sh` при своём боте сначала ждёт разрешения владельца в боте и только потом показывает QR-код.
- Без своего бота всё это применяется сразу, как в 0.0.3.

**Защита от внедрённых инструкций**

- Каждое входящее текстовое сообщение при записи в архив оценивает модель-классификатор `Horizon-Labs/prompt-injection-guard-small` в отдельном контейнере без выхода в интернет. Подозрительное скрывается от ассистента; владелец получает одно уведомление с кнопками «Показать ассистенту» и «Оставить скрытым» (`docs/guard.md`).
- По умолчанию выключено. Включается командой `./ops/guard.sh on`: около 0,3 ГБ скачивания, около 0,6 ГБ памяти.
- Измерено на синтетическом русском наборе, порог 0,9: модель находит 79 % попыток на своём наборе и 56 % на независимом; ложных срабатываний 8 % и 2 %. Просьбы переслать данные, сказанные как обычная просьба, ловятся редко. Это снижение риска, а не гарантия.
- Все пути, которые отдают переписку ассистенту и модели, учитывают новый признак `messages.agent_visible`. Текст скрытого сообщения через внутренний API не отдаётся, выключателя защиты в API нет.
- `/api/status`: счётчики `guard_*`. Маршрут `GET /api/guard/status`. Миграция `0014_guard.sql`.

**Режим установки без Hermes**

- Второй режим — «только архив и согласования»: `SHTURMAN_MODE=standalone`. Работают сервис переписки и база; у сервиса свой бот и своя модель; архив подключается к Codex CLI или Claude Code владельца (`docs/standalone.md`, `docs/runbooks/deploy-standalone.md`, `prompts/deploy-standalone.md`). Режим по умолчанию прежний, с Hermes.
