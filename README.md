# Штурман

**Вы ведёте — он читает дорогу.** Личный ИИ-помощник руководителя в Telegram на собственном сервере. Работает поверх стокового Hermes Agent как набор расширений и один сервис рядом; сервис с архивом можно поставить и без Hermes. Читает и помнит переписку владельца в Telegram, готовит ответы, следит за договорённостями и поручениями. Один экземпляр — один человек. Архив хранится на сервере экземпляра; выбранный провайдер модели получает необходимые для задачи фрагменты. Подключённые источники и клиенты обрабатывают данные по своим правилам.

> **Статус: 0.0.7, пилотная реализация.** Реализованы архив и память с источниками, независимые согласования владельца, ограниченные задачи ответа с дополнительным доступом, раздельные чтение и раскрытие, управление в Telegram и репетиция без доставки. Качество личных ответов, настоящие аккаунты Telegram, выбранные провайдеры модели и внешние источники требуют пилота владельца. Локальная проверка не подтверждает личный экземпляр; исторический Docker-стенд 0.0.6 описан отдельно. **Отправка по умолчанию выключена.** Целевая модель и приёмка — [docs/target-model.md](docs/target-model.md) и [docs/runbooks/validate-pilot.md](docs/runbooks/validate-pilot.md).

## Что умеет (цель)

- **Архив переписки** — владелец выбирает один из двух способов: подключает свой аккаунт Telegram только на чтение и выбирает чаты либо подключает бота к личным чатам через бизнес-режим Telegram, а в группы добавляет отдельный аккаунт помощника; прошлое можно догрузить выгрузкой из Telegram Desktop.
- **Ответы и разумная самостоятельность** — обычные ответы готовятся в пределах выбранных правил; при нехватке сведений помощник запрашивает конкретный источник и продолжает задачу после решения владельца. Чтение личных данных и раскрытие собеседнику согласуются раздельно. Повседневные решения — в отдельном боте согласований в Telegram.
- **Дополнительный Telegram-аккаунт** — «ассистент такого-то»: пишет первым, напоминает о сроках, собирает документы, работает в группах.
- **Память** — дословный архив переписки и поверх него страницы о людях и проектах и список обязательств, каждое утверждение со ссылкой на исходное сообщение.
- **Сферы** — владелец делит переписку на области жизни («Работа», «Семья»), в том числе из папок Telegram; ассистент по умолчанию ищет в сфере разговора и подписывает ответы сферами. Сейчас это правило для ассистента, а не замок; своя обработка и своя модель для сферы — следующие шаги (`docs/spheres.md`).
- **Голосовые и «кружки»** — по желанию владельца расшифровываются в текст на его же сервере; ассистент и поиск работают с ними как с обычными сообщениями.
- **Связь с системами организации** — через MCP, ассистент выступает только клиентом.
- **Имя и характер на выбор** — Штурман, Нестор, Савельич, Бэрримор, Дживс или своё; только в разговоре с владельцем.

## Как развернуть

**Сначала выберите вариант.** Их два, и выбираете вы, а не агент — он обязан спросить вас об этом до первого шага:

| Вариант | Что вы получаете | Что нужно дополнительно |
|---|---|---|
| **Ассистент в Telegram (Hermes)** | Ассистент отвечает вам в Telegram, ведёт архив переписки, готовит ответы и сводки. Настройка — в браузере: мастер, затем страница «Настройки Штурмана» | Адрес для входа в браузере — свой домен, IP-адрес сервера или посредник `sh.namre.app`; агент проверит сервер и порекомендует (`docs/address.md`) |
| **Только архив и согласования** | Ассистента в Telegram нет. Архив переписки с поиском и список обязательств; вопросы по архиву вы задаёте из своего Codex CLI или Claude Code. Полного диалога с агентом нет; сервисные задачи требуют своего бота и модели | Домен не нужен: страница «Настройки Штурмана» открывается через туннель SSH. Чтобы разбирались обязательства — ключ провайдера модели и отдельный бот от @BotFather |

Чем варианты отличаются подробно — `docs/standalone.md`. Сменить вариант позже можно, но это отдельная процедура.

Проект рассчитан на то, что развёртывание и сопровождение выполняет ИИ-агент под вашим присмотром.

**Основной путь — ваш агент делает всё сам.** Откройте новую сессию Claude Code (в приложении Claude — режим работы с кодом) или Codex у себя на компьютере и вставьте текст из [`prompts/deploy-remote.md`](prompts/deploy-remote.md). Терминал и SSH вам не нужны: агент сам создаст ключ доступа, подготовит сервер (`docs/runbooks/server-prepare.md`) и развернёт ассистента. От вас — ответы на его вопросы, пара действий в панели хостинга (и у регистратора домена, если он есть), которые он покажет по шагам, и «да» на стоп-точках. Нужны: сервер (VPS) с Ubuntu 24.04 и вход в панель его хостинга. Домен — по желанию: как вы будете открывать ассистента — по своему домену, по IP-адресу сервера или через посредника, — агент спросит вас сам, проверив сервер (`docs/address.md`).

**Режим «агент на сервере»** — для тех, кто сам работает с SSH: Claude Code или Codex CLI запущен на самом сервере, репозиторий склонирован в `/opt/shturman` (образец прокси ждёт именно этот путь; домашний каталог прокси прочитать не сможет):

```
sudo install -d -o "$USER" /opt/shturman && git clone https://github.com/namre/shturman.git /opt/shturman && cd /opt/shturman
```

затем дайте агенту текст из `prompts/deploy.md` (вариант с Hermes) или из `prompts/deploy-standalone.md` (только архив и согласования). Агент переспросит, какой вариант вы ставите, и пойдёт по своему runbook — `docs/runbooks/deploy.md` или `docs/runbooks/deploy-standalone.md`: проверит сервер и поднимет стек командой `./ops/up.sh`.

Дальше в варианте с Hermes вы всё делаете в браузере, по двум одноразовым ссылкам от агента:

1. **мастер** — имя и характер помощника, модель, бот в Telegram, с которым вы разговариваете;
2. **страница «Настройки Штурмана»** — сначала бот согласований, затем выбор одного из двух способов подключения и шаги выбранного способа:
   - **«Через ваш аккаунт»** — ключи приложения Telegram, вход в ваш аккаунт по QR-коду (только чтение), выбор чатов;
   - **«Через бота и помощника»** — бизнес-режим Telegram для личных чатов (видны только новые сообщения; Telegram Premium для этого не нужен), по желанию для групп — отдельный аккаунт помощника на втором номере.

   В обоих способах прошлую переписку можно догрузить выгрузкой из Telegram Desktop. Способ можно сменить позже: собранное не теряется. Страница открывается кнопкой из мастера, отдельно от ассистента, чтобы ваш вход в Telegram не проходил через него.

Ботов у вас два, оба вы создаёте сами у @BotFather: в одном вы разговариваете с ассистентом, второй — бот согласований, «пульт» с кнопками «Да» и «Нет»: через него вы подтверждаете решения ассистента. Без Hermes бот один — бот согласований.

**Режим «агент ведёт, вы вставляете»** — обычный чат (ChatGPT, Claude): дайте ему текст из `prompts/guided-chat.md` и выполняйте команды сами.

Облачные агенты, работающие в собственной песочнице, до вашего сервера не дотянутся; SSH-ключ от сервера в облако не отдавайте. Основной путь рассчитан на агента, который работает на вашем компьютере.

Обновление установленного экземпляра — по `UPGRADING.md`.

## Что понадобится

- Чистый сервер Linux (Ubuntu 24.04). Рекомендуется 8 ГБ памяти и 4 ядра: тогда расшифровка голосовых, поиск по смыслу и защита от внедрённых инструкций работают одновременно. Минимум — 4 ГБ: тяжёлые дополнения помещаются по одному — расшифровка голосовых (около 1,4 ГБ) **или** поиск по смыслу (0,2–1,2 ГБ) с защитой (около 0,6 ГБ). Для расшифровки голосовых нужен процессор x86-64. Диск — от 40 ГБ и ещё около 4 ГБ под распознавание речи. Подробно — `docs/voice.md`, «Какой сервер нужен». Сервер скачивает образы, пакеты и модели с Docker Hub, GitHub, Hugging Face и других официальных адресов — список и проверка в `docs/deployment.md`, «Что откуда скачивается».
- Адрес, по которому вы будете открывать ассистента в браузере, — один из трёх способов; выбираете вы, агент проверит сервер и порекомендует. Сравнение — `docs/address.md`. Свой домен: страница «Настройки Штурмана» живёт на том же имени, на порту 8443: его нужно открыть на сервере. Набирать этот порт вам не придётся — туда ведут кнопка и ссылка. Если порт открыть нельзя, странице можно дать отдельное имя. Домена нет — подойдёт IP-адрес сервера: ассистент откроется по адресу вида `https://203.0.113.10`, сертификат на IP-адрес сервер получит сам; нужен открытый порт 80, только IPv4, а при переезде сервера на другой IP сменится и адрес (`docs/deployment.md`, «Без домена»). Нет ни домена, ни белого адреса (сервер дома, в офисе, за общим NAT) — адрес через посредника `sh.namre.app` по коду приглашения от его держателя: входящие порты не нужны, но держатель посредника технически может подменить ваше имя — подключайтесь, только если ему доверяете (`docs/relay.md`).
- Бот от @BotFather: мастер настройки подскажет, как его создать. Его токен, как и остальные ключи, вы вводите в браузере, а не в терминале.
- Доступ к модели через штатные настройки Hermes: ключ провайдера либо поддерживаемый выбранной версией вход по подписке. Настоящий вход и фоновые задания по подписке в пилоте проверяются отдельно; матрица фактических проверок — `docs/target-model.md`.
- Для входа в аккаунт Telegram (ваш — в способе «Через ваш аккаунт», аккаунт помощника — для групп): собственное приложение Telegram (`api_id`, `api_hash` с my.telegram.org) — страница «Настройки Штурмана» подскажет, где их взять; для аккаунта помощника — ещё и отдельный номер.
- Если с сервера нет прямого доступа к Telegram или провайдеру модели — исходящий прокси.
- Ещё один бот от @BotFather — бот согласований. Это первый шаг страницы «Настройки Штурмана»; там же показано, как его создать.
- Для способа «Через бота и помощника» в группах — вторая SIM-карта для аккаунта помощника. Подписка Telegram Premium для бизнес-режима с ботом не нужна: по документации Telegram API подключение бизнес-бота её не требует (сверено 2026-10-14).
- Для режима без Hermes домен не нужен. Чтобы сервис разбирал обязательства и присылал их вам, нужны ключ провайдера модели с API, совместимым с OpenAI, и отдельный бот от @BotFather.

## О чём нужно знать заранее

- **Дополнительный аккаунт — автоматизация пользовательского аккаунта Telegram.** Telegram может его ограничить, особенно новый номер. Риск несёте вы.
- **Провайдеры моделей работают не во всех странах** и могут блокировать аккаунт при доступе из неподдерживаемого региона. Проверьте условия своего провайдера.
- **Вы обрабатываете переписку других людей.** Требования закона о персональных данных в вашей стране — ваша ответственность.
- **Отправка по умолчанию выключена.** `off` блокирует доставку; подготовка требует отдельного решения владельца; `prepare_only` позволяет пройти подготовку и согласования без доставки; `on` включается владельцем отдельно. Без собственного бота сервиса реальная отправка не работает. Разрешённый автоответ отличается от ручного согласования конкретного черновика; новый источник и раскрытие проверяются отдельно. Настоящая доставка и отзыв проходят пилот по `docs/runbooks/validate-pilot.md`; остаточный риск — `docs/architecture.md`.
- **Без бота согласований ассистент не готов к работе.** Архив читается, но запросы ассистента, которые должен подтвердить владелец, — принять найденное обязательство, включить чтение чата, импорт и другие защищённые изменения — не применяются, а отклоняются: подтвердить их некому. Отправка без своего бота тоже не работает. Поэтому бот согласований — первый шаг страницы «Настройки Штурмана»; подробно — `docs/architecture.md`, «Открытое ограничение».
- **В способе «Через ваш аккаунт» основной аккаунт Telegram подключается через сессию — это не официальный механизм для ботов.** Сервис с этой сессией только читает и ничего не отправляет, но риск ограничений со стороны Telegram есть, и он ваш.
- **Защита от внедрённых инструкций — не гарантия.** Модель ловит большинство грубых попыток управлять ассистентом через входящее сообщение и пропускает заметную часть тихих. Измеренные числа — `docs/guard.md`.
